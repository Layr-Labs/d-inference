# Small model-free native qualification route

2026-09-14. Source proposal only. Root owns all builds, processes and observation.
There is no runnable new command or new public resident mode in this note.

After the pure descriptor fixtures and old-readiness vector pass, add one closed
model-free test entry in the existing executable. It should call the actual new
cohort readiness wrapper on two local loopback ranks, using the existing completed
[64] Int32 exchange. Do not run the full P2P residual matrix or any model forward.
The entry accepts only a fresh epoch, explicit loopback, bounded timeout and a
closed fixture case; it rejects model paths, traces and performance options.

Build the local cohort through the actual CPU admission with the already retained
configuration fixture and generated A/B/A histories. Use fresh, common deterministic
per-request epochs derived from the new run epoch, with the first equal to that
epoch; validate uniqueness through the existing admission. Record that these are
synthetic descriptor observations, not verified loaded models or actual arithmetic
environment qualification. No model directory, payload, external baseline or weights
are needed. A test-only marker after successful exchange replaces the load call;
the separate pure integration check must prove the real load seam has the same order.

## Three fresh cohorts

| Case | Native behavior | Required parent evidence |
| --- | --- | --- |
| Match | Both ranks admit the same three ordered requests and one excluded warmup; call actual cohort readiness, then return a CPU marker. | Both native exits0, matching descriptor/digest, two successful markers, bounded complete output, all owned supervisors reaped. |
| Warmup mismatch | Rank1 admits zero warmups while rank0 admits one; both lists remain individually valid. Exchange the resulting different digests. | The source-bound mismatch error, no successful post-agreement marker, whole-cohort cancellation/reaping. Rank0 may block after rank1 rejects before its reply. Expected failure is not native success. |
| Missing peer deadline | Archive both configurations but start only rank0. Use a3s parent execution deadline while native/supervisor bounds stay30s. | Parent deadline is the actual failure reason, the started process group is retired and supervisor reaped; configured2/started1 remains explicit. An earlier native failure is inconclusive, never silently accepted. |

The third case qualifies bounded startup cancellation. It does not claim that a
cohort receive was reached or that an established-connection peer loss was tested.
If that later matters, add one separately reviewed barrier-controlled peer-loss
fixture; do not infer it from a Collective constructor or an early ready record.

## Retain the existing guard mechanics

Use the current runtime's local `processes.start`/`stop_processes`, shared new
`run/bundle`, ordered `run/rank-0` and `run/rank-1`, and unchanged `rank_worker.py`.
The worker strips inherited MLX/JACCL/DARKBLOOM settings before applying the exact
test config and owns each native process group. Both endpoints come from the
existing bind-both-then-close loopback allocator; bootstrap races fail, with no retry.

Reuse the guarded tiny driver's exact native pin, immutable source/dependency and
release/resource snapshot checks, initial and pre-native actual-free>=1GiB screens,
pressure<=2, no increase from the initial reported swap baseline, bounded observation
commands and final rechecks. These are the small diagnostic policy, not the larger
real-model resource gates. No artifact/model hashing is appropriate in this entry.
Freeze the newly integrated sources and executable before each actual cohort.

For the two-rank supervisor retain the latest `long_supervision.py` ordering:
check the deadline again after a resource observation, preserve primary and cleanup
errors separately, cancel the whole cohort on any failure, and explicitly wait for
owned supervisors. The old standalone P2P supervisor is useful scenario precedent
but overwrites the original reason on cleanup failure; do not copy that behavior.
The existing public mode-specific record validators cannot run this new test without
a narrow explicit contract adapter. No broad public-launcher refactor is needed.

Use native/supervisor<=30s and parent execution<=45s for normal/mismatch cases,
plus the existing bounded stop/reap phase. Bound each native stream and line to
64KiB; admit only the exact archived-source loopback warning and, for the negative
case, the exact frozen mismatch diagnostic. Pin rank configs, raw stdout/stderr,
source archive, bundle and final receipt. Keep scenario success, actual native
success and cleanup success separate. Root's postflight should inspect only exact
owned PIDs/groups/paths; missing RSS samples are absent, never zero. A reaped local
supervisor and delegated child-group cleanup are distinct observations.
