### Two-Mac pairs: a pair no longer stays stopped when its service ends in the middle of a restart of its own

- The leading Mac stops both parts and starts them again by itself in four cases: after an update, when a Mac's memory keeps refusing its share of the model, when the pair's cluster approval changes, and when a start registers the pair with the coordinator. If its cluster service ended between that stop and the start (a restart, a crash, an update), only the update case put the pair's start back. In the other three the pair stayed "■ Stopped" on both Macs until someone ran `darkbloom start`. Now the service's next run puts the start back in all four. A registration that the `darkbloom cluster` command on the leading Mac runs itself is ended by that command; if that command is killed between its stop and its start, the pair stays stopped as before.
- A registration whose stop failed (the other Mac did not answer) left the pair stopped while its screen said "Starting both Macs' parts again…". The pair now stays started, and the screen adds "The cluster was not registered with the coordinator; the pair stays started."
- While this Mac's update is about to restart its cluster service, the memory re-plan and a change of the cluster approval wait for that restart, as setting the pair up again after an update already did, and a registration stops nothing meanwhile. The service log says so: "this Mac's update to … restarts the cluster service next: … waits for that restart".
- A stop a person asked for still stands: the start is not put back after `darkbloom cluster stop`, `darkbloom stop` or `darkbloom start --solo`. `darkbloom stop` and `darkbloom start --solo` on a Mac whose pair is down now clear the pair's start even while another process is rewriting this Mac's cluster record, where they could miss it before. When `darkbloom stop` cannot update that record it says so and exits 1 instead of leaving a start that could come back.
- Limit: if the write that ends such a restart fails while the cluster service keeps running, the pair stays stopped until the service next starts within the hour, or until `darkbloom start`.
