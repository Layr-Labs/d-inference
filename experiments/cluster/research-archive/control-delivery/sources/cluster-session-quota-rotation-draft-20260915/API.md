# Listener-preserving quota rotation

First slice: rotate only after normal request-quota exhaustion. Existing fixed-lifetime expiry, explicit stop/drain and no-factory initialization keep their current stop behavior. The same generation boundary can later close admissions before the remaining-lifetime threshold; this slice does not raise limits or claim lifetime rotation.

Proposed API: add an optional `replacementSessionFactory: @Sendable () async throws -> DistributedInstalledSession` to the installed-session host initializer. Nil preserves one-session behavior. The factory prepares one session from the same captured `ClusterConfigurationReference`; it must not start owners. The host compares the candidate's existing `ClusterStatusBinding`, model metadata and profile against the initial session before start, and requires a membership epoch never seen by this host. A retained epoch set rejects ABA reuse after intervening rotations. An internal protocol-valued factory supports the existing host test seam. No changes to installed owner/session retirement rules are needed.

Separate `DistributedLocalServerGeneration` retains one immutable generation ID/session/response registry and its engine entry/acquisition. A small stable response router supplies the currently published registry to the one HTTP listener. Closed registries never reopen. Each response ticket records its generation; a late old ticket cannot acquire a replacement entry. The existing public HTTP application and discovery record are created once.

Quota sequence: close old admissions and begin the exact old installed session's drain independently of HTTP delivery; keep the listener, discovery and bridge pump while waiting for that generation's acquisition and actual response hold to finish. Shut down its bridge, then require the installed session's existing `.released`/`canRotate` barrier, including native cleanup, authenticated release ACKs and actual owner transport exits. Starting the drain before waiting for HTTP delivery avoids an owner-retirement/response cycle. Only then call the factory. Retain its result before any awaited tokenizer validation/start. Publish a fresh bridge/registry only after new Ready and an unchanged generation/stop token. Reload is an unavailable interval with no queue and no deadline extension.

Stop cancels and joins the specific generation's pending preparation/start/rotation work, sends cleanup to that captured session, and prevents late publication. A replacement returned after cancellation is retained and stopped. Old monitor and acquisition callbacks compare their generation before acting. A missing proof or failed replacement retains the corresponding session/bridge/response obligation, exposes zero admission and quarantine/failure, and never invokes another factory.

Implementation files: new generation/factory binding and response-router helpers; split only the epoch preparation and rotation portions from DistributedLocalServer; narrow HTTP acquire/status/application changes; add the `rotating` host phase to the existing strict status codec. DistributedInstalledSession, Pair, native commands, device journal and all deadline origins stay unchanged.

Validation will use the actual host and installed-session implementation. Reuse the current InstalledFixture/InstalledFakeOwner/InstalledFakeWorker sources for model-free owner children, with a tokenizer-only test bridge. Stage cases for two quota boundaries on one bound port/discovery record, held acquisition/response, missing release ACK/nonzero owner exit, stop during replacement start, late old-generation callbacks, changed preparation and exact fresh epoch identity. Existing no-factory HTTP/lifecycle tests remain controls. The full Provider fixture target and owner-child build recipe will be private and source-only until the next explicit compiler grant.

Capacity readers traced: host catalog/acquire/tokenizer/status; generation's bridge/DistributedCBv2Engine capacity; installed readiness/admission; existing local application closures. This first slice does not attach the local host to ProviderLoop/coordinator BackendCapacity/WarmModels/CurrentModel or change those fields.

The newly confirmed production requirement remains separate: both trusted Macs must run Darkbloom, be coordinator-verified and routable, and have their device capacities reserved atomically as a cluster. Local HTTP/session fixtures do not establish those membership, routing or double-assignment protections.
