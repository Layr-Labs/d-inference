# Observed dense loader metadata increment

This draft adds shared checks of actual prepared descriptors and compact inventory records. It does not add 27B execution, a resource permit, a loader overload accepting a caller ceiling, or a new receipt schema. Compiler/native validation belongs to the root; none was performed by this author. The fixture source expects 22 positive and 104 rejection checks; those are prospective counts, not executed Swift results.

## Integration surfaces

1. Add the four `core/*.swift` files and `bridges/QwenDenseObservedSourceBridge.swift`. Apply `bridges/legacy-and-records.patch` against the pinned originals. `QwenLayerStageInventoryTypes.swift` is the byte-identical Codable tail extracted from `QwenLayerStageLoadReceipt.swift`, with a Foundation import. Existing names, fields, encodings and receipt construction remain unchanged.
2. The existing full and stage source loaders call `observedQwenDenseSource(prepared, model:)` and `validateLegacy(...convertBF16:purpose:)`. This projects actual descriptor shapes/dtypes/byte counts, one-part counts, prepared expected shapes and actual packed/floating constructor classes. The pure validator computes the same sorted loaded layout and fixed byte budget. Legacy source and host constants are aliases to their unchanged 6 GiB/512 MiB values; manifest 8 GiB and TP rank/combined 4/8 GiB limits and their existing call sites remain unchanged.
3. Optional, separable raw-manifest binding: add `manifest-pin/QwenCheckpointManifestPin.swift` and apply `manifest-pin/manifest-pin.patch`. `VerifiedCheckpoint` and `PreparedQwenCheckpoint` gain a final defaulted `expectedManifestSHA256: String? = nil`. A supplied expectation is syntactically checked before opening the manifest, then matched to bounded exact raw bytes before JSON decoding or payload verification. `verifiedManifestSHA256` becomes visible only after the constructor's unchanged complete file/aggregate verification succeeds. Nil retains the old bounded/unbounded manifest IO choice and avoids another hash. Existing loaders do not supply this new argument.

The full loader's materialization/update/evaluation body is unchanged. The stage materializer, compact constructor inventory, quantization checks, source activation query, retained descriptor checks, weak metadata-model release and native failure checks are unchanged. The stage source record loop still takes actual file/offset/shape/source dtype/bytes from the same prepared descriptors; only loaded dtype and byte totals come from the shared validation. No additional eval/sync, model, payload copy, environment read or parameter mutation is introduced. There are additional CPU metadata projections/sorts; no runtime-overhead invariance is claimed.

## Unwired registered seam

`validateRegistered(observations, identity:profile:requirement:plan:)` requires the closed admitted model, exact rebuilt Plan and storage role, raw config/manifest/artifact identity, complete retained count and actual BF16 loading policy. It compares every canonical name/shape/stored dtype/byte count with the admitted inventory. The 27B 635,699,200-byte largest tensor and 15,132,802,048-byte source may pass this metadata function while the legacy 512 MiB/6 GiB path still refuses them. This is intentional separation, never a materialization permit.

`validateObservedQwenDenseStage(inventory, source:profile:requirement:plan:stageIndex:)` consumes the existing `QwenStagePreparedInventory`. It validates actual sorted active mapping records, loaded/stored dtypes, exact local/source ownership, inert parameter replacement contracts and every existing summary field. The existing constructor/quantization loop must first validate actual model parameters. A pair requirement admits inspection of both stages; a stage requirement admits its own stage only; a full-model requirement cannot be replayed as compact stage metadata. The source metadata token is separately role-bound.

A future authorized loader should obtain observations through the supplied bridge, the aggregate and optional verified raw-manifest identity from the actual `PreparedQwenCheckpoint`, and the configuration SHA from the exact configuration passed into that verified constructor. Do not fill observed identities from expected profile fields as if they were observations. Matching scalar strings/records alone does not establish payload, constructor, OS or runtime provenance. The result explicitly remains `runtimeExecutionAuthorized = false`; no method upgrades it to a permit. Before wiring this path, an actual independent OS/runtime resource admission must cover the requirement plus still-unmeasured fusion/workspace/framework/host/OS terms. The pure resource-planning input is not that admission.

## Checks and limits

`check_source.py` is CPU-only and reads pinned source/retained metadata, not downloaded headers or model payloads. It verifies mechanical preservation of read/eval loops, record schemas, fixed bounds, manifest-check ordering, dependency/source identities, and the complete retained 927/1,847 tensor metadata/ownership vectors. Mutation checks test those source guards, not compiled Swift semantics. All commands in `ROOT_CHECK.md` are proposed for the root only.

The Swift fixture uses synthetic constructor observations derived from the frozen retained metadata. It tests exact source bounds/layout/F16 policy, missing/duplicate/foreign metadata, wrong raw-vs-retained counts, same-byte shape/dtype substitutions, actual class/one-part rejection, stale Plan/role replay, complete stage and inert inventory, coherently rehashed wrong records, and optional raw-manifest mismatch. A separate constructor fixture creates only an invented three-byte config and three-byte payload in a fresh temporary directory, validates their actual file/aggregate hashes, and requires precise refusal errors. It does not construct a model, establish actual 27B sanitized inventory, read downloaded tensors, estimate numerical correctness, or prove memory safety. The downloaded-header verification receipt is a separately pinned root attestation; this draft did not repeat its header reads or the full-artifact verification.

Independent source reviews are pinned in `review-bindings.json`. The earlier 20/99 helper-only fixture review and `source-checks.json` remain historical; the actual-constructor addition is separately reviewed, and `source-checks-v2.json` plus the current 30-input source list describe the final 22/104 source. No Swift execution is claimed by either review.
