### Tensor parallel only where it keeps every feature

- On a two-Mac pair, Gemma 4 and MiMo V2.6 Flash use tensor parallel only where it keeps every feature and caching behavior of the mode it would replace: prompt-prefix and SSD cache reuse, speculative (MTP) rounds, batch lanes, media, penalties and logit bias, and stop handling. What tensor parallel adds, such as logprobs, never counts against it. Each mode's features come from the installed cluster worker's capability record.
- Today Gemma 4's tensor parallel keeps no prompt prefixes and MiMo's has no speculative rounds, so these pairs keep the pipeline, whatever tensor parallel's measured speed. The plan's "Tensor parallel or pipeline" line says what tensor parallel would drop ("Pipeline: tensor parallel would drop prompt-prefix reuse and the SSD prefix tier that the pipeline keeps; held back until it keeps them."), and the model list says "tensor parallel: drops a feature".
- Where only tensor parallel fits the two Macs, the plan refuses with that reason and saves no setup, instead of saving one with fewer features. The developer's forced mode (debug builds) still places tensor parallel, and the plan says exactly what it drops.
- Qwen and GLM plans are unchanged.
