## Name and quantization rules

For these artifacts, `Gemma4Model` owns `language_model.model.*`, exactly matching all text checkpoint keys and explicit quantization overrides. Its wrapper sanitizer drops `vision_tower.*` and `embed_vision.*`; admitted text names remain unchanged. The text sanitizer leaves all admitted converted triplets unchanged, with no norm shifting, transpose, concatenation, or scalar rewrite. It has alternate raw-checkpoint rules splitting `.experts.gate_up_proj` on axis -2 into `.experts.switch_glu.{gate_proj,up_proj}.weight`, and renaming raw `.experts.down_proj`; those paths are absent here and should be rejected by the initial direct reader rather than inferred from a dummy scalar. No rotary or quantization-range tensors occur in the admitted text set.

Using `Gemma4TextModel` alone would change the module root to `model.*`; both weights and override policies would then need explicit remapping. Preserve `Gemma4Model` for the initial whole-model path. `Gemma4Configuration` propagates root quantization metadata into its nested text configuration. `loadWeights` then sanitizes, quantizes only modules with stored `.scales`, resolves per-path policy, and performs strict parameter update. `Gemma4Model` has no additional quantization alias implementation; exact canonical override paths are sufficient.

Both root `quantization` and `quantization_config` blocks agree. Active W8 has 326 affine W8/G64 text modules; its 120 explicit W8 overrides are redundant. QAT4 has 206 affine W4/G64 modules and **120 W8/G64 exceptions**: every layer's three dense `mlp` projections and `router.proj`. All packed weights are U32; all text floating tensors, including scales, affine offsets, norms, router scales and layer scalars, are BF16. A float16→BF16 loader rule is therefore a no-op for these exact files. The `.biases` suffix is the affine quantization offset, not an output bias.

## Exact constructor topology and partition boundaries

Both configs explicitly declare 30 layers, H=2816, dense I=2112, 128 global experts, top8, expert I=704, GeGLU tanh approximation, no PLE (`hidden_size_per_layer_input=0`), no shared-KV tail (`num_kv_shared_layers=0`), and no double-wide MLP. The ordinary constructor must preserve these explicit values rather than inherit Gemma-family defaults. The uniform rank plan uses dense 1024/1088 and expert 320/384 (G64 groups 16/17 and5/6). Taking exact arithmetic halves 1056 and 352 would split quantization groups. Uniform rank widths intentionally produce unequal payloads; a half-total byte invariant is invalid. Alternating ownership across layers could balance aggregate payload, but needs per-layer construction changes and is outside the uniform plan.

All layers contain dense gate/up `[2112,2816]`, dense down `[2816,2112]`, expert gate/up `[128,704,2816]`, expert down `[128,2816,704]`, and router `[128,2816]` logically. Expert IDs/count and router tensors stay global. Gate/up select inner output rows; down selects matching input packing words and metadata groups. All 540 FFN tensors shard; 799 text tensors replicate. The JSON contains exact packed W4/W8 shapes and BF16 metadata shapes for both layer types.

There are 25 sliding layers and 5 full layers (indices 5, 11, 17, 23, 29). Sliding attention: Q16/KV8, D256, q output4096, k/v2048, o input4096. Full attention: Q16/KV2, D512, q output8192, k1024, o input8192. `attention_k_eq_v=true` applies only to full layers: **full v_proj does not exist**, whereas all sliding v_proj tensors do. K and V still pass through distinct normalizations and occupy separate caches. Each layer has seven H-wide RMSNorm weights, q/k norm[D], router.scale[H], router.per_expert_scale[128], and layer_scalar[1]. Thus sliding layers contain 45 tensors, full 42, plus 4 top-level text tensors. No trainable v_norm weight exists. Tied embedding has one quantized `[262144,2816]` logical triplet and serves the head; there is no lm_head tensor. Preserve sqrt(H) input embedding scale and final logit softcap30. Config max_position_embeddings262144 differs from catalog admission131072; that does not authorize raising provider limits.

Dense and routed FFNs have different input and output norms. Their partial outputs must each reduce **before** `post_feedforward_layernorm_1` and `_2`; only then are branches added, passed through the final FFN norm, added to the residual and scaled by layer_scalar. Qwen's single whole-MLP reduction boundary cannot be reused directly. Initial FFN-only execution should keep attention, routing and all norms replicated. Private typed GemmaMLP/Experts fields rule out substituting a generic UnaryLayer wrapper; public decoder construction and typed Linear/SwitchGLU module replacement are usable seams.
