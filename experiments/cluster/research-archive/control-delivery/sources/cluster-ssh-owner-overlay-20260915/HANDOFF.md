# SSH owner implementation slice

Private additive overlay; no SSH, model, GPU, or main repository execution.

`ClusterRemoteWorkerEndpoint(configuration:clusterID:expectedIdentity:profile:rank:executionPlanSHA256:lifetimeDeadlineUptimeNanoseconds:)` implements the reviewed `ClusterWorkerEndpoint`. It launches only `/usr/bin/ssh` with explicit host/key files and the fixed installed command `exec <configured absolute darkbloom> cluster worker-owner --stdio`. Host verification is strict; passwords, agent forwarding, ambient SSH config, forwarding, proxies and interactive fallback are disabled. Trust files must be owned regular files. This uses configured OpenSSH authentication, not new cryptography. Configuration and trust-file provisioning remain the installed CLI's responsibility.

`ClusterWorkerOwnerService.serve(input:output:clusterID:leaseDirectory:maximumLifetimeNanoseconds:binding:native:)` is the remote installed entry. The required trusted binding/native factories supply local identity/profile/plan, executable, model, environment, native resource policy and hard native lifetime alarm. Wire messages cannot select these. Factory must return an unlaunched Process; actual successful-launch PID and actual termination reason/status are additive Process observations. For a physical JACCL configuration the factory must require the authenticated bootstrap attachment described below; the CPU factory deliberately launches only a model-free fixture.

The outer integer-only JSONL envelope reuses the existing strict worker JSON scanner, line decoder and command/event codec. It adds epoch, lease, fresh owner incarnation, launch UUID and independent sequence checks. Reserve sends separate remaining generation and delivery/admission durations, sampled at dequeue; remote owner derives local uptime deadlines. No absolute uptime crosses hosts. The parent retains its original deadline independently: one-way transit is not estimated. Pending admission and active request expiry are observed by the remote poll loop and request native fencing without waiting for a further command. Queuing under Pair/Request locks performs only bounded CPU validation/enqueue; pipe IO and invalidation callbacks run on independent queues.

Request `retired` remains local state retirement. A native-terminal message is emitted only after the direct-child supervisor observes/reaps native exit or a definitive failed launch. It binds owner incarnation, lease, epoch and launch ID. SSH exit/EOF, elapsed time and signal delivery never set `nativeCleanupObserved`. A native terminal asynchronously invalidates the pair even if a token callback is blocked. On missing authenticated terminal proof, cleanup waits remain unresolved; this deliberately does not claim automatic reconnect/recovery.

The configured device directory is private and owned, and is common to every cluster using that device. A regular no-follow file is locked with `flock`; descriptor/path/directory identities are rechecked. The intended launch is fsynced before native launch. A nonempty unresolved journal refuses any new owner, without PID probing. It is cleared only after actual native cleanup, successful terminal publication, acknowledgement on the current connection, and actual local request-charge release. Owner EOF fences native while the owner is alive and leaves the journal unresolved. If the owner itself dies, the configured native hard alarm remains necessary and the sticky journal prevents a second load. No automatic orphan recovery or manual-delete command is added.

## Bootstrap and installed CLI work remaining

The existing generation stdin/stdout is not a JACCL bootstrap channel. `jaccl-owner-channel-draft` supplies a private Unix listener/connection with kernel PID+UID checks and bounded epoch/rank/sequence rounds, and the frozen C callback shim replaces plaintext native bootstrap. The configured native factory must create its listener before launch and attach using `launchedProcessIdentifier`; its relay runs independently with a fixed local deadline. Full authenticated two-owner rank-ordered round relay and installed `darkbloom cluster worker-owner --stdio` configuration dispatch are the next integration work. This slice does not silently use the old plaintext bootstrap and does not claim a physical endpoint run.

Promotion mapping: six new Remote runtime files, one Protocol scanner wrapper, two read-only Process observations, plus Package target registration. The four previously frozen pure-owner files and endpoint Pair/Request/Endpoint files are unchanged. Keep main's existing Process test runner/deadline groups; this overlay adds a separate `Tests/RemoteChecks/run.sh`. CPU fixture changes to the existing fake worker only add delayed admission and delayed exit behaviors.

CPU command: `bash workspace/libs/darkbloom-cluster/Tests/RemoteChecks/run.sh`. Nine groups exercise codec/clock/type/replay-direction bounds, durable unresolved lease and symlink refusal, fixed SSH construction, actual fake-child two-token lifecycle/release, SIGTERM-ignoring child fencing, wrong-incarnation and transport-exit rejection, actual owner EOF with SIGKILL proof and sticky journal, short admission expiry with a longer generation budget, and peer fencing while the rank-zero token callback blocks. No real SSH or authentication handshake is executed by these tests.
