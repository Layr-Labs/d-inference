### A stray `<tool_call>` no longer fails a GLM-5.3-Flash response

- GLM's tool parser reads a response from its first `<tool_call>` to the end as one batch of calls, and on `auto` tool requests that includes the model's reasoning. A tag the model only mentioned or a call it drafted in its thought, or a text answer that mentions the tag, failed the whole response with a 500 (`native GLM tool output is invalid`).
- Such output is now text instead of a failure, as vLLM's and SGLang's GLM parsers never fail a response on tool syntax, with a stricter rule for what is still a call: the calls are the well-formed frames that end the response; everything before them is text, so the reasoning still splits at `</think>`. A frame inside or after another frame's arguments is never a call. Output with no such calls (a malformed or cut-off final call, text after the calls) is all text, and so is output cut off at `max_tokens` whose tool suffix does not parse. No call is completed or salvaged.
- Required and named `tool_choice` still fail closed (422). `DARKBLOOM_GLM_TOOL_TEXT_FALLBACK=0` restores the 500; `darkbloom start` passes it to the launchd provider.
