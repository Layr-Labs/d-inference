The actual V3 assertion covers status.AttestationPublicKey; the service matches it to the valid registration key bound to the current encryption endpoint. Existing EvaluateAuthorization still requires fresh verified assertion, qualified Apple CodeDirectory/release, matching hardware, current receipt/revocation/archive and account/verified-machine continuity. Existing API release validation checks the registration-signed metallib under its provider lock and immutable release snapshot. New optional ApprovedRuntime returns that exact signer/binary/metallib tuple from the same check. Authorizer carries it to the lease; registry checks the carried tuple against the current registration and flags under its existing locks. Reading a later matching pair of registration/template hashes cannot replace the previously approved metallib. The ordinary Bool callback is preserved for older callers; a lease lacking the typed metallib result cannot produce native identity.

Go NativeMemberIdentity and Swift NativeMemberIdentity encode DBNID v1 with explicit legacy-MDA or qualified-App-Attest evidence. The former has only the genuine serial. The latter has only verified account/machine/credential/proof-session identity and never copies the reported serial. Both carry actual connection/control signer/process endpoint, binary/metallib hashes and release generation. Key encoding remains the actual signed representation; a separate normalized P-256 point digest prevents alternate raw/X9.63 encoding from becoming a second future device hold. The decoder rejects invalid points, missing/cross-kind fields, unknown tags, malformed/truncated/surplus bytes and values outside its 1024-byte bound. Lease times are not stable transcript identity; they remain current authority checks.
