## BLOCKING — must land before the release ships

### 1. Split `BenchCBv2` so swift-testing runs again

**728 `@Test` entries across 67 files are unreachable.** `Tests/BenchCBv2Tests`
depends on the BenchCBv2 *executable* target, so SwiftPM routes the
swift-testing pass at that binary, which rejects `--test-bundle-path` and
exits. Only XCTestCase classes execute.

`swift test` **exits 0** in that state, so four CI gates — eligibility,
backend, kernel, safety — have been reporting green while running nothing.
Those are precisely the gates added because "the paged-KV migration had no
automated numerical gate".

Verified with a control: `CBv2PagedEligibilityTests` → `Executed 0 tests`,
exit 0; `WiredMemoryPolicyTests` (XCTestCase) → 4 tests.

**The code is sound.** Removing the offending target locally makes all four
reachable: **70 tests in 5 suites pass.** The evidence is recoverable; only
the harness was broken.

A tripwire is already landed (`0ac056b0c`) failing those steps on a zero
executed count. The structural fix — library target plus executable shim —
is in flight.

### 2. Decide the flip

`.auto` still resolves to **contiguous**. Flipping to paged is one line in
the backend resolver, reversible via `DARKBLOOM_CBV2_PAGED_KV=0`.

Blocked on two things that are not code:
- **G3/G4 are 24-hour canary soaks** that cannot run on one machine. There
  is no way to compress this; the soak *is* the canary.
- **gemma-4 greedy outputs change.** More accurate against an fp32
  reference (7–17× closer on full-attention layers) but *different*. That
  is a product call, not a benchmark result.

## NOT blocking — but do not lose

### 3. Paged MTP: batch the verify columns

Measured: paged verify costs **+2.217 ms** vs contiguous at k=3, and the KV
layer accounts for **100.4%** of the reported engine gap. Mechanism is
dispatch count — `2 × (1+k) × layers` against `(1+k) × layers`.

The paged kernel has the *better* fixed cost (1.46 vs 2.83 ms) and a 2.55×
steeper slope; break-even is 1.52 columns. So paged wins at k=0 and loses
at every k ≥ 1.

Fix: hoist the KV write out of the column loop, pack columns onto the
kernel's batch axis. **No Metal changes.** ~150 lines, medium.

> **Land this BEFORE the depth-controller fix.** Fixing the controller
> alone pushes it toward k ≥ 1, which is exactly where paged is slower —
> regressing the backend the release is named for.

### 4. MTP depth controller: credit the seed's token

`CBv2MTPRoundDriver.swift:472` computes
`attributed = wallTimeNanos &+ claimedSeedCostNanos`, charging the seed's
full wall time to the verify round while `expectedCommitted` never credits
the token the seed emitted.

Consequence, derived and swept: depth 1 is selected iff `a·T > V₁`, and
since `V₁ > T` and `a ≤ 1` that is **unsatisfiable** — 9/9 parameter
combinations lose as written, 8/9 win once the token is credited. Worse,
`CostState.observe` sets `ewmaNanos = sample` on the first sample, and the
first sample at every depth is the seed-inflated one.

Worth **+14.7%** decode throughput on contiguous. ~5 lines.

### 5. Per-row ragged commit

`EngineLoopV2+MTPFinalize.swift` computes `commonEmitted` as the **min**
accept-prefix across the batch and truncates every row to it, discarding
tokens the target already confirmed. Modelled loss: 0% at B=1, 31% at B=2,
53% at B=4, **62% at B=8** — because `P(commonEmitted > 1) = pᴮ`.

The stated justification ("keeps quantized MoE target batches
shape-identical") appears exactly once in the tree, nothing depends on it,
and heterogeneous per-row KV lengths are already routine on both backends.

vLLM commits per request. Moderate, contained in one file.

### 6. Prefix-outcome telemetry defect

`EngineLoopV2.watchdogTick` and `forceFinishStreamsOnShutdownTimeout`
publish a bare `CBv2Usage`, whose default `prefixCacheOutcome` is
`.disabled`. `EngineV2Bridge+PrefixCache` maps `.disabled` into the same
bucket as `.skippedPolicy`, so **every watchdog- or shutdown-killed request
books its prefix outcome as "policy declined" on the wire** — inflating
exactly the metric anyone tuning prefix-cache policy would read.

There is already a compensating hack two cases above it (`.disabled` +
`hitTokens > 0` reinterpreted as `.hit`), which says someone met this
before and patched the symptom.

Multi-site because the outcome mutates after enqueue when adoption flips it
to `.hit`.

## From vLLM — ranked, and mostly cheap

Read against `vllm-project/vllm @ b153ae6089`. Full detail in the gate
results doc.

| # | change | shape |
|---|---|---|
| 1 | **Asymmetric watermark** — charge the reserve only to waiting/preempted rows | two branches |
| 2 | **Capture blocks as they fill** — publish the NAME inline in a not-ready state, materialise off-thread | three stages, no new field |
| 3 | **Bridge link 5** — `stagedWindow` is built, tested, and never called | 4 of 5 links already exist |
| 4 | Lift `L==1` on the paged kernel — kills the prefill gather copy | re-derive the threadgroup budget |

**The root cause underneath all of them:** we move KV *bytes* where vLLM
moves *references*. `cache_full_blocks` performs zero tensor operations.
Our 25,600-token reuse floor, the tiling requirement, the 200 MiB sidecars,
the 20 GiB ceiling, and `retainPage`'s zero callers are six symptoms of one
choice.

**Target gpt-oss first** — symmetric head geometry gives a flat 16-token
floor (1600× below ours), an 8-block contiguous run instead of 64, and 2
cache groups instead of 6.

**Do not build:** CoW, beam fork (`vllm/core/` is deleted), cascade
attention (needs ≥ 8 requests, gated off for sliding-window models), block
de-dup, SLO-aware admission. And vLLM does **not** solve long-prefill
delaying decodes either — its knob ships disabled, like ours.

## Process notes worth keeping

**Citation rules**, derived from ~190 machine-checked citations across five
agents (19 range slips, 1 wrong path, 0 fabrications):

1. Anchor to `grep`, never to a position counted inside a rendered read —
   elisions silently absorb lines.
2. Escape regex metacharacters when searching literal code; unescaped
   parens return confident false negatives.
3. Cite `git grep … HEAD`, not the working tree, when the artifact is
   durable.
4. Verify against content, never against the message claiming it.
5. Cite what survives the refactor — cite the definition site, or by
   symbol.

Corollary: **a negative needs a control.** "Absent from file A" is evidence
only once the same pattern is shown to match in sibling file B.

**Concurrency:** `git commit --only -F <msg> -- <paths>` protects other
agents' *other files*. Nothing at the git level protects a *shared* file —
`--only` commits that path's full worktree content. Shared files need a
claim, not a flag. Three index sweeps today, all on
`docs/releases/v0.8.0-notes.md`, the one file nobody claimed.

**Four checkouts of this repo exist on the box.** A relative
`libs/mlx-swift-lm/...` resolves to a real but two-PRs-stale tree. Use
absolute paths.
