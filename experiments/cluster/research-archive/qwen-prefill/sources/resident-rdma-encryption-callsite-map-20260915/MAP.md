All ordinary shared runtime native P2P calls found by source search are in `QwenLongPrefillReadinessExchange.swift` and `QwenLayerStageGenerationTransport.swift`. Their common lower shim is `Collective.sendCompleted/receiveCompleted` → `CollectivePointToPoint.send/receive` → Cmlx send/recv. The shim validates peer/shape/bytes, evaluates, synchronizes CPU and GPU streams, and retains send input. It has no encryption/key state. `QwenGenerationLookaheadProducer.run` relies on completed-send release before preparing one subsequent prompt chunk, then separately waits boundaryConsumed; an adapter must preserve that ownership contract and charge its additional buffers.

## Native tail-byte caveat

`jaccl/lib/jaccl/mesh_impl.h:445` copies only the logical message bytes into a selected shared scratch buffer, while `send_to:543` posts that entire buffer. `rdma.h:119` sets the scatter/gather entry length to `size()`. `rdma.cpp:25,76` uses `posix_memalign` without initialization. Therefore encrypting the logical input alone does not prove that all emitted native frame bytes are safe: tail bytes may be uninitialized or previously used data. This is source evidence, not an observed wire capture. Required mode needs a proven exact-size/zero-tail native send or fully initialized record padding matching actual native frame behavior; treating these bytes as harmless by assumption is insufficient. Ring/reduction paths need their own coverage or explicit refusal.

`jaccl/jaccl.cpp:132,141` enqueues raw send/receive pointer jobs; `mesh.cpp:62` exchanges connection destinations over its SideChannel before QP RTS. Native setup therefore remains a separate authenticated binding from protected payload records. Group handle deallocation is not a native fence (`JACCLBootstrap` documents backend cache retention).

## Scope boundaries

This map is of current source, including reachable reusable bypass APIs. It is not an exhaustive audit of every experimental executable or native collective backend. Existing trusted-two-Mac/coordinator verification, routability and atomic dual-device capacity admission remain separate product prerequisites. No claim of forward secrecy, peer distrust, traffic-analysis resistance or encrypted qualification follows from this source map.
