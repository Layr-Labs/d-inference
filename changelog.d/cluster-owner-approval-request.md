### The guided cluster setup asks the DevNet coordinator for its own approval

After the Test stage passes, `darkbloom cluster` asks the coordinator to register a model approval for the pair (model, its artifact, prefill schedule and the installed app's version, with the account's credential). The pair then reads the coordinator's public approvals together with the account's own approvals, at setup and at every later check, and saves the match as before. On DevNet no operator adds an approval row for a new pair. Production and staging do not take the request: the setup says so on one line ("Cluster approval request: …"), and the pair serves as before. The cluster service asks the same way while the pair holds no approval (at its start and after an update) and renews the approval a week before it ends. A failed request never stops serving, and running the setup again is safe.
