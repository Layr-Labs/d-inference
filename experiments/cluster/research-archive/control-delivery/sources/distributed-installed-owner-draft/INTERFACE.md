This is an isolated Foundation/control implementation. No main source was changed, and no agent native model, SSH, GPU or network execution occurred. The main Provider/CLI typecheck and the installed two-host/HTTP path remain root-owned and unqualified by these tests.

Promote `integration.patch` against its source pins, or use `integration.json`. ## Public startup and server interface

- `DistributedInstalledSession.prepare(reference:)` performs bounded local metadata/trust/native-executable verification, then runs the existing metadata-only native command and compares its complete canonical capability. It returns a retained handle before launching generation owners. It requires the saved leader role.
- `session.model` exposes `publicModelID`, `directory`, `modelType`, configuration `eosTokenIDs` and `vocabularySize`. The same capability-pinned manifest contains the full product ModelManifest fields; the native CheckpointManifest decoder reads a subset. Preflight binds the public ID to model_id, verifies metadata aggregate/config joins, and requires the complete tokenizer/template pin set. Native identity remains capability.runtimeModelID. There is no second manifest format or fabricated alias.
- Load only `LocalTokenizerLoader` from model.directory, with `session.validateModelInputs()` immediately before and after. Pass the loaded tokenizer's EOS conversion to `model.stopTokenIDs(tokenizerEOS:)`. The current source reads config.json, tokenizer.json, tokenizer_config.json and chat_template.jinja/json; unpinned template fallback files refuse. These checks bind current regular file identities, not an adversarial same-user file system or a copied immutable tokenizer snapshot.
- `start() async throws` starts the fixed local installed owner and configured authenticated SSH peer owner, uses the required closed mesh bootstrap relay, then requires actual bilateral Ready before exposing the existing execution-owner contract. Native Ready is the only capacity source. The Session itself conforms to DistributedDeadlineExecutionOwner; request deadline context is forwarded unchanged to the existing origin/profile/lifetime clamp.
- `status`, `lifetimeDeadlineUptimeNanoseconds`, and optional `admissionState` expose lifecycle and remaining lifetime/admissions. `canAdmit(minimumRemainingNanoseconds:)` checks a caller-supplied minimum, not an estimated completion time. Actual reserve revalidates and clamps deadlines. The capability's maxRequests is passed to Pair; its existing default remains unchanged for other callers.
- `drain(until:)` stops new reservation admission, permits the active request to retire and explicitly release, then shuts down. `stop(until:)` cancels; abnormal stop can interrupt an existing drain. Both deadlines bound the caller's wait only. Missing cleanup/release proof retains quarantine and background ownership. `shutdown()` remains actual-proof based.
- `canRotate` becomes true only after both native cleanup observations, authenticated owner release ACKs and actual natural owner exits with status zero. There is no auto-rotation, resume/reconnect or journal recovery. A fresh session/epoch belongs to the caller after drain/release.

## Installed owner and shared exclusion

`cluster worker-owner --stdio` reads only the default provider configuration through a strict bounded reader. It accepts no runtime/model/environment/config/lease/capacity override. Both member defaults must already be configured. A Start --config alternative must resolve to the same saved reference as the local default installed owner before start; root is adding that check.

The owner derives identity/profile/Plan, fixed worker arguments and the closed arithmetic/JACCL environment from verified setup/capability. It requires the authenticated mesh attachment and lets the unchanged native admission/resource/bootstrap logic execute. Each owner installs its own local deadline from the authenticated remaining duration. The leader never acquires its local child owner's device lease. The canonical shared gate retains the existing sticky journal and actual cleanup/release guard; it cannot clear an unknown journal.

Filesystem checks currently require caller-owned, non-writable-by-group/other installed files and parents, with regular bounded metadata and no symlink final inputs. Native executable SHA is verified and metadata is recomputed. The owner application, dependent libraries, metallib, release signatures and remote installation are not independently attested by this slice. Existing pinned host keys and explicit SSH identity authenticate the configured peer; provisioning is separate. Native payload verification remains in the unchanged native loader, with all memory/resource floors intact.
