# Private protected shared-request hardware driver

This source-only candidate connects the real TLS Server, actual Registry Provider objects, existing NativePair approval/Reserve flow, existing installed member loop and retained `nativePairRequestOwner`. It requests exactly the ordinary 9B P32/C16/O2/cut16 input. It does not create a second inference owner, synthesize readiness, seed attestation flags, or use ordinary request routing.

Nothing here has been compiled or executed. No native, CLI, coordinator, capability or new numerical descriptor hash is invented. The package is not ready for a hardware launch until the real trust and late binding steps below are complete.

## Concrete changes

- The private Go build tag `native_pair_hardware_experiment` enables a single in-process selector on the real Server. Selection matches attested serial and SHA256 of the exact UTF8 SE public key, then resolves current Provider pointers. Provider IDs are generated on each actual WebSocket registration; they must not be guessed in advance. The existing atomic Reserve repeats current connection, trust, idle, release and catalog checks. Selection is bounded to 60 seconds and one grant, with original 300-second membership lifetime.
- Copied observation scalars retain the existing aggregate publication failure outcome. Existing release branches, cancellation, writer ordering and ownership are unchanged. The coordinator receipt requires actual bilateral owner release, mesh/key-confirmation/readiness and completed successful aggregate publication. The leader independently waits for the retained owner's actual aggregate shutdown result.
- Private Swift build flags on ProviderCore, darkbloom and DarkbloomCLITests enable the leader dispatch and read-only native UUID provenance. The actor-install correction `6a0b152c...318ae` is preserved exactly. Existing lease generation supplies the native UUID; the driver records public request UUID → CBv2 ID 1 → actual native UUID before request start and retains that same map after retirement.
- The explicit application-scoped TLS option is loaded once by the existing ProviderLoop config factory. The option contains canonical bounded public CA DER, its SHA256, exact wss hostname and port. Every reconnect checks that URL. The verifier preserves every original Network.framework SecTrust policy, adds the same hostname SSL policy, sets only the pinned anchor, and accepts solely `SecTrustEvaluateWithError`. No exceptions, date override, system trust write, HTTP downgrade, or fallback after a verification error is introduced. The absent-option branch uses the original TLS parameters. This is **application-scoped trust**, not OS-default-root trust.
- The callback retains only two token scalars and the terminal reason. No hot-path files, extra forwards, logits, tensors or timing arithmetic are added. Reserved and terminal files are create-only; request retirement, released bytes and aggregate owner shutdown are required before success.

The current result is expressly a token/retirement smoke test, `numericallyQualified=false`. Transport's separate `qwen9b-protected-numerical-evidence-draft-20260917` supplies charged final row/state capture. It must be built and bound before using its changed policy/Ready/evidence directory; this driver does not turn tokens into numerical proof.

## Real trust prerequisite, not fabricated enrollment

Read-only observations under `native-shared-hardware-trust-observation-20260917` show both actual Macs have user-approved MDM enrollment at `https://api.darkbloom.dev/mdm/connect`. Target serials are G36VWKJ304 (24 GB) and MKJV9DJWDC (48 GB), from retained hardware evidence. Neither existing stale daemon snapshot contains the signer public key; the 48 GB snapshot only has an old self_signed status. The public attestation feed omits serial/UDID, so memory/model cannot identify these machines.

Current pair eligibility is therefore **unproven**, not presumed absent or satisfied. Root needs the actual current signed member's persistent signer public key/serial and current connection, plus legitimate existing MDM hardware verification and Apple MDA proof. `stageDurableMDAChain` reads the newest nonempty stored chain by serial; `attachCachedMDAProof` re-verifies Apple's root, validity and exact FreshnessCode SHA256 of this connection's SE public key, and requires current hardware trust. Serial-only import or copied trust booleans cannot satisfy it. Real enrollment lookup is the existing read-only MDM `POST /v1/devices` query by serial; obtaining a genuine stored proof uses authorized private-store inputs, not a new public bypass.

An isolated coordinator needs its own configured Store, real account/auth binding, release artifact and hardware/MDA evidence. `MemoryStore` does not enable durable trust reuse. Use the existing release verification path: a loopback HTTP artifact origin is allowed by `expectedReleaseArtifactURL`; the real signed bundle is verified before a private store release is activated and `SyncBinaryHashes` / `SyncRuntimeManifest` consume it. Do not mutate the production catalog. Existing MDM API credentials, any store DSN, auth tokens and signing keys stay outside this package.

2. Under a granted exclusive CPU compiler slot, run `python3 -B Tests/run_tls.py 1` with regular outer stdout/stderr logs. 3. Reuse the actually qualified shared-request Go and corrected Swift workspaces only after root releases them. Verify all preimages before overlay.
