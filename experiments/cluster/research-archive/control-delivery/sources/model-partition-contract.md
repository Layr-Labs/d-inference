# A model partition contract for Darkbloom cluster inference

Source review: `d-inference` at `e4df336bc8399f4fd0a46d1207b594d2514f14f5`, `mlx-swift-lm` at `ce446cc5f76e013855fe0bde9002b6db1ac091b7`, and `mlx` at `3fa8f25e6451174d7b06be372c3a24272b77d88e`. This is a proposed architecture, not implemented support or a performance claim. Only the registered Qwen dense artifacts have been inspected at the tensor level in this research directory; configuration defaults in other model classes are not evidence of their registered checkpoint dimensions.

## The useful abstraction

Keep the existing Swift/MLX model implementations and give each adapter an explicit description of **which operators can be split, where partial outputs must be combined, and which request state each partition owns**. A model-family name or a universal "two all-reduces per layer" rule is insufficient. The selector chooses among legal implementations of a model's operators; it does not infer their semantics from tensor suffixes.

Initially, support a replicated residual stream and local reductions around selected projections. This preserves existing normalization, routing and cache code while permitting dense FFN TP, expert-inner-dimension TP, attention-head TP, vocabulary-head sharding, and whole-block placement as separately qualified capabilities. A minimal descriptor needs these six parts:

| Contract | Required contents |
| --- | --- |
| Artifact and execution identity | Verified aggregate/config/template identities; adapter version; build and MLX/native revision; numerical settings; per-module effective quantization; input modality; target/MTP policy. |
| Operator and value graph | Stable global layer/operator IDs; exact activation and routing semantics; logical shapes/dtypes; input/output layouts; state reads/writes; nonlocal edges such as Gemma shared KV and Qwen3-VL DeepStack; which rows actually require final logits. |
| Partition alternatives | Replicated, output-column/input-row TP, expert ownership, query/KV-head ownership, whole-block pipeline; legal ranges and group constraints; required reduction/broadcast/dispatch; bias placement; conversion cost and peak allocation bounds. |
| Execution schedule | Plan digest, membership epoch, ordered ranks, phase, step/position range, expected collectives with stable sequence IDs, rank-local tensor signatures, graph-completion fences, cancellation/error behavior. Every rank takes the same collective sequence, including ranks with no selected experts. |
| Request-state schema | Logical owner and global ranges for each K/V, convolution, SSM and assistant state tensor; actual dtype/layout; absolute positions and sliding-window interval; aliases; committed generation; checkpoint codec and supported resharding operations. |
| Qualification and profiles | Correctness status per artifact/partition/phase/backend, numerical tolerance and token checks, available shape ranges, measured timing/memory distributions, hardware/software identity, sample provenance, and confidence/unknown fields. |

An adapter should expose `describe`, `enumerateLegalPartitions`, `loadPartition`, `executePhase`, and `export/importCommittedState` boundaries. These are conceptual interfaces; declaring one does not establish that every model supports it. Unsupported phases or state conversions must be explicit refusals. Existing local `supportsMTP`/`supportsPackedPrefill` flags are necessary inputs, not proof of distributed support.

## Legal boundaries and reduction rules

**Quantization.** Resolve the effective policy for each module after checkpoint path aliasing. Retain packed weight, scale, offset and ordinary bias tensors as a unit. An input-dimension cut must land on complete quantization groups and packing blocks; output-row and expert-axis cuts must preserve corresponding metadata rows. For the inspected W4/G64 checkpoints, input cuts align to 64 logical elements and eight-value U32 packing. Do not apply that formula blindly to other bit widths or formats. MXFP4 scale storage is packed U8, unlike affine BF16 offsets; the existing `QuantizedLinear` deliberately treats these differently. Fused gate/up slicing must preserve both semantic halves and equal effective quantization policies. Loading a shard should materialize only its ranges and release source buffers; "half the weights" is not a peak-memory guarantee.

**Bias and nonlinearities.** In row-parallel `y = sum_r(W_r x_r) + b`, add ordinary output bias once after reduction, or assign it to one contributing rank. Adding it on every rank multiplies it by the rank count. Quantization `biases` are per-group offsets and stay inside the local matmul. For expert TP, per-expert output bias must also be weighted and included exactly once. A reduction may move through a shared scalar gate, but not through RMSNorm, softmax, clipping, or an activation. This is why Gemma's two normalized FFN branches need different placement from Qwen's unnormalized routed-plus-shared sum.

**Attention.** Partition complete query heads with their gates, normalization and sink values. Preserve the query-to-KV grouping and all relevant rotary dimensions. Equal head TP initially requires divisible head counts; a future alternative may replicate KV heads when query groups span ranks, but that must be an explicit layout and memory charge. Gemma head widths/KV counts are per-layer properties. KV-shared consumers and their source layer must either share a compatible head layout or have an explicit transfer/remap edge. Whole-layer pipeline cuts must account for these skip dependencies.

**GDN and Mamba.** GDN partitions matched Q/K/value-head segments, convolution channels, A/dt vectors, output-projection inputs and state heads. Mamba's fused input contains gate, convolution inputs and dt; its convolution block contains X/B/C segments. Mamba head partitions must preserve B/C group membership and the group RMSNorm boundary, or explicitly replicate groups/perform extra reductions. A_log, D, dt_bias, convolution history and FP32 SSM all move with those logical heads. The GDN adapter is not a Mamba adapter. Nemotron 3.5 also distinguishes execution timestep limits from training metadata; preserve its selected artifact's numerical semantics.

**Experts.** Intermediate-width TP preserves every global expert ID; keep routing semantics identical across ranks and reduce local expert partials. Whole-expert ownership can use uneven expert ranges, so expert count need not be divisible by rank count, but token-to-expert IDs/weights and empty-rank behavior must be defined. Routing must consider the full expert/group domain before dispatch. At two ranks with replicated token activations, each rank can compute owned selected experts and reduce the weighted outputs; token all-to-all is not automatically necessary. Wider deployments can compare dispatch plans using measured route distributions. Do not assume uniform expert load or proportional speedup from "active parameters."

**Vocabulary.** Output-row sharding preserves complete quantized rows and global token IDs. Greedy/top-k can merge local candidates; general top-p sampling and requested log-probabilities need correct global normalization and sufficient candidates. Keep penalties, constraints, softcap, tied embedding semantics and RNG ownership unchanged. Start with gathered logits or a replicated head until the distributed sampling path is independently qualified.

## State ownership and phase changes

Extend existing request-owned CBv2 state semantics rather than putting mutable cache state in model-global objects. The existing complete-checkpoint identity already includes artifact hash, prompt contract, build and numerics fingerprints; the existing recurrent transaction enforces ordered commits and newest-first rollbacks. Reuse these concepts, plus actual observed attention/conv dtypes—Nemotron can promote activation/cache types, so a global BF16 assumption is unsafe.

For cluster migration, add plan/membership epoch, global layer/head/expert ranges, absolute visible attention intervals, position axes, alias-source relationships, request/cache scope and all committed-generation identities. Include target KV, convolution/SSM, assistant checkpoint/frontier, sampling/constraint history and the next un-emitted token ordinal. Quantized cache layouts need their actual scale/block metadata or a qualified canonical conversion.

Export only after all participating ranks have completed the same committed position and no speculative generation is pending. Materialize/evaluate lazy roots, retain source ownership until bounded transfer buffers are safe to reuse, validate every destination range and total coverage, then atomically switch the request lease to the new epoch. Release the source only after adoption succeeds. A failed or partial transfer does not publish a cache. A lost rank invalidates the old collective epoch; restore/recompute from a complete committed point rather than continuing with incomplete reductions. Token emission is coordinated with committed ordinals so retries cannot emit duplicates.

The current `CBv2CompleteCheckpointManifest` is a **disk-prefix** contract: it requires chunk-aligned positions, its tensor key is only role/layer, and it has no TP ranges. Its layout/codec cannot be reused unchanged for arbitrary decode-time cross-plan migration. Introduce a versioned cluster envelope/conversion capability first; preserve cache salt/tenant scope and the existing privacy boundary. Gemma borrowed-KV aliases must be reconstructed against validated source state, never serialized as pointers.

## How a measured selector consumes this

First reject plans that violate semantics, capacity, artifact/backend eligibility, or unqualified conversions. Then compare the remaining finite candidates using profiles keyed by artifact/adapter/build, hardware and GPU configuration, phase, local shapes, quantization/dtypes, prompt/context length, batch size, MTP mode, cache backend, rank count and transport. For MoE include observed token counts per expert and skew; for hybrid models separate recurrent-chain timing from projection timing. Record resident/peak/scratch memory, actual collective payloads and CPU/GPU synchronization, warm/cold distinction, repeated samples, and thermal/load conditions.

Operator profiles estimate a schedule's critical path: parallel branches use their dependency graph, pipeline stages include bubbles and load imbalance, and collective times include staging/fences. End-to-end measurements calibrate that estimate; do not sum timings that already overlap or count a transferred byte twice. Preserve unknown profile cells and test promising candidates in isolated shadow benchmarks. Interpolation is a labeled estimate within measured shape ranges; extrapolation gets uncertainty and cannot become an unsupported TPS claim.

Choose an objective explicitly: batch-one TTFT/prefill latency, decode inter-token latency, or aggregate committed token goodput under latency/memory limits. Report uncached input tokens and committed output tokens; never count draft or replay tokens as user goodput. Compare replicas, selective/full TP, pipeline placement, and phase-specific placement under the same workload. Prefill-to-decode handoff is worthwhile only after its measured transfer/repartition cost and competing-node load are included. RAM constrains feasibility; it is not a compute allocation ratio.

The first deliverable is a small set of correct, measured alternatives and reproducible profiles, not a universal optimizer with guessed speed tables. Add operators and plans when a model or a measurement provides a concrete reason.
