### `darkbloom --opencode` and `--hermes` say what happened to your default model, and where the models run

- OpenCode: Darkbloom's model becomes OpenCode's default only when neither of OpenCode's global config files sets one (`opencode.json`, `opencode.jsonc`; OpenCode 2 doesn't read OpenCode 1's `config.json`). Its own line says so: ``New OpenCode sessions now use Darkbloom's Qwen 3.8 27B. Switch back with /models.`` When a file sets one, nothing is written for it, and the line names it: ``Your default stays exo/llama-3.3-70b; pick Darkbloom with /models.`` The `Undo:` line stays.
- Hermes: Darkbloom still becomes the main model, and the line names the one it replaced: ``New Hermes chats now use Darkbloom's Qwen 3.8 27B (before: gpt-6-astra via opencodex). Switch back: hermes model``. Its headline matches OpenCode's (``✓ Hermes can use Darkbloom: 1 model.``).
- A start with a tool flag beside a local API that already serves names the URL the tools use, not the address it listens on: ``Darkbloom already serves at http://127.0.0.1:8001/v1; setting up OpenCode for it.`` (it said `0.0.0.0:8001` for a pair's).
- On the Mac that serves a pair's local API, the tools name the pair's models ``Qwen 3.8 27B (your pair)``, not `(this Mac)`, for a pair of any size; a run again changes nothing. Hermes makes the pair's model its main one, as it does this Mac's.
