### A Mac pair is offered to the coordinator for pairing by itself (DevNet)

- `darkbloom cluster` asks the coordinator for the cluster approval of this Darkbloom version (`GET /v1/cluster/approvals`). Each Mac checks the approval against its own installed app and model before it saves it, and both Macs save it, or neither does. Both Macs then run as coordinator-paired members, and the ready screen and the status say "Offered to the coordinator for pairing" with the approval and its end, instead of the local API line.
- The leader asks again at each start of its cluster service and after each Darkbloom update, and takes a later approval when the saved one ends within a day. An approval that ended is removed before a part starts, and the pair serves on the leader's local API again; the status says why in one line.
- When the coordinator of an offered pair gives no answer for 10 minutes (the absence grace), the pair serves on the leader's local API. When the coordinator answers again, the pair is offered again with the same approval while it is current. The status says which mode the pair is in and why.
- A coordinator without pairing (production, staging) answers that it has no approval: nothing changes, and the saved setups stay byte for byte as they were. `darkbloom cluster local` serves without the approval. The hand-saved approval of `darkbloom cluster configure` stays available.
