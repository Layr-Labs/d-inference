# Publish cacheable R2 model chunks

> Last updated: 2026-09-16 · commit `0f7b1e611`

Use this runbook to publish large model files as separate R2 objects below
500 MB, while preserving the original safetensors files after download.
The HF mirror keeps the original files. No GPU is needed for packaging.

## When to use

Use chunk transport for model files too large for the CDN object cache. Existing
manifests without `r2_chunks` retain their original download behavior. Publishing
also retains its original-file default until `R2_CHUNK_BYTES` is explicitly set.

## Prerequisites

- Deploy a coordinator with `r2_chunks` manifest support and the additive
  `model_version_files.r2_chunks` migration. Production operations follow the
  approval requirements in [the deployment runbook](coordinator-deploy.md).
- Release providers with `r2_chunked_downloads` support before promoting a
  chunked build. The catalog requirement prevents older providers from being
  assigned it. Retain an existing unchunked build for rollback.
- Download the original model and generate its manifest with
  `darkbloom-publish hash`. Use a **new version and R2 prefix**: never replace
  bytes at an already cached immutable URL.
- Have enough local disk for the original model plus the packaged model.
  `TMPDIR` controls the publisher's temporary package location. The provider
  assembles one chunk at a time; allow extra temporary space of up to one
  chunk per active file download (normally four foreground files).

## Package locally

The standalone tool accepts the manifest generated by `darkbloom-publish hash`:

```sh
python3 scripts/chunk-model.py \
  --manifest /data/original-manifest.json \
  --model-dir /data/model \
  --output-dir /data/r2-package
```

The output directory must not exist and must be outside the model directory.
The default chunk size is **480000000 bytes** (480 decimal MB). Values at or
above 500000000 are rejected. Each large file becomes, for example:

```text
model-00001-of-00021.safetensors.chunks/000000.bin
model-00001-of-00021.safetensors.chunks/000001.bin
...
manifest.json
```

Small files retain their original paths. The tool checks source hashes and
writes the output manifest only after all files succeed. A failed package can
leave partial output; inspect/remove that newly created directory before retrying.

For `EigenLabs/Qwen3.8-Flash-Next-MLX-4bit-mtp` at HF commit
`e555958420096f695d449111693a6647b698479b`, the 21 weight files total
106294664646 bytes and yield 228 chunks at the default size. Reserve a little
over 213 GB for both source and packaged weights, plus auxiliary files.

## Publish and register

With `R2_CHUNK_BYTES=480000000`, `scripts/publish-model.sh` runs the packager, uploads the generated
objects, and uploads `manifest.json` last. Large originals are not uploaded to R2.
It adds `r2_chunked_downloads` to the registration command when chunks are present.
Leaving `R2_CHUNK_BYTES` unset preserves original-file uploads and existing
capability requirements. The standalone packager defaults to 480000000 bytes.
The existing `HUGGING_FACE_ARTIFACT_JSON` setting retains the pinned HF mirror.

Source selection is per version: a configured HF artifact stays first, with R2
chunks as fallback. Set `hugging_face_artifact` to `null` at registration to use
the cached R2 path directly. This does not change other models' source selection.

### Already published Flash-Next artifact

The [publication report](../reports/2026-09-16-qwen38-r2-chunk-publication.md)
records the immutable version, original aggregate hash and observed cache hit.
Reuse that package; no re-upload or re-chunking is needed.

The model declares `qwen4_exp`, which current master does not serve. Native
integration is tracked in [provider PR #1030](https://github.com/Layr-Labs/d-inference/pull/1030)
and its pinned SDK dependency. Release a provider containing both native model
support and this transport before activating this model. Download success is
not inference qualification; retain the runtime PR's hardware, MTP, vision,
memory and API release gates.

Use these transport fields in the reviewed registration request:

```json
{
  "model_id": "EigenLabs/Qwen3.8-Flash-Next-MLX-4bit-mtp",
  "version": "2026-09-15-r2chunks-e5559584",
  "required_provider_capabilities": ["r2_chunked_downloads"],
  "hugging_face_artifact": null,
  "promote": false
}
```

This is a fragment, not a complete registration payload. Use the qualified
runtime's model metadata, context/output limits, RAM requirement and approved
prices in the existing registration workflow. Add any runtime-specific required
capabilities from that release. Registering a new model without promotion keeps
it out of the active catalog; validate on a designated provider before promotion
or alias migration. Production registration/promotion needs explicit operator
approval under the existing deployment policy.

Objects are served through the R2 custom domain (normally `models.darkbloom.ai`),
not the S3 endpoint or an `r2.dev` development URL. `.bin` is a cacheable default
extension, and the publisher sets `Cache-Control: public,max-age=31536000,immutable`.
Check the zone for rules that bypass caching or override TTLs. If necessary,
scope a Cache Rule to the model chunk paths and mark them eligible for cache.
Do not cache authenticated application responses as part of this rule.

Cloudflare documents a 512 MB cacheable-object limit for Free/Pro/Business
plans. The stricter publishing limit leaves room below it. See
[Cloudflare cache behavior](https://developers.cloudflare.com/cache/concepts/default-cache-behavior/)
and [R2 custom-domain caching](https://developers.cloudflare.com/r2/buckets/public-buckets/#caching).

## Verify before promotion

1. Confirm every chunk object is smaller than 500000000 bytes and the live
   coordinator manifest retains `r2_chunks`. Confirm the catalog includes the
   `r2_chunked_downloads` requirement and the intended pinned HF artifact.
2. Download the same complete chunk twice through the custom domain. Inspect
   response headers: the warmed request should return `CF-Cache-Status: HIT`
   (and normally `Age`). A successful upload or a small `Content-Length` alone
   does not prove caching. Account for the two complete chunk transfers.
3. On a test provider, exercise both HF success and an unavailable HF source.
   HF success should avoid R2 chunks. Fallback should request the `.bin` objects,
   reconstruct the original file, and pass per-chunk, per-file and aggregate
   checksum checks. Interrupt/restart the fallback and confirm verified prefix
   chunks are reused.
4. Confirm the published snapshot contains the original safetensors and
   tokenizer/config files, with no reconstruction directories. Verify model
   loading before promoting via the existing model migration procedure.

## Rollback

If rollback is needed, restore the previous unchunked build using
[the model migration runbook](model-migration.md). Retain its original R2 objects
until all providers have moved. The nullable database column is backward
compatible and need not be removed during rollback.
