## Concrete entry points

Target48 uses the actual full `Gemma4OwnedForwardSession`, original rank1 `Collective`, and `Gemma4MTPPullTarget`. Assistant24 uses rank0 of that same two-rank group and `Gemma4MTPPullAssistant`, the registered 94-tensor assistant, the registered three-tensor target embedding, and frozen `Gemma4MTPAuxiliaryOwner` with `.remoteAssistant`. The epoch/request/build/artifact/embedding identities come from the original job/owner; these classes authorize none of them.

After ordinary prompt prefill, the target evaluates/reconciles one actual width-one seed step. Its committed frontier is P+1 and its newly generated output token is the unfed initial assistant seed. `reseed(after:session:admitSend:check:)` obtains the real full29/window28 capture and pre-norm hidden through that session. The remote service learns the seed from this first target message; launch metadata never invents it. Both endpoints independently bind request SHA, initial frontier, maximum frontier and the original ledger scope. Each branch additionally binds seed, frontier, ordinal and hidden dtype.

`fill(draftCount:check:)` obtains 1–2 initial proposals. `verify(draftCount:session:admitVerification:check:)` selects the ledger window, sends another bounded credit, receives queued acknowledgment, evaluates the real `[seed,drafts]` target window (width at most3), pulls the completed lookahead, resolves greedy acceptance, reconciles actual target state, and sends the authoritative resolution. It returns publishable tokens only after the corresponding response. Full acceptance requires the next queued proposal to equal the actual target bonus before frozen-branch reuse. Rejection or bonus mismatch requires `retireRejectedBranch`, followed by a NEW actual target capture before reseed. The caller must retain at most the previous/current returned window; do not accumulate logits/hidden arrays in a history.

`finish` stops the auxiliary protocol and drains even unpulled work; it does not finish the target owner. If one output remains, finish the assistant first and execute the final ordinary target seed step. `cancel(session:check:)` first calls actual target cancellation and only then requests auxiliary cancellation. Any fault/deadline which prevents this exchange leaves no reusable release; the original bounded parent must retire both owners. Do not retry/reset a failed service/channel. Retain the service (and its failed native roots) in the original native owner through terminal cleanup.

## Serialization and actual completion

The single synchronous control owner sends requests and receives responses. Assistant responses are only replies; no background receiver, second sender, alternate socket or new physical owner exists. Inner records use a closed 256-byte layout in the existing fixed16KiB CPU-control frame, with exact version/opcode/scope/sequence/branch metadata and all unused bytes zero. A command and response share one sequence, then both endpoints advance once. Bounds and canonical padding are checked before dispatch. These ordinary research controls are not an encryption or new authentication claim.

The existing P2P contract forbids local model evaluation concurrent with its calls. The implementation preserves that contract: prepare the lazy batch, send **queued** response, submit one native async batch, join both native streams, read its bounded token result, and only then receive the next control. While the assistant does this, the other Mac may evaluate its target window. The queued response means accepted credit, not GPU completion, receiver consumption or retirement. The later pull returns completed tokens. Raw C async and synchronization statuses are checked in the existing native error scope. No timing/overlap effectiveness follows until real phase measurements.

One original `Collective` global lock remains authoritative. No call holds it while issuing a second same-process transport/model operation. Every control and tensor operation keeps the original check callback and independent process deadline. Native group/lease ownership is unchanged.
