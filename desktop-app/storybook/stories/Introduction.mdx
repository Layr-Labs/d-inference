# Darkbloom desktop UI audit, as stories

Every story renders the **real desktop components twice** with the same data:

- <span style={{color: '#fca5a5'}}>**Before**</span>: the code at `bfa75a2c` (`codex/desktop-mac-preview-20261012`, the base all PRs target).
- <span style={{color: '#6ee7b7'}}>**After**</span>: the same code with all audit PRs applied (local integration branch `preview/audit-final4-20261014`, `3862646f`: every open desktop audit PR at its latest head, through #1507, including the follow-ups on #1471, #1499, #1502 and #1503 and the CLI wording; also the next preview DMG).

How a new user gets from the website to serving (DMG, **Install the Darkbloom CLI**, check this Mac, link, start; macOS 27 or later, and what a Mac below it sees) is on its own page: {story('install-flow--docs', 'Install flow')}.

Each story says what was wrong and what the PR changes. Interactive stories run a **play step**
(watch the *Interactions* panel, or reload the story to replay it) and show a
**Sent to the runtime** log for each version, so you can see exactly which actions each version
would have sent. Nothing talks to a real runtime, account, or production endpoint: the native
bridge is mocked per version and data comes from the app's own test and preview fixtures.
