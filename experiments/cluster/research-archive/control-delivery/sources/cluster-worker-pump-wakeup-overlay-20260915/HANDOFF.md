# Wake the direct-child pump after command enqueue

The existing pump excluded the child-input FD from its `poll` snapshot while the outgoing queue was empty. Enqueueing a command did not interrupt that wait, so a later command could wait for the 50 ms watchdog timeout before its FD was considered writable. Incoming-event semaphore waits are unrelated and remain unchanged.

This isolated overlay adds `WorkerPumpWakeup.swift` and a small integration in `ClusterWorkerProcess.swift`. The helper owns a private nonblocking/CLOEXEC self-pipe and coalesces notifications into one pending byte. A successful bounded command enqueue signals it. Only the **first** fault transition signals it, so repeated deadline checks cannot create a self-waking failure loop. The pump includes the read end in its existing 50 ms poll, drains it, and reconstructs its input-FD snapshot on the next iteration. There is no busy-poll timeout reduction or global signal policy.

The helper serializes signal, drain, and close around its private state. Signal writes are one nonblocking byte; four EINTR attempts are bounded, with the original timeout as fallback if all are interrupted. The pump alone closes the read FD after leaving polling; the failed-launch path closes before any pump starts, and deinit handles an owner that was never launched. The writer cannot use a stale FD number after close because signal/close share the lock and the closed check. No external fence closes the reader during `poll`. Closing is idempotent and does not retry a potentially reused descriptor after EINTR. A wake-drain error disables that descriptor and follows the existing failure/fence path rather than spinning on a broken wake FD.

Command bytes, sequence advancement, queue limits, write deadlines, incoming framing, startup/lifetime checks, SIGTERM/SIGKILL grace, actual-child terminal evidence, and the `next`/arrivals path remain. The request source is the current MAIN version with per-rank partial-admission cleanup. All request/Pair/SSH/protocol files are unchanged. Matched timing-controller sources, prior binaries, frozen native bundles and MAIN were not edited.

`integration.json` maps five files: the two runtime files, two focused fixture files, and the Process runner append. `runtime.patch` contains only the runtime delta; `integration.patch` adds the fixtures. Apply only to matching originals. `base-pins.json` captures all 43 copied upstream inputs; `source-checks.json` records exact unchanged-file and preserved-body checks.

Verification:

- Existing Process 10 groups, actual provider-contract source check, four deadline children, two endpoint groups, four partial-admission groups, and four new wakeup groups passed together in 25.388 seconds, empty stderr (`checks-1` Process result).
- Focused checks use real kernel `poll`, 10,000 coalesced notifications, concurrent producers/draining, 40,000 signal/close calls with actual FD reuse, and an actual owned-child 128-token exchange within a four-second request deadline. The latter catches the old per-decision idle-poll delay; it is a CPU regression, not a hardware inference benchmark.
- All 13 existing local-owner SSH groups and the configured-owner compile passed in 16.364 seconds, empty stderr (`checks-2`). The initial SSH run passed those groups but lacked a copied final compile input; that failure is retained in `checks-1`, and the exact missing `Tools/ConfiguredOwner/main.swift` was added before the completed rerun. No runtime fix was needed.

Run the isolated suites with `bash workspace/libs/darkbloom-cluster/Tests/ProcessChecks/run.sh` and `bash workspace/libs/darkbloom-cluster/Tests/SSHChecks/run.sh`. These compile Foundation-only modules and run local invented workers/owners. No native model, GPU, real SSH, network, deployment or production action was performed. The kernel close test joins the reader before closing, matching the production single-reader contract; arbitrary callers closing an FD underneath a live poll are not supported.
