# V3 group retirement correction

V2 could treat a reaped leader as complete cleanup after its first group signal failed. A living descendant in that same group could remain, because successful leader wait skipped the kill retry and allowed watchdog cancellation. Frozen V1/V2, the V2 handoff identifying this condition, and their test results remain unchanged.

Only `worker_processes.py` changes at runtime. A private set records each group for which SIGKILL was accepted or `ProcessLookupError` confirmed absence. Cleanup retries unresolved groups after leader waits even when those waits succeed. Both closed-state publication and watchdog cancellation require leader retirement plus resolved group fencing. A graceful close checks group absence; finding a live group records cleanup failure and attempts SIGKILL. Existing error recording and operator-interruption precedence remain unchanged. No command, callback, timeout, output cap or event contract changes.

Accepted SIGKILL is a fence, not proof that arbitrary descendants have finished kernel work or been reaped. Workers that escape their owned groups remain outside this supervisor's guarantee. Persistent fencing failures keep cleanup incomplete and retryable. No model execution, numerical validator, resource admission or performance qualification is added.

The first Python 3.9 combined run passed all original 19 tests. Its three new methods reached the expected cleanup states, then failed because post-SIGKILL `killpg(..., 0)` returned EPERM rather than the fixture's assumed ESRCH; redundant test cleanup made the same assumption. That failing fixture is retained in `history/test_cleanup_v3-first.py`. Runtime was unchanged. The corrected fixture keeps the fake descendant's stdout open and uses a duplicate reader to observe EOF after SIGKILL, with a three-second observation deadline before the descendant's 30-second fallback exit. All three corrected methods passed; they cover four actual fake leader/descendant pairs. Both execution receipts are pinned in `checks.json`.
