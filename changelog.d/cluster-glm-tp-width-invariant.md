### GLM pair: speculative depth follows load without changing outputs

- A GLM-5.3-Flash tensor-parallel pair now verifies one NextN proposal a round while three or more requests decode together and two otherwise (`DARKBLOOM_GLM_TP_MTP_DEPTH_POLICY=load`, the default; threshold `DARKBLOOM_GLM_TP_MTP_LOAD_LANES`, 2 through 8, default 3), so a busy pair verifies fewer rows per accepted token: aggregate decode +15.6 % at four lanes and +9.6 % at eight in tp-check on the pair. It is on by default because two- and three-row verification windows are one arithmetic class on the pair (depth 1 identical to depth 2, depth 2 keeping only first tokens identical, every lane identical to its request alone at 2, 3, 4 and 8 lanes); the endpoint's c1 to c16 byte-equality check is the release gate. `DARKBLOOM_GLM_TP_MTP_DEPTH_POLICY=fixed` keeps depth 2 every round with the previous windows and load agreement.
- `DARKBLOOM_GLM_TP_WIDTH_INVARIANT=1` (implied by `load`) gives every verification row one arithmetic at any window width: a request's last round at its output limit verifies its token beside a discarded padding row, a window straddling the dense-to-sparse attention switch at 2,048 tokens projects its attention rows in one product, and four-row windows (depth 3) absorb their attention queries in products of at most three rows, so depth 3 matches depths 1 and 2 too. Prefill is unchanged. Both Macs' cluster services must set the same values (the owner forwards them to its worker and both ranks bind them into their load agreement).
