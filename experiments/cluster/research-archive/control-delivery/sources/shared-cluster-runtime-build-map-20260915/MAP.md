# Shared resident runtime in the normal Swift build

Source-only proposal, 2026-09-15. No repository changes, builds, dependency resolution or native work performed for this map.

## Selected placement

Create one repo-owned package `libs/darkbloom-cluster/` with a `DarkbloomClusterRuntime` library and a small `darkbloom-cluster-worker` executable. This is a sibling of, not an edit inside, the two MLX submodules. Move the selected runtime implementation into that package once; both the experiment target and product integration depend on it. Do not duplicate the 425-source executable tree in ProviderCore. Keep the actual Qwen model implementation in the existing `MLXLLM/Models/Qwen35.swift`.

Keep the library's model/plan/session/load/state/transport implementation internal. Its public facade should contain only typed model/peer/request identity, readiness, token/completion events, a resident controller and request retirement operations. A provider-side owner wraps that facade or its worker protocol and implements the already-tested `DistributedResidentExecutionOwner`; the runtime must not depend on ProviderCore. This avoids a package cycle and keeps MLX arrays and compact models out of provider callbacks.

The first product attachment should use a separately built native worker, with ProviderCore's owner doing bounded Swift process/pipe orchestration. It need not ship or execute the private Python benchmark launcher. The worker owns one peer's MLX process environment, collective, model and request state; the parent retains the lease until both workers acknowledge retirement or are fenced. One readiness event from one rank is insufficient. The library also remains usable in process for an explicitly 26.2-targeted experimental build later.

## Concrete build constraints

* `provider-swift/Package.swift:6-9` declares macOS 14; its normal release command at `.github/workflows/release-swift.yml:321` is plain `swift build --product darkbloom`. Selecting a new SDK alone does not raise the Cmlx deployment target.
* `libs/mlx-swift/Source/Cmlx/mlx-conditional/jaccl_conditional.cpp:23-41` includes the real backend only when **both** SDK and C++ minimum deployment macros are at least 26.2; otherwise it compiles `no_jaccl.cpp`. A Swift `@available` guard, linked metallib deployment target, or a new Swift library target does not change that C++ selection.
* Preserve the macOS 14 provider build. Build the new worker in its own scratch/build directory with the experiment's proven flags: `swift build --package-path libs/darkbloom-cluster --scratch-path <worker-build> -c release --product darkbloom-cluster-worker --triple arm64-apple-macosx26.2 -Xcc -target -Xcc arm64-apple-macosx26.2`. The shared package may retain macOS 14 declaration for value/API compatibility; the real-worker invocation must explicitly raise the whole dependency build, and its entry must refuse unavailable JACCL. Do not attempt two differently configured copies of Cmlx in one link.
* `experiments/cluster/inference/prepare_dependencies.py:20-25` only swaps the real TCP ring exclusion for its stub exclusion. It does **not** enable JACCL. Remove that generated dependency from the production worker graph; keep the overlay only in the separate loopback diagnostic build. The experiment can keep its root override while importing the shared package, but package identity must resolve to exactly one MLX checkout in each graph.
* `libs/mlx-swift/Package.swift:1` currently requires Swift 6.3 with experimentalCGen despite the root manifests' 6.1 headers. Reuse the working native toolchain, not a presumed Swift 6.1 compiler.
* Shared library dependencies are `Cmlx`, `MLX`, `MLXNN`, `MLXLLM`, `MLXLMCommon` plus system Foundation/CryptoKit/Darwin. Use the existing local MLX package identities and pins; no new MLX copy or Python source generator is necessary.
* Ship the same source-matched `mlx.metallib` using the existing provider metallib build/packaging pipeline. The current experiment copies it next to the executable (`build.sh:16-23`); worker startup must use the verified supported resource location. Real JACCL still requires the native `librdma.dylib`, supported OS/hardware and admitted actual device/coordinator matrix (`rdma.cpp:36`); compiling real JACCL is not device readiness.

## Move by responsibility, not by historical executable membership

1. **Core transport/control:** `Collective.swift`, `CollectivePointToPoint*.swift`, exact control/ACK and boundary types, `QwenResidentJACCLConfiguration.swift`, arithmetic/resource admission primitives. Keep actual rank/world checks, environment precedence and common device-matrix agreement. Move small `ProbeError`/hash/canonical serialization helpers out of `Options.swift`/`ModelLoading.swift`; replace direct diagnostic `log` use with an injected event sink.
2. **Qwen adapter/load ownership:** the used `QwenLayerStagePlan` and construction/ownership maps, `VerifiedCheckpoint`/SafeTensor reader, prepared source/stage validators, `VerifiedQwenLayerStageLoading` and receipt types. Include the separately reviewed selected-payload cache policy only after root selects that source revision. Preserve legacy caps and keep model/profile resource admission distinct. Extract `constructQwenModel` and required layout helpers from `ModelLoading.swift`; do not drag the broad `loadModel(Options)` dispatcher, synthetic/Gemma diagnostics or full benchmark loader into the dependency closure.
3. **Request execution:** `QwenLayerStageSession`, admitted request/schedule/boundary types and CBv2 owned state/stepping dependencies; move the actual long request body unchanged, and add pipeline's generation-only contract after its validation. Models and kernels continue to come from MLXLLM. Keep loader/collective/request serial ownership and checked native-error precedence.
4. **Resident facade:** refactor the useful lifetime scopes in `QwenLongPrefillResidentRankOwner.swift:6-45,56-159` and SoloOwner behind typed owner configuration, rather than exporting `Options`. `onModelReady`, request permit, post-retirement result, and model release are useful seams. The historical fixed four-request cohort command is a benchmark wrapper, not the shared engine API. Move `QwenStageMemoryObservation` out of `QwenLayerStageComparison.swift:5-16` so library ownership does not require a baseline comparator.
5. **Worker/product adapters:** a small worker Main installs process deadline/SIGPIPE/native error handling and invokes the library; a Swift parent owner implements `readiness/reserve/start/cancel/waitUntilRetired/release/shutdown` for `DistributedEngineFactory.makeBridge`. Its value protocol must support token events and explicit early clean stop; existing benchmark `result.execution` is terminal CPU evidence, not a streaming token protocol. Runtime-invalidated membership withdraws provider capacity.

Leave `Main.swift`, `Options` CLI parsing, `*Check.swift`, fixtures, synthetic constructors, baseline/numerical comparisons, phase trace CLI and all private auditors/benchmark parents under experiments/tests. Move tests which exercise moved pure runtime types into a package test target with `@testable import`; the remaining experiment wrappers call a deliberately small diagnostic facade. Do not make every historic type public merely to keep an executable test harness unchanged. Pure shared DTOs currently co-located with diagnostic code must be split first.

## Minimal ordered increment

1. Resolve the actual source baseline (root's payload-cache revision versus frozen JACCL revision); inventory the runtime dependency closure and extract the small mixed-file utilities/DTOs.
2. Move that closure into the single package, add a typed resident library facade and thin native worker, then update the experiment to import it. Verify unchanged diagnostic behavior against the same moved implementation before product attachment.
3. Build the real worker with explicit 26.2 C++/Swift flags and source-matched metallib, separately from the default macOS 14 provider; verify linked backend availability. Unit tests can still exercise pure admission/control without model work.
4. Attach the Swift worker-owning implementation to the existing opt-in provider factory. The existing 20 provider tests validate lifecycle with fake owners; they do not validate a native backend. Add bounded fake worker protocol/retirement tests, then root's actual load/generation parity.

Current resident long-prefill mode remains registered 9B, output one, and a fixed four-request benchmark. Pipeline's generation contract is required for real 128-token streaming, EOS/client-stop and per-token two-rank frontier confirmation; it is not supplied by moving files. MTP and new model adapters are separate later work. Hard native blocking remains process-fenced; moving it in process would lose that isolation unless cancellation/retirement is independently made interruptible.
