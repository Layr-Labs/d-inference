### Tool calls that break only their schema are calls, on every model

- A GLM-5.3-Flash call that left out a `required` argument, carried an argument the schema does not declare (`additionalProperties` absent or `false`), or filled a parameter without a type, of a union (`anyOf` string or null) or of another type was returned as its raw `<tool_call>` markup in `content` with `finish_reason: "stop"`, so agent loops stopped (#2156). One such call turned every parallel call beside it into text too. Agents that add a required parameter to every tool (oh-my-pi's `i`) hit it on most turns.
- A check of every served family found two more: Gemma 4 showed a call with an undeclared argument under `additionalProperties: false` as text, and MiMo V2.6 failed the response (500) on a value of a union or of another type. GPT-OSS, the Qwen 3.5/3.6/3.8 builds and Nemotron 3.5 Super and Lightning already returned such calls; a two-Mac pair parses on its leader exactly as one Mac does.
- The SDK's GLM, Gemma and MiMo parsers (`mlx-swift-lm` #434) now check their frame grammar and the declared function name only, as vLLM's and SGLang's do. Such a call is a call (`finish_reason: "tool_calls"`) with the arguments the model wrote; an `auto` request without `strict` returns it as generated, for the client to check. GLM: a value declared only as `string` stays raw text; any other value is JSON when it parses as one, else its raw text. MiMo: a value of a declared type other than `string` is JSON when it parses as one, else its raw text.
- When GLM's final calls do not all parse, each is decided on its own: a call is a call, and only a frame the parser still refuses (an undeclared function name, a repeated argument) is text. A frame that breaks the grammar (open at the end, misplaced or nested tags) still keeps every frame after it from being a call.
- Schema guarantees are unchanged and now reached: a call to a `strict` function that breaks its schema is refused (422), or leaves as generated once a streamed response has started (`DARKBLOOM_STRICT_CALLS_AS_GENERATED`), and a required or named `tool_choice` refuses such a call (422).
- `DARKBLOOM_GRAMMAR_ONLY_TOOL_PARSING=0` (or `off`, `false`, `no`) restores 0.10.13's parsing for all three families; `darkbloom start` passes it to the launchd provider. `DARKBLOOM_GLM_TOOL_TEXT_FALLBACK=0` still restores the 500 for a GLM suffix that does not parse.
