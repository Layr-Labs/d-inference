Account login · Swift owns the dashboard session

Reuse browser email sign-in and the existing device-code flow with purpose=desktop_account. Swift polls, stores a separate read-only session and owns all account reads. Deploy the prepared coordinator and console changes to enable this flow.

Device link · the provider retains its identity

The serving provider retains its device credential. Account sign-out does not unlink or stop this Mac. desktop serve and the serving provider can be separate processes of the same darkbloom executable, reusing ProviderCore and the existing CLI commands.

01 / NEW SWIFT CAPABILITY

Account session

Implemented separate read-only sessions through browser approval. Credentials stay in Swift; sign-out keeps serving intact. Coordinator and console deployment are still needed.

02 / EXISTING API EXTENSION

Complete earnings windows

48,800 lifetime records versus 1,000 returned in the audit. Summing the returned rows is not a complete seven-day total. Preserve integer precision and mark coverage.

03 / LOCAL RUNTIME FIELDS

Exact activity and capabilities

Publish input/output tokens, optional cache/reasoning counts and supported actions through native state. Prepared usage changes require a signed provider release to run in the serving provider.
