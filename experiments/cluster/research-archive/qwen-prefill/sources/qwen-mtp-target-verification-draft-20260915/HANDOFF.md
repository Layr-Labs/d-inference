# Private target verification transaction

This additive source overlay supplies the local target-state transaction missing from the corrected MTP proposal increment. It does not enable distributed MTP, change the serving driver, define a new peer protocol, or publish tokens. No compiler, native array execution, model execution or remote operation has been run for this overlay.

Apply the eight Runtime sources over the corrected proposal lineage in `base.json`. The only existing-file edits are `CBv2OwnedRequestState.swift` and `QwenLayerStageSession.swift`; arithmetic's proposal/assistant/probe files stay unchanged. The ordinary nil path is mechanically restored by `check_source.py`.

## Native ownership

`beginTargetVerification(profile:proposal:generation:ownerCheck:)` joins the proposal to the current continued generation control, exact loaded source/Plan/rank and session frontier. It refuses lookahead, replayed round UUIDs, missing decode capacity, and a byte-only substitute for the registered resource profile. It derives the actual base reservation and additional bounded residual, ingress, pre-norm, logit and token arrays before state mutation. The mandatory owner check must retain/charge the returned increment along with the existing assistant/transport allowance and enforce the original request deadline. There is no default callback. Existing actual-free, allocator, AC and thermal checks remain in force.

`stageTargetVerification(roundID:step:incoming:ownerCheck:)` performs one token at a time: step0 consumes the already agreed seed, step1 consumes the unaccepted draft. The output type is provisional and cannot enter ordinary committed boundary APIs. Both target recurrent evaluations remain pending. The production recurrent `bind()` reads `pending.last`, so step1 observes the seed's pending state. Both KV appends remain inside the speculative write scope. At most the existing three generations (committed, seed, draft) exist. Rank1 retains the raw pre-final-norm row from the same trunk call and evaluates it with the target output/state roots; rank0 uses its unchanged hidden trunk. There is no extra target trunk call or head evaluation on rank0.

`commitNextTargetVerification(roundID:ownerCheck:)` commits only the oldest pending recurrent generation and advances the logical committed frontier, while retaining the evaluated suffix and its full-KV writes. Its local receipt names both committed and still-pending inputs. Full KV remains at the speculative frontier until final reconciliation; the immutable committed prefix and actual confirmed recurrent generation are distinct from that pending suffix. Each raw hidden row is delivered once when its input commits. A second native forward is not needed to commit the next already-evaluated input.

`reconcileTargetVerification(roundID:keepingInputs:ownerCheck:)` accepts an already-committed…staged prefix (0…staged before any progressive commit). It prepares a value-copy schedule, rolls rejected recurrent evaluations back newest-first, commits retained evaluations oldest-first, trims rejected full KV, closes its speculative write scope, then immediately invalidates/rebinds the cache bank so device position offsets match host counters. Native KV/recurrent validation precedes both the core committed frontier and session schedule assignment. The returned receipt is LOCAL only. Zero retained inputs is a successful restoration; an error poisons and retires the whole request instead. Ordinary decode, snapshot and clean finish are refused while the transaction is active.

Cancellation is serialized by the existing owner and retires the whole request. It synchronizes native work, rolls back an evaluated active binding and pending generations in reverse order, abandons an unevaluated binding by releasing it, then uses the existing cache/backend/recurrent release checks. A failed native cleanup is an error requiring existing process fencing; a local receipt never substitutes for retirement/fence proof. Native-error checks remain inside the active handler, including the throw path.

## Owner integration still required

A later MTP owner must bind one accepted-input count to request/round/agreement/base/token chain and provisional residual identities, obtain matching actual local receipts from both ranks, and only then advance the bilateral control or publish output. The existing serial generation control does not accept a two-input verification ACK, and this overlay does not pretend it does. It must also carry cancellation/deadline checks while awaiting peers, fence blocked native work, and preserve all charges until provisional outputs and returned hidden rows release.

Returned rank1 row0 belongs to the consumed seed; row1 belongs to the consumed draft. Assistant history pairs row0 with an accepted consumed draft token, using the assistant's existing single final normalization. It must not pair the proposed token with row1 or append target output tokens that were never consumed as inputs. The local reconciliation result allows its retained hidden rows to be consumed once, only after actual local reconciliation; the owner still waits for the other rank.

Streaming owners must separate acceptance agreement from irrevocable input commit. After staging seed+draft, both ranks progressively commit the seed; the owner joins those two prefix receipts, publishes target token2 and receives the existing continue/stop decision. On stop it final-reconciles keeping1, rolling back only the still-pending draft, and clean finish matches the selected/committed frontier. On continue it can commit the already-evaluated draft on both ranks and publish the bonus, then close the transaction. EOS/quota may require keeping only seed even when the draft was speculatively evaluated. No API can roll back an already committed/published prefix. Ordinary decode remains blocked until final reconciliation, even when no pending inputs remain. For outputCount2 the request admits only seed evaluation. Final reconciliation can commit several remaining inputs for nonstreaming diagnostics, but a streaming owner must use progressive commits to preserve per-token stop semantics.
