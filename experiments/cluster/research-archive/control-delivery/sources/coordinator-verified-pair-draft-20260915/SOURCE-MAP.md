# Source map and scope

All paths below are repository-relative; their identities are bound in `compilation-snapshot.json` and `context-source-pins.json`.

| Source | Existing boundary | Candidate integration |
| --- | --- | --- |
| `coordinator/api/provider.go` — registered reader loop | `Register` returns the connection object after frame parsing; attestation/account continuation and challenge verification precede routability. Registration binds process X25519 key to SE evidence. | No edit. Future ACK/release handlers must use the reader's object. No textual provider ID may substitute. |
| `coordinator/registry/provider_lifecycle.go` — Register / disconnectProvider | Registry membership is live and rebuilt per reconnect; exact-object eviction protects replacements; disconnect clears pending load/request/session state, preserving stable fault history. | Pending pair removed on disconnect; active pair physical hold and Done invalidation retained separately from live provider entry. |
| `coordinator/registry/scheduler.go` — commitProviderReservation / routing gate chain | `r.mu` read plus one `p.mu` commit atomically rechecks/debits pending capacity. | Pair uses registry write lock and both provider locks; original shared chain rejects pair-held devices. Same exact-hold exception is used only for pair validation. |
| `coordinator/registry/dispatch_plan.go` — ReserveNextFromPlan | Current snapshot/gates and pending debit under the same locks, after a precomputed plan. | Unchanged; common gate rejects the held pair at commit. |
| `routing_eligibility.go`, `model_aliases.go`, `model_capacity.go`, `fleet_sample.go` | Common liveness/privacy/current challenge/state-restore gates feed aliases, public capacity, dispatch and eligibility views. | Pair-held devices return the new closed `pair_reserved` reason. No hold means unchanged eligibility. |
| `model_loading.go` | `pendingModelLoads` is planning, not solo capacity admission. BackendCapacity.Slots is authoritative; idle/running slots with no active work still contain loaded models. | Pair selection checks existing pending work; load-plan commit rechecks hold. Existing slot/heartbeat ingestion is unchanged. |
| `warm_pool_controller.go` | Separately copied gate chain emits granular warm/cold reasons. | Explicit pair exclusion; no reliance on the common liveness wrapper reaching this path. |
| `model_commands.go` | Catalog eligibility precedes unlocked WebSocket writes; desired-model writes serialize with their existing per-provider mutex. | Count in-flight nonempty model commands under r.mu/p.mu so selection cannot cross the write. Empty desired-model revokes remain allowed. IO holds no fleet/provider lock. |
| `provider_evidence.go`, `attestation_policy.go` | Hardware trust, SE/process binding, fresh code proof and current application-release evidence are separate. Solo enforcement may be shadowed. | Pair always requires current approved-release evidence and fresh code proof. Existing loss setters invalidate exact-object holds; release-policy generation changes invalidate grants before carrying evidence forward. No solo trust-floor change. |
| `gate_state.go` | Stable physical fault history has lock order r.mu → p.mu → gatesMu → gate.mu. | No mutation to gate history. Pair state is separate, under r.mu, and never autoexpires possible native ownership. |
| `heartbeat.go` | Capacity sequence and omission semantics are connection-scoped; idle means loaded; active_model omission means no model. | No edit. Pair preparation reads these values conservatively and additionally requires actual local preparation ACK. |
| `provider-swift/Sources/darkbloom/StartCommand.swift`, `ProviderCore/Service/ProcessLifecycle+DeviceExclusion.swift` | Current solo foreground acquires canonical exclusion before MLX and retains until process exit. Local distributed branch delegates ownership and returns before this path. | No edit. Control-only registered member mode is the next prerequisite; no in-place early release of a solo process gate is proposed. |

No durable Store fields change, so CachedStore invalidation remains untouched. No new protocol shape or endpoint is introduced in this slice; Swift protocol mirroring becomes required with the future wire integration. Actual owner cleanup/release ACKs must be supplied by that future trusted control path, and remain distinct from this registry's observation of them.
