### Two-Mac pairs: a stopped pair says what stopped it

- The words for a stopped pair were chosen by letters its cause happened to contain, so three causes read as something else. An unresolved device journal left by an earlier session read "One of the Macs is busy with other work"; it now reads "An earlier session still holds the cluster device of one of the Macs", and the next step names `darkbloom cluster recover`. Two Macs whose workers speak different versions read "The pair stopped (version_mismatch)"; they now read "The two Macs run different Darkbloom versions", a start stops waiting on it, and the next step names `darkbloom update` on both Macs. A worker that differs from the saved setup read "isn't verified by Apple yet … retries by itself"; it now reads "The pair stopped (worker_runtime_unverified)".
- After 15 minutes without serving, `darkbloom status` and `darkbloom cluster status` replaced every reason except two Macs on different versions with "The pair hasn't served for 15 min …". They now keep every reason that only a person mends: a Mac that isn't logged in, a Mac's clock, a model the coordinator doesn't let a Mac serve in a pair, different builds, a pair not offered to Darkbloom, and single-Mac serving on a Mac. A reason the pair is waited through still gives way to that line.
- When the leading Mac's session with the coordinator ended, its log line and both Macs' status said only "committed start ended". They now say how, for example "The pair stopped (committed start ended: the coordinator's grant expired)". A Mac on an earlier release shows the same text.
- Every other cause reads as before, for example "The pair stopped (peer_lost)". The two Macs of a pair can be on different releases: the earlier one still reads every stopped line this one writes.
