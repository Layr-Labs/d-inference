# Owner-supplied JACCL bootstrap

This private source proposal exposes the existing native `AllGatherFactory` initializer through a small C callback bridge. It provides an internal Swift callback adapter and a nil-default `Collective` parameter. The existing C initializer, C++ backend cache, JACCL serializers, connection construction, barriers, numerical collectives and default Swift call path remain unchanged. No main repository or submodule was edited.

`mlx_distributed_init_jaccl_with_bootstrap` always selects strict `jaccl`. Its arguments are the expected rank/world size, maximum per-rank and total raw bytes, a synchronous gather callback, an opaque context and a release callback. The C ABI sends the actual factory rank/size and a monotonic `uint64_t` sequence to the callback. Each callback receives a raw local contribution and an output region for the rank-ordered concatenation. The callback returns zero only after writing the whole output. It must not retain pointers, throw, reenter MLX or invoke another collective.

The new bridge serializes callback invocations, validates rank/size, rejects zero/oversize contributions, checks multiplication against the total bound, stages the result, checks the local rank's bytes were echoed unchanged, and copies to the native destination only on success. Errors poison that bridge instance permanently; the callback is not retried. This is a byte-transport contract, not authentication or a peer-consumption acknowledgment.

The C API permits 2–64 ranks, up to 1 MiB contributed per rank and an 8 MiB total maximum. The caller must provide a total bound large enough for its entire declared per-rank bound. The internal product Swift adapter further fixes the existing two-rank cohort to 64 KiB per rank/128 KiB total. Its closure receives the immutable membership UUID, actual rank/world size, sequence, copied `Data` and expected output byte count. It returns a copied `Data` result of exactly that size. No RDMA structure is redefined in Swift.

## Ownership and first initialization

With a non-null release callback, the C call consumes one context reference on every return path, including invalid arguments and factory failure. The release callback must not throw. The reference is shared with the native callback and may remain retained by the backend cache after every public group handle has been freed. Do not use reference-count release as evidence of native process retirement or assume `mlx_distributed_group_free` closes the owner channel.

The C++ cache ignores a factory passed after JACCL initialization. The new bridge records whether its factory was actually invoked and refuses a cached result before assigning the output C group. It does not clear, replace, reauthenticate or relabel the cached group. The old API retains its original cache behavior. This detects an already initialized JACCL backend, not all prior initialization of unrelated backends. The application must own initialization exclusively and use a fresh native child per membership epoch; the existing global native cache itself is not made thread-safe by the callback mutex.

A later change to the owner channel or membership does not replace the callback in a live cached group. Failure ends that worker's epoch. External owner-observed cancellation/fencing and process exit remain the authority for reclaiming the native worker and its resources.

## Hookup to the authenticated owner

1. The local Darkbloom worker-owner establishes the already authenticated SSH owner session and a dedicated local duplex channel before native initialization. Supply a dedicated inherited descriptor to the native child; do not multiplex these raw rounds with generation `WorkerCodec` stdin/stdout records.
2. The native worker duplicates and owns that descriptor in a channel object captured by the `JACCLBootstrap.Exchange` closure. This proposal does not open, duplicate, frame or authenticate a descriptor itself. The callback/context API is the ownership boundary; pipeline's remote-owner adapter supplies the actual descriptor and IO implementation.
3. Bind the channel to the immutable owner incarnation/lease, membership epoch, both configured peer IDs/build identities, exact rank/world size, connection configuration and topology. For each synchronous round, authenticate and bound epoch/rank/sequence/length, collect exactly one contribution per rank and return the raw concatenation in rank order. Duplicate, missing, stale or mismatched rounds fail the epoch. Bound all IO by a once-installed local bootstrap deadline; callback blocking must also be covered by the independently enforced native process deadline/fence.
4. Pass the bootstrap object into `Collective(transport: .jaccl, bootstrap: ...)` inside the existing MLX error scope, before any default distributed initializer. Current facade/worker startup does not yet supply this object; that final selection/FD wiring remains a separate reviewed change. The default nil path is still plaintext native bootstrap and must not be advertised as authenticated.
5. After native initialization, retain the ordinary source/Plan/load/request agreements and actual bilateral retirement/fence checks. Bootstrap success is not loaded-model readiness, resource permission or proof of physical data transfer.

The C++ `Config::get_side_channel` chooses the nonempty factory before its `TCPAllGather` branch. Therefore this selected path does not instantiate that native TCP listener. Existing registered local device/config validation remains required. JACCL's RDMA data traffic is not encrypted by this change; the intended scope remains the explicitly trusted pair and direct fabric.

## Native serialization limits

The pinned source currently makes four callbacks for a mesh: container length, destination bytes, then two integer barriers. Ring construction makes six: left length/data, right length/data, then two integer barriers. The adapter must preserve that ordering, including both barriers. C++ serializes the `Destination` values; Swift treats them as opaque bytes. The factory remains stored in the group's side channel even though these source call sites are initialization-only today.

`SideChannel::all_gather` interprets native scalar lengths before allocating its next container buffer. This existing behavior is unchanged. The callback byte ceiling alone does not bound an allocation induced by a hostile returned scalar length, and this proposal does not claim memory safety for arbitrary adversarial native payloads. Before forwarding these rounds, the authenticated owner must admit the exact pinned native topology/round sequence and validate scalar length/barrier rounds against that contract (including nonnegative, bounded compatible lengths); preserve native encoding rather than inventing a Swift RDMA layout. An explicit native scalar-bound enhancement may be preferable before supporting less-trusted peers. The current trust boundary assumes the source-validated native worker on each authenticated host. An authenticated host identity alone is not proof of correct native bytes.

## Validation and integration

- `bash Tests/run.sh`: PASS, 12 direct C++17 checks of the actual new state helper. Covers matching bytes/sequence, rank1 positioning, cached/factory absence, wrong/repeated binding, failed callback with untouched destination, local echo mismatch, size/zero refusal, exactly-once context release, reference retention and two serialized concurrent callbacks.
- `bash Tests/run-abi.sh`: PASS, three C/Swift ABI groups. Compiles the actual new C++ entry point, public C declarations and internal Swift adapter. Only the native factory/cache/group and MLX error handler are test stand-ins. Verifies epoch/byte delivery, one-shot Swift use, cache rejection, wrong-size failure and context retention after group-handle free until test cache destruction. No real MLX/JACCL/Metal/network work is linked.
- The first ABI harness failed because its header search path auto-discovered a second `Cmlx` module map. `history` retains the prior script and failure description. Only the test header-search root changed; runtime bytes were unchanged.
- The new `Collective` hook passed syntax parsing only. Full Cmlx/Runtime native integration compilation and real authenticated two-host bootstrap are pending root execution.

`runtime.patch` contains three public-header replacements, the new C++ entry/helper, the internal Swift adapter, and the narrow Collective replacement. Public C headers are copied in this repository: both include and framework variants must remain synchronized. The Cmlx SwiftPM source scan already includes new source files under `mlx-c/mlx/c`; no package source-list change is required. Shared Runtime already depends on Cmlx. The Collective base is the separately pinned shared-runtime copy in `runtime-origin.json`, not a main-repository file that existed when this proposal started.

`cmlx.patch` is the native/header-only subset and passed read-only `git apply --check` against main. `runtime-hook.patch` is the private shared Runtime subset; apply it only against the pinned Collective base. `runtime.patch` contains both subsets.
