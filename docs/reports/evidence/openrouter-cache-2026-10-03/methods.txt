This script reads saved results and payloads only; it makes no network calls.
Run: python3 summarize-study.py [--root STUDY_DIRECTORY] [--no-plots]

Readable tables: by-model-readable.csv contains a compact model overview; throughput-readable.csv contains one row per model/throughput input bucket, with actual input-token medians and separate timing/TPS sample counts. summary.json includes those same compact tables. Full CSVs retain all analysis fields. Token-axis labels use 1k=1024 tokens.

Primary comparative outputs exclude pilot and validated-pilot phases, which appear in separate validation outputs, and availability-short probes, which appear in separate availability outputs. Every recorded attempt is counted; rows are deduplicated only when source, timestamp, phase, index and response ID all coincide. Files are read once into a snapshot. An incomplete last JSONL line is deferred; other malformed lines are reported.

Success requires the runner's successful complete response, Darkbloom provider and no recorded error. A successful response containing only reasoning is still successful, but has no visible output. HTTP or streamed error codes 400/401/402/403/404/405/413/422 are configuration errors; 429, 5xx, stream and transport/incomplete responses are service failures.

Cache hit means reported cached_tokens > 0. Missing cached-token usage is unknown, not silently zero. Cache rate denominator is successful requests that reported cached_tokens. An additional conservative rate uses every success and treats missing usage as a miss. Token-weighted coverage is sum(cached_tokens)/sum(prompt_tokens) over those same reported successes.

Floor-eligible rates restrict those successful requests to reported prompt_tokens >=1024. They remove obviously sub-floor prompts from scaled model cohorts; they do NOT prove an actual capturable checkpoint exists (last-token exclusion, model schedule, packing, retention and all exactness/capacity gates still apply). Models using a reduced matrix are explicitly marked and have different measured contexts; aggregate model rates are workload-dependent, not a fair causal ranking. The by-phase table and actual input-token medians support matched-length comparisons.

Repeated-only primary rate excludes cold-control calls and the first successful request per model/system-prefix/template-control cohort. This harness varies suffixes and conversation history inside a cohort, so full-message hashes would incorrectly exclude every suffix variant. Revisits share their original cohort; concurrent-prime shares the concurrent cohort. First-attempt-excluded rates are also exposed. Pilot validation uses separate cohorts and never primes comparative denominators. Saved-payload message hashes are checked; overwritten or missing payloads use declared phase grouping, with a diagnostic count.

Wilson 95% intervals are descriptive binomial intervals, not a guarantee about production or independent samples. Serial repeats, routes and fleet conditions correlate observations. The workload is synthetic, and interrupted models have incomplete matrices.

Long-output rows are successful requests with >=128 reported completion tokens. Total output TPS = completion_tokens/(last_any_output-first_any_output), where any output is content or reasoning. Visible TPS is estimated as (completion_tokens-reasoning_tokens)/(last_visible_output-first_visible_output), and requires actual visible output. Counts and timing spans are measured at the client and include framing/batching effects. All tokens are divided by the observed first-to-last interval to remain comparable to the original study; the first event can contain multiple tokens. End-to-end TPS divides by complete elapsed wall time. TTFT-any and TTFT-visible are separate. Tail = complete elapsed minus last any output. Usage-after-last-output is also exposed. Old timing rows fall back to visible timestamps ONLY when reasoning_tokens == 0. Otherwise total streaming TPS/TTFT-any remains missing. Nonstreaming calls cannot supply streaming TTFT or stream TPS. Reasoning-token usage is the provider's clamped retokenized subset, so visible token estimates may contain special/framing tokens.

Expected cost uses the saved Darkbloom endpoint pricing snapshot, in USD per token: uncached_prompt*prompt_price + cached_prompt*input_cache_read_price + completion*completion_price, plus an explicitly priced cache-write component if present. Completion price includes reasoning tokens. Missing cached usage or a positive cache-write count without its price is unreconciled. Match tolerance is max(1e-10 USD, 1e-6*expected_cost). Pricing reconciliation is independent of latency and includes known billed failures. Reported cost may differ from account-level debits/fees.

Main matrix completion is established by each model's matrix.done marker or both .completed-valid-main/.completed-valid-throughput markers. Reduced matrix completion uses .completed-scaled. Completed means the runner settled its prescribed attempt sequence, not that all phases had the desired number of successes. A growing/incomplete matrix should be rerun after the runner finishes; artifacts describe their UTC generation time and file snapshot counts.
