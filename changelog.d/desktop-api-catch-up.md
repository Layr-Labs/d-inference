### The desktop API reads clusters, Darkbloom Sandbox, waitlists and local serving, and runs their actions

- New resources: `cluster` (`darkbloom cluster status --json` as this build prints it; when it can't be read, the same shape with `state: "unknown"` and why), `sandbox` (the add-on's status, with its last update check in Unix seconds), `sandbox-logs` (the agent log's last 200 lines, without terminal escapes) and `waitlists` (`darkbloom waitlist --json`, or why there is no list and whether linking the Mac helps). Each is read only when the app asks, and repeated reads share one run.
- The state snapshot adds `local`: how this Mac serves (`[local]` in provider.toml), where your requests go, whether an account key is saved (never the key), and how long Darkbloom stays paused for you.
- New actions: start with `network` (`--network`) or, on a paired Mac, `solo` (`start --solo` with its models); `cluster_leave`; `waitlist_join`; `sandbox_pause`, `sandbox_resume`, `sandbox_uninstall` and `sandbox_setup`, which reports its lines, the installer's stage and the one browser approval while it runs and can be cancelled; `route`; `route_key`, whose key goes to `darkbloom route key --stdin` on standard input only and never reaches the operation journal, an operation, a snapshot or an error; `local_settings` (me first, applied at the next start); `tool_setup` (`start --opencode` or `--hermes`); and `update_rollback` (`update --rollback --yes`). Contradictory starts (two ways to serve) are refused before anything runs.
- `darkbloom sandbox setup --json-events` (hidden, for the app) writes each line and each installer event as one JSON object per line; a SIGTERM ends it, or reaches a running installer as Ctrl-C so an enrollment waiting for approval goes on.
- `darkbloom sandbox setup` shows the installer's approval link, code and progress as soon as the installer prints them. It read the installer's output 16 KiB at a time, so they could appear only once that much had arrived or the installer had ended.
- `capabilities` names `cluster`, `sandbox`, `waitlists`, `local_serving`, `tool_setup` and `update_rollback`.
