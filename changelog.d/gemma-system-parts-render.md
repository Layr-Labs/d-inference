### Gemma 4 system messages render as text parts, as vLLM renders them

- A Gemma 4 26B request with a system (or developer) message whose prompt the coordinator neither planned for its prompt cache nor counted exactly, and every such request on the local API, now renders the message as the chat template's text parts. Those parts end in a space before the system turn closes, as vLLM-served endpoints render every such request, so `usage.prompt_tokens` and the prompt the model reads match theirs (OpenRouter's GPQA prompt: 88 tokens, not 87). List-shaped system and user content keeps its parts instead of being joined first, as Transformers renders it; the parts of a user list are trimmed one by one and join without a separator, as there.
- Requests the coordinator planned or counted keep the string prompt its prompt sidecar renders, so their cache receipts and deadline calibration still match; on the network most Gemma requests are planned and still count as before until the sidecar renders the parts too. Media requests and other models are unchanged. `DARKBLOOM_GEMMA_SYSTEM_PARTS_RENDER=off` restores the previous render on a Mac.
