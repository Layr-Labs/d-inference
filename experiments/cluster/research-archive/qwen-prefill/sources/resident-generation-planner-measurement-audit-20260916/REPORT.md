The resident reports cannot yet populate the planner's per-chunk service costs truthfully. No new report adapter or runtime change was made. The useful existing measurements are whole-request intervals and exact workload/Plan/retirement evidence; producer and consumer chunk intervals are absent. The smallest next step is an optional, bounded CPU observer on the existing generation driver, followed by a separate resident-report adapter. The old loopback adapter should remain unchanged.

This audit reads the current planner, qualified c35c resident generation sources, corrected 53f5b5a8 solo sources and common timing-controller sources. The exact 30 small source pins are in source-pins.json. It does not read a model, executable, current live output, or cross-host clock calibration, and performs no compiler, native or remote operation.

A validated optimized solo sample can already supply a baseline through the existing `validate_returned.py` result. That path performs the complete report/terminal/resource checks before returning timing. A new generic adapter that emits an otherwise all-null candidate would add no measured stage services, so it was not introduced. The planner should continue withholding candidate estimates/ranking when compute, overhead or complete memory evidence is missing.

The old measurement adapter has two separate restrictions: its packet parser admits only the old 9B long-rank two-record/phase-trace format and same-device loopback provenance; its action replay assumes the old received-ACK protocol. The newer resident driver is not merely that schema with another model name:

- `QwenGenerationLookaheadProducer.run` begins the next preparation after `sendBoundaryUntilSent` returns and the original producer wrapper is released. `sendBoundaryUntilSent` returns after local `collective.sendCompleted`; its comment explicitly disclaims peer validation/consumption. The receiver validates its payload later. There is no received ACK in this protocol. Do not move the producer's next preparation to a fabricated receiver-validation instant.
- `receiveBoundary` runs the consumer, then sends `boundaryConsumed`. Only after returning to the driver does `agreeGenerationToken` perform finite argmax and token agreement. The old trace included final selection in the consumption section before consumed ACK. Preserve the separate selection/ACK intervals.
- The current planner is intentionally a collapsed fork/join scenario, not a physical timestamp replay. Same-clock sender and receiver call durations may be measured; subtracting timestamps across ranks, summing overlapping waits, or calling an ACK wait a Thunderbolt cost remains invalid.

The minimal observation hook should use the existing Session/CBv2 observer seam and add only outer scalar markers:

1. Add an opt-in benchmark request observer to the existing resident reservation/start/driver path; nil preserves ordinary behavior. Keep all model forward calls, transport calls, native error precedence, resource checks, deadlines, per-token delivery and retirement unchanged. Reuse `QwenLayerStageSession.prefillChunk(observer:)` / `CBv2OwnerPhaseObserver` for optional graph/staging/evaluation/commit diagnostics; generation currently leaves that observer nil.
2. Capture complete local producer preparation before token-slice/session work and after the evaluated/committed residual and its existing hash/checks. Cover both the serial `runGenerationFrame` route and lookahead `prepare` route. On rank1, capture the local consumer call/checks separately from final argmax and token agreement. Session microphases alone are insufficient: stage0's residual serialization/hash occurs after `state.run` returns.
3. Add sender-local markers around header/ready, completed payload send, original-wrapper release and consumed drain; add receiver-local markers around payload receive/validation, consumption and consumed-ACK send. Record first-token selection/receipt separately. Export these as named local service/wait intervals. Do not automatically map them to `handoff_ns`, `completion_ns`, `startup_ns` or `return_token_ns`; overlapping protocol work and branch-start skew remain explicit unknowns for the collapsed scenario.
4. Bind records to the actual request UUID/fingerprint, membership epoch, agreement, rank, Plan/stage/storage/build/numerical policy, admitted prompt/chunk/frontiers and active scheduling protocol. For the current 8K/C512 scope, bound prefill-only recording at 512 events per rank. Derive any larger frame/event allowance from admitted geometry before allocation. Charge the bounded recorder and final serialization scratch to the existing owner resource reservation. Retain CPU scalars only; no tensor references, new forward pass, global trace, hot-path file I/O or clock-alignment claim.
5. Seal/export after the complete request and bilateral retirement succeed. A recording/clock failure must preserve pending native/deadline errors and fail the request; an incomplete trace cannot enter measurement aggregation. Use a new resident trace schema, closed replay of the actual resident actions and all existing terminal/canonical exclusion gates. Keep old 9B loopback data and parser unchanged.

With those markers, a new bounded adapter can validate exact per-rank local service arithmetic and attach only the measured chunk compute intervals to the matching native candidate. Hardware placement, resource profile and execution/numerical provenance need explicit pinned inputs; unrelated candidates remain unmeasured. Transport/startup/completion costs remain null until separately supported. A same-origin round-trip/payload microbenchmark can provide a separately named transport observation, but cannot manufacture a one-way offset or turn peer wait time into wire cost.

Future protected-transport observations must retain their own authenticated transport/security-policy identity and exact binary/prelude provenance. Existing cleartext JACCL measurements or standalone codec timings cannot be relabeled as an encrypted end-to-end transport cost. This audit grants no public capability, execution admission or performance qualification.
