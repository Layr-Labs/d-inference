### Gemma 4 Checkpoint F: Pre-Layer-0 Block-SDCM hyper, fused DFlash with staged stepped KV cache, and Hi4 sparse ordinary decode history

- Upgraded opt-in `Block-SDCM hyper` (`DARKBLOOM_GEMMA4_PREFILL_SDCM=hyper|extreme|v4`) to perform Pre-Layer-0 (`earlyPreCompactAfterLayer = -1`) embedding Tri-Signal pre-compaction using 32-token blocks (`30%` retention, `topHaloK = 10`, stripping filler and heterogeneous Mode B right-padding before Layer 0 runs) with `k = 4` MoE on Layer 5 for sharper full-attention bilateral scoring and `16%/10%/8%/7%` retention at L6/L12/L18/L24.
- Added `CBv2SparseHeadSampleableModel.forwardHiddenForSparseHeadWithMTPHidden` and `trySparseDecodeSample(..., returnsHidden:)` so non-recurrent continuous-batching decode steps carrying persistent DFlash history (`B >= 3` ordinary decode) remain on `Hi4/Lo4` sparse LM-head sampling instead of falling back to full 8-bit `lm_head`.
- Added zero-extra-RAM load-time `QKV`/`KV` and `GateUp` fusion (`prepareFusions()`) in `Gemma4DFlashDraftModel` (`45 -> 25` draft linear dispatches per pass, protected via non-`Module` slots and `ParameterUpdateObserving` invalidation) plus a staged stepped (`step = 256`) full-attention `Gemma4DFlashLayerCache` that eliminates `O(T^2)` KV copies over long thinking trajectories while preserving exact O(1) `discardRound` rollback and in-place Metal buffer donation.
- Limitations: `Block-SDCM hyper` remains opt-in (default `off`) and DFlash still requires an external `DFlashDraftModel` checkpoint directory configured via `mtp_drafter_path`.
