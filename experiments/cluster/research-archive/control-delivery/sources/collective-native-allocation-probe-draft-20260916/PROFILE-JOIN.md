# From observed allocation to an enabled correctness candidate

The follow-up profile must be a closed internal catalog entry, not JSON-decoded authority. Parent evidence must first bind every report to the exact source/SDK/build/resource bundle and actual machine/OS, all fixed case IDs, actual process exit/reaping, the canonical empty-journal gate, and the unchanged native tail fix. Missing observations, unexpected errors, nonzero final native allocation/cache or unauthenticated publication refuse derivation.

For each observed process, retain the actual native peak and OS lifetime maximum. The conservative physical increment is `max(0, lifetimeMaxAfter - currentFootprintBefore)`. Never subtract two historical maxima or infer a host-only allocation by subtracting native bytes from OS footprint. The same-process mailbox deliberately includes both codec endpoints, source and validation overhead; charging its entire peak on each real rank is conservative, but does not prove RDMA-buffer/group memory. Record that limitation.

Choose the maximum across fresh and reused/failure cases for the admitted dtype/shape domain. Keep derived native-array/frame bounds separate, add a nonzero reviewed safety allowance, and charge both the resulting physical/host reserve and the derived native staging even where this double counts. Session creation has its own fixed reserve. Bind the profile to suite, exact code/tail/build family, hardware/OS/cache policy, maximum plaintext/frame, one operation in flight, observations/receipt digest and explicit safety bytes. The initial profile may use a narrower BF16/control domain if only that subset passes; unmeasured shapes cannot inherit admission.

Opening the facade needs three concrete edits after measurements: (1) add the one reviewed catalog case to `CollectiveProtectedResourcePolicy` with private construction; (2) add its fixed session cost to actual load checks and its maximal operation reserve alongside state/fusion/recording/lookahead in Ready, reserve/start and live checks, preserving six-GiB headroom; (3) reserve the worst-case directional record/byte envelope under the actual serialized owner, including post-state-release retirement ACK, before any request begins. No Ready or capacity claim comes from a counter snapshot alone. Recheck source/profile binding before creating the native group.

Then run a short real encrypted two-rank correctness request, retained-state/token comparison, tamper/cancel, and actual retirement/release proof with fresh coordinator-verified membership/key authority. A successful allocation probe is not encrypted RDMA qualification. The existing plaintext API and workload remain unchanged throughout.
