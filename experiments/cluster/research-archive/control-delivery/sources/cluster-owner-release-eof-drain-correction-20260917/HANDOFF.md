# Drain owner protocol through EOF

This is a source-only one-file successor to the actual c43 candidate `eb981ab1`. Its rebuilt helper passed all 17 steps, and its Provider run passed 111 of 112 methods. The remaining five-second combined-mesh refusal test did not observe the signed release message. The key-only refusal passed. Original sources, helper, failed run, and both unchanged five-second assertions remain retained.

The endpoint reader currently checks `!process.isRunning` after accepting each owner frame. That can discard a release ACK already written by an owner that exits while the terminal callback is returning. `ClusterOwnerPipe` already drains its pending frames before reading again and treats actual pipe EOF as closure. The correction removes only the process-state shortcut. The original lifetime plus two-second bound, diagnostic drain, native terminal identity, explicit ACK validation, actual owner exit status, and process reaping stay unchanged. A writer retained after owner death is still bounded by the original deadline.

The existing failed test has no retained endpoint receipt, so it does not by itself prove this race caused its missing public release. The race is a concrete independent source defect. The new deterministic actual-owner control is staged to prove or refute that explanation before qualification. No test or compilation has run for this correction.

The four new controls use the real `ClusterWorkerOwnerService`, its actual private lease, and an actual CPU child which emits forbidden Ready without opening bootstrap. A test-only relay records the real Service release ACK. A synchronous native-relay cancellation callback holds the endpoint reader until that owner has actually exited. The writer can send release while the reader is held; no test signal is sent. This places the real ACK in the pipe before the old process-exit check runs.

The valid case requires actual cleanup, the current-owner ACK, normal owner exit, and an empty reusable private journal. Negative cases suppress that ACK, alter its incarnation, or make the actual owner exit with status 9. None may return successful release, even though the real Service has cleared its journal. The retained baseline executable must demonstrate ACK loss using the identical fixture source. Timing and PID observations are fixture controls, not physical model evidence or an ownership grant inferred from process absence.
