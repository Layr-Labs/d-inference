### Opt-in PR CI, hardened Darkbloom routing, and CI cost reductions

- Pull-request macOS test suites in `ci-dev.yml` and `ci-master.yml` are now opt-in via the one-shot `run-ci` label (`gh pr edit <PR> --add-label run-ci`), while `Release Integrity` and `Docs Lint` keep running automatically on `master` PRs and `master` PRs respect `scripts/ci-component-paths.py` diff filtering.
- Non-blocking `Cluster GPU Tests (shard 1-3)` now run only on `master` pushes, manual dispatches, or PRs labeled `run-gpu-ci`, skipping routine PRs and `dev` pushes.
- `darkbloom-route.yml` retries transient plane failures up to 6 times with bounded exponential backoff, `darkbloom-watchdog.yml` no longer cancels partially completed or active Darkbloom attempts, and `scripts/ci-tested-tree.py` deduplicates squash merges and skips build jobs on tested trees.
- `release-dev-branch.yml` (6-hour schedule + dispatch) and `provider-release-cache.yml` (daily schedule + dispatch) now coalesce behind cheap `ubuntu-24.04` diff gates while keeping macOS release jobs on Blacksmith; `threat-model-review.yml` is now opt-in via `run-threat-model`; public Linux orchestration/utility jobs moved from paid Blacksmith Linux runners to free `ubuntu-24.04`; dead `ci-dev-hourly.yml` was removed.
