### Muse Glimmer 30B drafter: wide batched rounds by default

- The Muse Glimmer 30B drafter shares rounds and passes between requests by default, with three switches to change it. A switch changes only how often drafts are accepted, never the output: acceptance stays exact, and the `DARKBLOOM_MTP_` prefix keeps each setting's SSD checkpoints apart.
  - `DARKBLOOM_MTP_MUSE_GLIMMER_ROWS`: `wide` (the default) lets up to four decoding requests share an exact round, drafting three tokens each at two rows (the 8 verify rows of one request at depth seven) and two each at three or four rows. `2` keeps two per round and `1` one, the binding before shared rounds.
  - `DARKBLOOM_MTP_MUSE_GLIMMER_BATCHED`: `1` (the default) lets the requests of one step share the drafter's context commit, block forward and head product, so its weights are read once per step instead of once per request. `0` takes one pass per request.
  - `DARKBLOOM_MTP_MUSE_GLIMMER_COUPLED=1` (opt-in, off by default): a sampled request's drafts are raced with the noise of the target's own verify draw. Greedy requests are unchanged. Measured so far, this lowers sampled acceptance, so leave it off.
  - Each is forwarded to the launchd provider job; any other value keeps the default and logs a warning. Other models ignore them.
- Measured on an M5 Ultra with the defaults against drafter off (aggregate tokens per second, short / 2K / 8K prompts): 1.78 / 1.79 / 1.41 × at 2 concurrent requests, 1.12 / 1.04 / 0.99 × at 4, and 0.90 / 0.89 / 0.92 × at 8. At 8 concurrent requests more rows decode than a wide round holds, so the drafter drafts almost nothing and costs about 10 % against drafter off. Every setting gave the same greedy bytes as drafter off.
- `DARKBLOOM_DEBUG_MTP_RECEIPTS=1` keeps each finished request's MTP rounds, proposed and accepted counts, decode rows and engine timing (no text, token ids, sampling values or request identity). Only `darkbloom start --local --no-auth` serves them, at `GET /v1/debug/mtp-receipts`.
