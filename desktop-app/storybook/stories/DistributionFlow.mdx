# Install flow: from the website to serving

Darkbloom is **CLI-centric**. The desktop app is how most people get the Darkbloom CLI onto
their Mac and set it up; the CLI owns the background service that serves models (the
“backend”) and keeps it current (`darkbloom update`). The app installs the CLI, checks the Mac,
links the account and starts serving, and afterwards shows what the CLI is doing.

**Darkbloom needs macOS 27 or later.** It no longer accepts new providers on macOS 26 or
earlier: the installer ({pr(1505)}, against `master`) refuses a new install below macOS 27 with
a prompt to upgrade, while existing installs can still update. The app enforces the same rule
before the installer ever runs ({pr(1506)}): it reads the macOS version from the main process
(`api.system()`), and an unknown version is never treated as too old.

> **Status.** The app side is in the After tree of these stories (`preview/audit-final4-20261014`,
> `3862646f`, also the next preview DMG): {pr(1504)} (click-only install, progress, Cancel,
> Retry), {pr(1502)} (step order 1 Install CLI → 2 Check this Mac → 3 Link your account →
> 4 Start, CLI wording) and {pr(1506)} (the macOS 27 gate). {pr(1505)} (the installer) targets
> `master` and isn't part of the app; it has no story.

## Step by step

| # | The user | What macOS shows | What the app shows |
| --- | --- | --- | --- |
| 1 | Downloads the DMG from the website | The browser's download. The DMG is signed and notarized | — |
| 2 | Opens the DMG and drags Darkbloom to Applications | The DMG window and the copy. **No code runs** on mount or drag; macOS gives the app no chance to run here | — |
| 3 | Opens Darkbloom from Applications | The standard first-launch confirmation for a notarized app downloaded from the internet (““Darkbloom” is an app downloaded from the Internet. Are you sure you want to open it?”) | Onboarding, step 1: **Install the Darkbloom CLI** (“Darkbloom runs on its command-line tool. It installs once, runs a background service that serves models on this Mac, and updates automatically.”) with **Install CLI**. Nothing is installed yet. Below macOS 27: “Darkbloom needs macOS 27 or later” with **Open Software Update**, and the flow stops here (see above) |
| 4 | Clicks **Install CLI** | On macOS 27: **no administrator password and no permission prompts**; only the system's “Background Items Added” notification when the CLI's background service is registered | Progress in plain words: “Downloading the CLI… 42%”, “Verifying the CLI’s signature…”, “Setting up this Mac’s identity…”, “CLI installed. Starting it…”, with **Cancel**. On failure: “Couldn’t install the CLI while …” with the installer's reason, **Retry** and **Get help** |
| 5 | — | — | The CLI's service connects; onboarding moves on by itself to **Check this Mac** (about 3 s). An ineligible Mac stops here, with the waitlist; it is never asked to link |
| 6 | Clicks **Link account**, then **Open link page** | The default browser opens the link page, only on that click | **Link your account**: the link code, large, with **Open link page** and **Cancel**; “Waiting for approval…”. A Mac that is already linked skips this step |
| 7 | Enters the code and approves this Mac in the browser | — | The link step is checked; **Start** follows |
| 8 | Clicks **Start serving with Autopilot** (or chooses models under Advanced) | — | Serving starts and Home opens |

**Explore the app first** leaves onboarding from any step once the CLI's service has sent its
first snapshot (before that there is no app to open). People who finished or left onboarding
see a short startup screen on later launches, never onboarding again.

## Updates

The CLI owns the backend and its updates: `darkbloom update` installs a new version, and the
app's **Updates** page and This Mac's required-update step run the same update. An installed CLI
that is too old for the app shows **Update CLI** at step 1; a broken one shows **Repair CLI**.
Returning users see the same in the startup screen (“Update the Darkbloom CLI to continue.”).
This Mac's Overview words its own connection step in CLI terms too since {pr(1506)} (“Install the
Darkbloom CLI”, **Install CLI** / **Repair CLI**; it said runtime before).
