# Protected 9B numerical evidence, source only

This private successor keeps the registered 9B cut16, serial P32/C16/O2, BF16,
greedy, MTP-off, empty-stop experiment. It reuses the original resident owner,
`reserveRecording` and `recordQwenLayerStageGenerationRequest`; it does not add
a decoder, state owner, collective, serving route or public approval.

The optional saved `nativeMember.numericalEvidenceDirectory` is read again by
the original installed owner and forwarded to its original native factory as
`--protected-evidence-directory`. The directory must already exist, belong to
the current user, have private permissions, and open without following its final
component. Omission preserves the smoke request path. Both ranks must select
capture for a numerical run. No environment flag or request-supplied path is used.

The native worker uses the existing recording Ready and reservation, including
the asymmetric rank 1 row charge. The shared recorder captures the final native
row after the existing final decision ACK and all local state components before
request retirement. After bilateral retirement and local lifecycle exit, the
new synchronous publication closure writes CPU values while the original
reservation remains held. Only successful publication, live checks and the
original deadline permit `control.completed`. Any failure poisons the owner;
the retained member/owner cleanup and actual lease release obligations remain.

`ResidentEvidenceSink.swift` is byte-exact qualified phase-source reuse. It
creates `<actual-native-request-uuid>.json` exclusively with mode0600, writes in
64 KiB pieces, checks original deadline/resources, and syncs file and directory.
A partial failure remains and cannot be overwritten. Cooperative checks cannot interrupt a blocked write or fsync; the existing enclosing worker/owner hard process fence remains required. No evidence is written to
the native stdout protocol. The synchronous Data publisher must release its
buffer; a retained buffer causes failure. The writer never accepts secret fields.

The new export adds no MLX evaluation. The original recording path does perform
its existing final-row and state capture/evaluation; this run is correctness-only
and must not be reported as serving throughput. File I/O and encoding run after
the original core returns. Original production core, capture, state and request
publication implementations are pinned in `controls.json`, without edits.
