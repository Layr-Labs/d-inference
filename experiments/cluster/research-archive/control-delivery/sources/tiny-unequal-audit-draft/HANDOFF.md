# Prospective tiny12 unequal-split output audit

This CPU-only, out-of-repository audit admits exactly thirteen JSONL records from the new `qwen-layer-stage-check`: the existing eleven-record tiny8 prefix, then an ordinary baseline checkpoint and `qwen_layer_stage_unequal_cut_recording_check`. It reads no checkpoint weights and starts no processes. Native execution, stderr admission, source/binary provenance, resources and cleanup remain root-owned, separate checks.

Run the frozen helper only after root's guarded invocation completes:

```sh
python3 -B tiny_unequal_audit.py SAVED_STDOUT
```

`validate_file(path)` returns a CPU result; `validate_records(rows)` supports a caller that already parsed the output. The CLI requires strict JSON on every one of thirteen nonempty lines, rejects duplicate/escaped-duplicate keys and nonfinite numeric spellings, and reads at most 8 MiB plus one sentinel byte. Native `-0` is preserved for BF16 logit reconstruction. The new suffix is closed, including optional-logit omissions; unknown fields, nulls, floating integer substitutions and booleans in non-flag fields are rejected. Existing prefix report semantics are preserved.

The prefix uses the exact three old audit functions by AST extraction from the pinned original source (`569a9532…91518`). No imports or executable launcher body from that file run. The separate new numerical helper keeps the frozen recorded oracle (`ba943e3e…d29e4`) with the finite tiny8→tiny12 and equal→4/8 substitutions recorded in `recorded-oracle-tiny12.diff`. It rejects the old real-model expected branch; no old helper or tolerance is modified. The source check binds the unchanged request, frame, state, logit and fingerprint algorithms, except the expected state count.

`tiny12_expected.py` independently derives the wrapped BF16 tiny12 configuration, compact 4/8 construction configurations, exact stage/whole fingerprints, all active parameter names/shapes/dtypes, inert placeholders, local/global mapping and storage totals from the pinned constructors and fixture writer. The finite Plan serializer handles Foundation's `activeModuleRoots` before `activeMTP` key order explicitly; it is not a generic Foundation float encoder. This fixture contains only integer/bool/string metadata. Derived source totals are 352 tensors and 1,855,336 bytes, split118/234 tensors and630,648/1,224,688 bytes. Stored F16 layer quantization metadata is186 tensors/190,752 bytes; inert parameters are512/256 bytes. The config's distinct `tiny-layer-stage-12x4` marker is bound by its SHA. The prospective expected metadata file and derivation sources are pinned in the manifest.

The suffix checks exact source/config/plan/construction/storage identity, complete disjoint source inventory, the fixed prompt65/chunk32/output4 with teacher `[12,25,38]`, six frontiers32/64/65/66/67/68, all27 global state components per frame, and four full512-value BF16 logit pairs. CPU reconstructs all eight encoded native rows, preserving signed zero, verifies each row SHA and compares the two rows byte-for-byte. State shapes/dtypes/byte counts and aggregate hashes are independently reconstructed; raw state payloads are not exported. The two recording requests must have different UUIDs. No target checkpoint content hash or native numeric result is predicted from RNG.

The invented fixtures in `tiny12_fixture.py` are test inputs, never numerical evidence. Thirty focused CPU tests cover successful bounded file replay, preservation of old-prefix failures, ownership and plan mismatches, equal-byte shape changes, request/frame drift, changed candidate values with a freshly recomputed SHA, signed-zero loss, state omissions, cleanup flags, schema changes and IO bounds. No actual native candidate was read while drafting or testing. No Swift compiler/native/GPU/SSH was used.

Limits: a passed audit validates the encoded evidence and its source-derived contracts. Per-entry state SHA equality, native handle ownership and model release flags still rely on the native code; the parent must bind the saved source archive/binary and separately admit resource/process/cleanup receipts. This audit neither revises the retained earlier legacy parent failure caused by unexpected stderr nor admits stderr itself. F16 conversion logging is a separate source-derived launcher contract. It establishes no throughput, transport, multi-GPU, hardware-target or causal performance claim.
