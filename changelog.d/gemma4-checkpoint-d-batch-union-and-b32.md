### Gemma 4 batch-union active-set MoE routing, opt-in high-concurrency B=16..32 compiled continuous batching, and compiled-safe SAM batch gating

- Added opt-in decode-only batch-union active-set MoE routing (`Gemma4DecodeMoEBatchUnionPolicy`, `DARKBLOOM_GEMMA4_DECODE_MOE_BATCH_UNION=off|auto|32|40|48`, default `off`) for continuous-batching decode (`B >= 4, S == 1`, outside row-independent `Gemma4BatchDecodeProjection` / `Gemma4PrefillProjection` scopes), ranking experts in FP32 by max per-row margin below peak with degenerate-row masking and mean-probability tie-breaking to guarantee every non-degenerate row's #1 expert for `B <= M` while capping unique expert DRAM loads at `M`.
- Added opt-in high-concurrency continuous-batching overrides (`DARKBLOOM_ENGINE_V2_MAX_CONCURRENCY_CAP=1...64` in `ServingPerformanceProfiles`, default legacy `8`, and `DARKBLOOM_GEMMA4_COMPILED_FEEDFORWARD_MAX_ROWS=16...64` in `Gemma4CompiledFeedforwardCache`, default `16`) wired through `requestedConcurrency`, `WholeMacServiceBudget`, `UnifiedMemoryCap` (`+256 MiB` per slot above `8` activation floor scaling), and `runtimeOverridesAreAbsent` so high-memory hosts (such as 512 GB M3 Ultra) can qualify `B = 16..32` compiled continuous batching without widening default ceilings or reviewed profiles.
- Hardened `CBv2SuffixTreeDrafter` for `B >= 2` continuous batches by capping draft depth to compiled-safe widths (`depth <= 2` at `B = 2`, `depth <= 1` at `B >= 3`) and requiring post-cap `>= 50%` strong-match (`matchLen >= 4`) batch profitability so non-repetitive continuous batches incur zero false-positive speculative stalls while keeping `B = 1` code-edit acceleration intact.
- Limitations: all Checkpoint D knobs are opt-in and preserve existing default ceilings (`8` / `16`) and exact routing when unset; `DARKBLOOM_ENGINE_V2_MAX_CONCURRENCY_CAP` and `DARKBLOOM_GEMMA4_*` disable reviewed serving-profile matching so expanded runs stay explicitly unqualified.
