# Provider Protocol v1 Compatibility Inventory

Generated by `make contracts-update`; do not edit by hand. Full field documentation lives in [`protocol-messages.md`](./protocol-messages.md).

Protocol v1 uses JSON WebSocket text frames and has no explicit protocol negotiation. The Rust migration must decode every case below before any v1 traffic is accepted.

## Compatibility rules

- Unknown additive JSON fields are tolerated; unknown message types are rejected.
- Omitted, explicit `null`, zero, and `false` are distinct where the golden cases say so.
- Signed registration attestation and status canonical payloads are byte contracts, not semantic JSON contracts.
- Legacy `hypervisor_active=false` remains decodable because old provider signatures cover it.
- `encrypted_response_chunks` means base64 ciphertext in v1 JSON; it must not be reinterpreted as protocol-v2 binary framing.
