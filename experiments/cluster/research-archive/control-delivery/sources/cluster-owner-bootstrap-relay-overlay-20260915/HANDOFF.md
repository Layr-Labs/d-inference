# Authenticated owner bootstrap relay

This private overlay extends the frozen SSH owner (d78ead9e…) and local channel (52952c67…). It does not edit main, run SSH, load a model, or execute RDMA. The previous SSH service/endpoint behavior remains covered by its nine actual-child CPU groups.

The current facade admits only mesh with two peers. The relay enforces exactly four contribution rounds: int32 little-endian two (4 bytes), opaque Destination[2] (64 bytes), int32 zero (4 bytes), int32 zero (4 bytes). Gathered replies are 8/128/8/8 bytes. No Swift RDMA structure is recreated and self-slot/padding bytes remain opaque. Transport's source note is `jaccl-bootstrap-source-note/NOTE.md`; root independently compiled and executed the exact C header ABI assertion in `jaccl-mesh2-abi-check-20260915/execution.json` (SDK26.5, arm64 macOS26.2, int4/Destination32/little endian). Ring and extra rounds refuse.

`ClusterOwnerBootstrapRelay` is shared by the root controller's two endpoints. Each contribution is bound to expected worker identity, source/build/configuration fields, Plan, rank, epoch, fresh owner incarnation and lease. The relay retains at most one contribution per rank and returns rank-ordered bytes only after both validate at the same round. A changed route, skipped/repeated round, invalid scalar/length, timeout or cancellation poisons the relay. It performs no IO and waits only on a dedicated bootstrap task.

`ClusterRemoteWorkerEndpoint` accepts an optional configured relay. Its ordinary reader remains free to process native terminal/failure events while a bootstrap task waits. The writer's existing bounded queue carries bootstrap replies. The outer owner line cap is512KiB in each direction; embedded WorkerCodec events still retain their16KiB cap. Base64 contribution/reply caps are64/128KiB, with the much smaller closed mesh sizes checked before forwarding. Outer open/hello bind the same closed bootstrap profile. No host uptime crosses the authenticated connection.

The remote entry calls `serveConfigured(...bootstrapProfile:.mesh2, native:)`. It creates `ClusterOwnerBootstrapAttachment` before native construction. The required factory appends `attachment.workerArguments` (the closed socket-path/actual-owner-PID/local-deadline triple) to the unchanged native12pairs. After launch, the attachment admits the exact `launchedProcessIdentifier` through the local kernel-checked Unix channel. Its task publishes a round and waits on a bounded reply mailbox; the service control loop remains responsive to EOF, reserve/admission/request/lifetime deadlines and fencing. Native readiness waits for all four successful local replies. Each actual native terminal cancels and joins the attachment before publication, so no late bootstrap round can follow terminal/released. Accepted connection installation also checks cancellation under its condition lock. An already-invalid endpoint validates and drains a valid in-flight round while continuing to receive terminal/released; a canceled socket is never used as native-cleanup evidence.

The fixed native hard alarm and configured resource gates remain authoritative. Owner death leaves the prior sticky unresolved device journal. Native bootstrap authentication does not encrypt TB/RDMA payloads or independently attest the physical device/group. The existing GID requirement remains; callback bootstrap does not by itself remove a source-required IPv4-mapped GID or authorize a temporary address.

## Private configured owner executable

`Tools/ConfiguredOwner/build.sh NEW_DIRECTORY` produces a portable Foundation-only `darkbloom-owner-qualification` plus four dylibs, all using `@rpath`/`@executable_path`. The SSH configuration's installedDarkbloom can point at this binary; its sole command is exactly `cluster worker-owner --stdio`. It reads the owned, bounded, regular no-follow file `owner.json` adjacent to itself, with descriptor stability checks. No config path, executable, model path or environment comes from the owner wire.

The exact local JSON keys are `schema` (`darkbloom_configured_worker_owner_v1`), `clusterID`, `workerExecutable`, `modelDirectory`, `leaseDirectory`, `stageCut`, `maximumLifetimeSeconds` (1…300), `workerEnvironment`, and `readyTemplateBase64`. The last field is an existing WorkerCodec ready event with a zero placeholder membership epoch; its identity/profile/rank/Plan define configured expectations, while the actual fresh epoch arrives in the authenticated open. Its capacity is a validation placeholder, not a resource grant. The local binding replaces the epoch and the actual child must produce matching readiness. The executable requires mesh2 attachment and always supplies all three native bootstrap flags. Root's configured native bundle/source pins, per-node model setup and matrix environment remain explicit deployment inputs.

The qualification executable has been compiled, but it has not launched a real native worker or run over SSH. Public `darkbloom cluster configure/start/status/doctor` wiring remains later. The root controller can construct two configured SSH endpoints sharing one relay, then reuse the existing `ClusterWorkerPair`/request lifecycle. The installed native bundle must contain the previously reviewed callback shim and local-channel worker triple before this can run physically.

The initial twelve groups are preserved as pre-correction evidence. The corrected thirteen-group suite also delivers a valid round only after cancellation, then verifies actual native SIGKILL terminal and the released journal. It passed without changing native/model code. These are local model-free Process children, not SSH authentication, MLX, RDMA, numerical parity or performance evidence.
