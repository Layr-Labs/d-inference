### GLM-5.3-Flash calls that break only their schema are calls again

- A GLM-5.3-Flash call that left out a `required` argument, carried an argument the schema does not declare (`additionalProperties` absent or `false`), or filled a parameter without a type was returned as its raw `<tool_call>` markup in `content` with `finish_reason: "stop"`, so agent loops stopped (#2156). One such call turned every parallel call beside it into text too. Agents that add a required parameter to every tool (oh-my-pi's `i`) hit it on most turns.
- The SDK's GLM parser (`mlx-swift-lm` #TBD) now checks the frame grammar and the declared function name only, as vLLM's and SGLang's do. Such a call is a call (`finish_reason: "tool_calls"`) with the arguments the model wrote; an `auto` request without `strict` returns it as generated, for the client to check, like every other model here. A value declared only as `string` stays raw text; any other value is JSON when it parses as one, else its raw text.
- When the calls that end a response do not all parse, each is decided on its own: a call is a call, and only a frame the parser still refuses (an undeclared function name, a repeated argument) is text. A frame that breaks the grammar (open at the end, misplaced or nested tags) still keeps every frame after it from being a call.
- Schema guarantees are unchanged and now reached: a call to a `strict` function that breaks its schema is refused (422), or leaves as generated once a streamed response has started (`DARKBLOOM_STRICT_CALLS_AS_GENERATED`), and a required or named `tool_choice` refuses such a call (422); before, the parser turned the first into text. `DARKBLOOM_GLM_TOOL_TEXT_FALLBACK=0` still restores the 500 for a suffix that does not parse.
