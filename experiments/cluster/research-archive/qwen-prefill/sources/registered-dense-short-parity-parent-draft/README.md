# Private guarded short parity parent

This additive private launcher runs one closed registered short parity request. It retains the reviewed selected-stage V2 process ownership, natural-exit race handling, source archive, immutable bundle acquisition/reference, power observations, deadline, cleanup and independent postflight checks. The original parent and receipts remain unchanged.

The exact native command has eight pairs: `--mode qwen-dense-short-parity-check`, `--model-dir`, `--registered-dense-profile`, `--tokens-file`, `--tokens-sha256`, `--teacher-tokens-file`, `--teacher-tokens-sha256`, and `--timeout-seconds 120`. Profiles are `registered_qwen35_9b` and `registered_qwen38_27b`. There is no cut, repeat, throughput, trace, reserve or allocator override.

Caller-provided prompt and teacher files must be distinct absolute regular files, each nonempty and at most 4096 bytes, with explicit lowercase raw SHA-256 pins. They contain exactly three and one integer token IDs in `0..<248320`. Booleans, fractional IDs and nonfinite JSON are refused. A nonblocking descriptor rejects FIFO input. The parent saves identical bytes as mode0400 `prompt.json` and `teacher.json`, passes those archived paths to native, and rechecks original and archived pins independently during postflight. No actual input paths or token provenance have been selected by this package.

The parent starts a fresh owned process group, supplies the established arithmetic environment, and retains every native byte. Native timeout is 120 seconds; the parent deadline is 135 seconds, anchored immediately before `Popen`. Stdout is bounded to 64 MiB total and 32 MiB per record including LF, both while running and after reaping. Exactly two complete records must appear in order: `qwen_dense_short_baseline_checkpoint`, then `qwen_dense_short_parity_report`. A baseline alone is a failed run. Stderr is bounded to 64 KiB and must be empty; no diagnostic allowance is added.

Every saved resource sample still requires actual free memory of at least 6 GiB, pressure 0...2 and absolute reported swap zero. Reclaimable memory is not an admission input. Power must report AC or an internal battery of at least 15%. The requested sampled RSS screens are 8 GiB for 9B and 20 GiB for 27B: these runs load a full reference, retire it, then hold both stages together, whereas the predecessor loaded only one half. These screens do not widen any native admission, establish a whole-process peak bound, or authorize sustained benchmarking. Actual native dynamic resource gates may still refuse before or during either owner.

The exact V2 exception for an observed `'<defunct>'` command remains: owned integer PID/PGID, integer zero RSS and the same `Popen.poll()` object's terminal integer result. Other command mismatches are refused. A nonzero native exit, cleanup error, source/input/bundle drift, deadline overrun or any postflight failure keeps the final receipt failed. Archive failure does not suppress the separate reused-reference recheck.

Outer validation checks the full closed top-level DTOs, source/configuration/artifact identity, released baseline and two-stage count assertions, raw input pins, three-step geometry and the exact native-recorded token history. It reconstructs the request fingerprint from the emitted UUID and pinned IDs, and the admission fingerprint from the recorded Plan hash plus registered/raw identities. It joins baseline evidence, source, Plan, layouts and request identities across the final comparison. The native UUID is generated by the native entry; no pre-run caller UUID is claimed.

State bytes, row arithmetic and baseline evidence digests are not independently replayed here. The deliberately nonmatching tiny fake row bodies are accepted only by the outer checks, with `independentNumericalAuditPerformed=false` and `independentTensorAuditPerformed=false`. The final native `numericalParityEstablished=true` is retained as a native assertion, not promoted into an independent claim. Plan serialization, metadata inventory, resource DTOs and native lifetimes also need their separate audits and source/provenance joins.

The three exact shared helpers are `tiny_support.py` (5af27994…), `prefill_compute_archive.py` (dde03189…) and `owned_bundle_reference.py` (c4832e45…). The original selected-stage contract is copied unchanged and pinned (8102af85…). Its resource predicate is copied with only the expected native mode changed; fixed registered input pins and the power/regular-file helpers are reused. New source files are archived and checked before final success just like the inherited files.

Root can run, with concrete absolute paths and pins substituted:

```sh
python3 -B run_short_parity.py \
  --runtime /ABS/REPO/experiments/cluster/runtime \
  --release /ABS/VERIFIED/RELEASE \
  --model-dir /ABS/REGISTERED/MODEL \
  --profile registered_qwen35_9b \
  --tokens-file /ABS/PROMPT.json --tokens-sha256 LOWERCASE_SHA256 \
  --teacher-tokens-file /ABS/TEACHER.json --teacher-tokens-sha256 LOWERCASE_SHA256 \
  --expected-native-sha256 LOWERCASE_SHA256 \
  --output /ABS/NEW/RUN \
  --reuse-bundle /ABS/OWNED/READONLY/BUNDLE \
  --expected-bundle-manifest-sha256 LOWERCASE_SHA256
```

The two reuse options are paired. Omitting both uses the original fresh snapshot path. Reuse does not claim a fresh copy: the exact owned tree, manifest, native bytes and archived runtime files are validated before launch and after execution by the unchanged helper. The release path must also match the supplied native pin. Output must be new and outside repository, model and release directories.

Author verification: 19 invented CPU tests passed. They use synthetic files and fake process objects, with real subprocess/network launches blocked. They do not invoke the native binary, read model payloads, use a real bundle, or inspect candidate outputs. `check_source.py` checks frozen lineage, exact native DTO keys/CLI, helper hashes and the narrow resource delta. Root owns all actual execution and independent numerical replay.
