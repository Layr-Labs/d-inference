### One local API port per Mac, and a local API that can't listen says why

- Every local API this Mac serves takes the same port: Only me and Both, me first from the start question, a saved choice, `--me-first`, `--local`, `--local-endpoint` and the Darkbloom app's starts, its local mode included. The first one chooses it (the first free port from 8001, never 8000 or 47420–47423) and saves it as `[local] port`; every later start uses it, so the address your tools were given (`http://127.0.0.1:<port>/v1`, with the key in `~/.darkbloom/local_token`) never moves. Before, `--local`, `--local-endpoint` and the app took 8000 while the start question took 8001.
- A saved port always wins, and is never moved. `--port <n>` replaces it and is saved too: ``Local API port: 8007 (saved, instead of 8005: tools set up for 8005 need `darkbloom start --opencode` or `--hermes` again).``
- A Mac without `[local]` started without a terminal still serves exactly as before: the Darkbloom network, with no local API and no port.
- When the local API of Both, me first can't listen, `darkbloom status` no longer reads "Darkbloom network only": it says ``Serving: Darkbloom and you, me first — the local API isn't up: port 8001 is in use (`darkbloom start --port 8002`)``, and `darkbloom local` says the same. Only me names the next free port the same way.
- The app's local mode runs as launchd's `--foreground` service on that port, and its log no longer shows the local key.
