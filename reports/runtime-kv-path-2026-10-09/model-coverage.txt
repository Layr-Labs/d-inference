## Choice

Choose a **model-independent, geometry-derived rotated nonuniform scalar encoding of owning attention K/V**, with packed 4-bit codes for old committed rows, 8-bit encoding as a configuration-time fallback, and the newest 128 committed tokens plus all pending/speculative tokens in original native precision. Keep Qwen/Bonsai/Nemotron recurrent state and persistent MTP state native initially. One codec/precision policy can cover all these attention geometries; it needs both paged and contiguous readers and an explicit extension of MiMo's owned native resources to cover all dispatched requests.

Use independent orthogonal block rotations for K and V, **after model projection/RoPE**, resolving block width separately as `R(D)=min(128,D & -D)` for positive widths. Split a head into D/R independent blocks. K192 therefore uses three R64 blocks without padding; V128 uses R128. Rotate original Q by the corresponding K rotation before compressed dot products; inverse-rotate the accumulated V-space output before model output projection. Nonuniform codebook, seed/sign pattern, norm dtype, precision and block width belong in stable runtime/checkpoint identity. Keep codebooks fixed/versioned rather than train them from private requests.

This is a concrete TurboQuant-MSE-style engineering direction, not a claim to implement every algorithm in the paper (no QJL inner-product correction). It still needs end-to-end numerical measurements on each artifact.

|---:|---:|---:|---:|---:|---:|

|256|128|2|136|264|512|

No active catalog text-attention K/V width80 or160 was found. The codec still supports those widths mathematically without padding; smaller rotation blocks increase norm overhead and change distortion, so test them independently. Positive odd dimensions yield R1, which is a degenerate rotation with excessive metadata cost; fail over to a native/other efficient representation rather than claim universal savings.

For one owner with H KV heads, K/V widths Dk/Dv, native bytes s, old count C=max(T−128,0), retained native count N=min(T,128):

`encoded = H * [ C * ((Dk+Dv)*bits/8 + 4*(Dk/Rk + Dv/Rv)) + N*(Dk+Dv)*s ]`

Add actual alignment, codebook/metadata, native pending/speculative rows, poison pages, transient compression/read scratch, and recurrent/MTP owners. This formula assumes FP32 per-block norm; any extra scale/bias needs its own charged bytes. Current native slot grants/reserve floors must not be reduced speculatively.

## Precise integration seams

1. **Model contract remains `CBv2AttendingLayerCache.updateAndAttend` / `attendBorrowing`.** `CBv2Contracts.swift:349` carries full/window, shared owner, sinks, distinct K/V width and original layer mapping. `:670` owns both storage append and attention. Inputs arrive after projection and positional transforms. This is the common boundary across Gemma/GPT/Qwen/Bonsai/Nemotron and MiMo's owned wrappers.
2. **Generic production construction is `EngineV2Factory+BackendPreparation.swift:104–309`.** `ProductionModelAdapter` collects model kinds and lazily builds caches. Contiguous builds `CBv2ContiguousKVBackend` + `CBv2LayerCache`; paged builds `PagedKVBackend` + `PagedLayerCache` after kernel preflight and actual native-KV probe. Shape policy must resolve from the loaded `layerKinds` and observed dtypes. Weight-quantization labels and catalog display family must not determine encoding.
3. **Paged physical format change belongs inside existing native page owners.** `PagedKVGroup.swift` and `PagedKVSegment` currently hold native float arrays and charge geometry×dtype; `PagedSequenceKV` owns table/ring/absolute position. The new encoded old-page representation and native tail must change real storage/physical receipts, writer/gather/decode bindings, segment metadata, `PagedKVResidency`/admission and poison-page handling together. `PagedLayerCache` already has separate fused decode, gathered/blocked prefill, packed prefill, vision-span, borrowing and MTP serialization paths; all must read the chosen representation.
4. **Contiguous is part of the current product, not optional coverage.** Both8bit Gemma IDs resolve auto-contiguous today, all generic models have operator/failure routes to contiguous, and MiMo media uses its native contiguous path. Encode old committed rows in its sequence owners and use the same common codec/attention semantics with bounded block reads; preserve window rings, source borrowing and rollback. A paged-only implementation cannot be described as all11model serving coverage.
5. **MiMo must extend its SDK-issued loaded tuple.** `MiMoV26CBv2.swift:725–784` requires the exact immutable loaded owner, per-layer probe, process owner, row ledger and concrete `PagedKVBackend/PagedLayerCache` tuple, and seals it in `CBv2NativeExecutionContract`. The provider's `EngineV2SlotFactory+Native.swift:512–650` assembles target-only, serialMTP and prefix tuples in protected construction scopes. Its contiguous wrapper similarly wraps owned `CBv2LayerCache`, verifies exact rows and keeps failure/quarantine resources. Introduce encoding through these native constructors; do not substitute a foreign cache or fake `.pagedFP16` identity to evade validation.
6. **Live quantization cannot materialize full native history on each read.** Packing old buffers and then dequantizing an entire long prefix every attention call recreates the peak-memory problem and cannot establish faster decoding. Use fused compressed decode or bounded streaming K/V blocks with an online softmax merge and a native-tail arm. Preserve sink denominator exactly once, causal/window absolute masks and vision span visibility. Prefill remains query-blocked with bounded scratch, not O(Q×T) unbounded score allocation.
7. **Compress only confirmed rows after actual GPU completion.** `CBv2SequenceKV` explicitly promises value-exact speculative rollback. Keep pending columns and any old native rows a transaction could need untouched until commit. The 128-token horizon must be based on the confirmed frontier, not speculative append length. Otherwise an MTP rejection may restore the cursor but leave formerly native accepted history compressed or overwritten. Encoded historical blocks should be immutable and encoded once; no accumulating re-quantization drift.
8. **Prefix-cache serialization/identity must understand the representation.** Current complete export expects native typed K/V (`PagedCompleteCheckpointCodec`, historical owner map, MiMo native DTOs). Choose an explicit compressed format or an explicit one-time native reconstruction path with accounted scratch; runtime numerics identity must include bits/rotation/codebook/horizon so old native and new lossy snapshots cannot be reused under an identical contract. Resident page reuse must bind precision too. Recurrent/assistant state remains exact/native.

## Concrete blockers to an all-model claim

- Current code has **no quantized CBv2 runtime backend**. Legacy `QuantizedKVCache` belongs to the older single-generation API; `maybeQuantizeKVCache` only scans `KVCacheSimple`, and rotating/window quantization is explicitly unimplemented (`KVCache.swift:744–750`, `:2150–2192`). Dropping that object into CBv2 does not wire continuous batching, paging, MTP or MiMo.
- Codec width coverage is not backend coverage. MiMo asymmetric K192/V128 and native-owned construction, GPT sinks and mixed FP32/BF16, Gemma window/borrowed assistant rows, and recurrent state accounting each need explicit integration tests.
- The current 11 active IDs include different actual serving routes. Default8bit Gemma and defaultMiMo contiguous/media requests remain outside a paged-only pilot. NativeMiMo paging currently refuses media and is opt-in text-only.
- Native paging has geometry/dtype/concrete-owner receipts that a different physical layout invalidates unless those contracts are explicitly extended. Current Nemotron requires observed segmented native paging; do not bypass that by reporting a new backend as `unknown`.
- Existing strict cache/native equality tests prove native contracts; accepted lossy inference needs new calibrated numerical/task gates while retaining exact isolation, mask, rollback, cancellation and accounting assertions. A single Qwen owner packet is not all-layer or all-model quality proof.
- The advertised source set is wider than the active catalog: it also accepts Qwen4 QSA and DiffusionGemma. Qwen4 owns extra indexer side state and asymmetric native paths; DiffusionGemma uses bidirectional/block checkpoints. If “every supported model” includes these architectures or arbitrary future configs, expand the inventory and tests rather than equate11activeIDs with the entire source capability set.

## Required qualification matrix

For each of10unique active artifacts: load/probe exact immutable identity; test owning K/V geometry, native recent tail and mixed dtypes; run actual B1/B2/B4 prefill/decode with whole-model quality tasks/logit drift and long-context retrieval; test MTP accepted/rejected/rollback paths where configured, windows acrosswrap, cancellation and post-cancel reuse, co-resident physical bytes and shrinking grants, authenticated prefix hit/miss/import/export, and supported media/tools. Confirm actual compressed live buffers/peak bytes, sustained decode speed and TTFT. Test alias/backend routes separately for the duplicate Gemma hash. Test4bit first; choose8bit at load for an artifact/profile that fails4bit task gates, with native mode still available as the safe capability fallback. Do not dynamically change precision midrequest after an observed bad answer.

No claims of implemented runtime compression, native GPU equivalence, full-model accuracy, all-model promotion, release or deployment follow from this investigation.
