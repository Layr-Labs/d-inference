# Inkling 2 Mini provider contract reference

> Last updated: 2026-11-25

Reference for the provider's side of Thinking Machines' Inkling 2 Mini (`inkling2_loop`): identity, prompt, output, cache and drafter contracts read from the pinned checkpoint `thinkingmachines/Inkling-2-Mini` at `6e7c8248f75265bdd4fbab5273304243b5d8c2cb`. The native model lives in the SDK (`Inkling2Model`, and the `Inkling2VLM` wrapper with its vision tower); nothing here publishes a model, approves a catalog entry or qualifies hardware.

## Cache layout

The looped tower runs its core layers once per pass, each pass with caches of its own, so a sequence holds one cache slot per layer application.

| Quantity | Value at the pinned config | Source |
|---|---|---|
| Slots | 48: stored layers 0–23, then layers 6–17 for passes 2 and 3 | `Inkling2ModelIdentity.CacheLayout` (`slotLayers`) |
| Full-attention slots | 8 (layers 5 and 23, and 11 and 17 in each pass) | `CacheLayout.fullSlotCount` |
| Sliding slots | 40, window 1024 | `CacheLayout.slidingSlotCount` |
| Marginal K/V per token | 32,768 bytes at FP16 (8 slots × 8 heads × 128 × K and V) | `CacheLayout.kvBytesPerToken`; `provider-swift/Sources/ProviderCore/Inference/Memory/KVEstimation.swift` (`parseModelArchitecture`) |
| Sliding plateau per sequence | 167,772,160 bytes at FP16 | `CacheLayout.slidingWindowBytes` |
| Convolution state per sequence | 3,833,856 bytes in the reference's FP32, 1,916,928 in BF16 (K, V, after attention, after the MLP; 3 rows each, every slot); the loaded model's state decides | `CacheLayout.convolutionStateBytes` |
| Context | `text_config.model_max_length` 1,048,576 | `KVEstimation.parseModelArchitecture` |

## Output contract

Output after the prompt is a run of `[<|message_model|>NAME]<|content_KIND|>BODY<|end_message|>` messages, as the checkpoint's `response_template` reads it.

| KIND | Channel | Rule | Source |
|---|---|---|---|
| `thinking` | reasoning | Ends only at `<|end_message|>`: a call drafted inside stays reasoning | `provider-swift/Sources/ProviderCore/Inference/Streaming/Inkling2OutputChannels.swift` |
| `text`, `tool_error`, `invoke_tool_text` | content | Refused for a forced choice | `provider-swift/Sources/ProviderCore/Inference/Streaming/NativeToolStreamRouter.swift` (`routeInkling`) |
| `invoke_tool_json` | one call | Exactly `{"name": NAME, "args": {...}}`; a header name must match; `<|end_message|>` inside a JSON string is data; body, header and nesting are bounded; a malformed frame is refused as native tool output | `Inkling2OutputChannels.parseCall`; `NativeToolStreamRouter.checkNativeToolFailure` |
| `image`, `xml`, text outside messages | none | Dropped and counted, as the response template ignores them | `Inkling2OutputChannels` (`droppedBytes`) |

Calls leave complete when their message closes to a client that streams, else at the end of generation (`provider-swift/Sources/ProviderCore/Inference/ToolStreamPreparation.swift`, `streamsInklingCalls`). No text tool parser reads the output (`makeHandler`).

The drafter's declaration and automatic intent (`ProviderConfig` `automaticEmbeddedModelTypes`, `SpecDecArtifactFunnel.isInlineTarget`) and its load into the serving engine (`EngineV2MTPAssistant`, bound to the text model) are wired; see the Drafter row above.
