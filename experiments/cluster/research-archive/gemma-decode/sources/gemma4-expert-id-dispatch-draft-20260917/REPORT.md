# Gemma expert-axis implementation decision

The existing `ExpertPartitionPlan`/`QuantizedExpertPartial` is tensor parallelism within every expert: all ranks retain every expert ID and split the intermediate width. `GemmaPartitionPlan` splits dense 2112 into 1024/1088 and sparse 704 into 320/384. It replicates attention/router/norms, and `GemmaReductions` orders dense then sparse collectives before their separate branch norms. This is implemented experimental code, not a true expert-ID dispatch path. The retained `GEMMA_RUNTIME_VALIDATION.md` explicitly leaves BF16 whole-model FFN TP unqualified; a changed argmax and large row errors prevent treating that path as a quality baseline.

The new pure helper implements the missing ownership/mapping contract, not native EP. A bounded targeted search of the existing inference experiment and cluster runtime found no expert-axis rank dispatch/unroute implementation. Native loading, device packing, return transport and actual decoder integration remain necessary. `source-inputs.json` pins the inspected files, and `metadata-summary.json` is derived from retained header/config metadata without reading model payloads. The artifact metadata is retained qualification input, not a claim that the local filesystem has an installed model or that the live production catalog was queried.

## Actual artifact and arithmetic

The retained `gemma-4-26b-qat-4bit` artifact has 30 layers, hidden width 2816, 128 experts and top-8 routing. Every sparse expert has intermediate width 704; the parallel dense branch has width 2112. Sparse weights are affine W4/G64; dense and router projections have W8/G64 overrides. Sparse scales/offsets are already BF16 and packed weights are U32. Each layer has nine expert tensors:

| Projection | Packed weight | BF16 scale and offset, each |
|---|---|---|
| gate and up, each | `[128,704,352]` | `[128,704,44]` |
| down | `[128,2816,88]` | `[128,2816,11]` |

Selecting axis zero copies complete expert planes and never splits a 64-wide quantization group or a packed U32 word. Noncontiguous increasing expert IDs can be expressed as ordered axis-zero ranges and packed by the existing selected reader. Do not use a view that retains the full bank or treat `MLXArray.copy` as independent storage. The actual converted artifact is split gate/up; accepting raw fused layouts is a separate adapter obligation.

The router computes RMSNorm of the post-attention residual with learned `scale / sqrt(2816)`, projects to all 128 scores, takes the final eight entries of `argPartition`, applies precise softmax to those selected logits, then multiplies by the corresponding learned per-expert scales. The selected order is the actual argPartition order, not sorted global IDs or descending scores. The final weights need not sum to one. Replicate the full router/scales or transmit the actual selected IDs/weights; never choose top-8 independently within each rank or renormalize local weights. Tie behavior must follow the original device operation.

The dense branch is an always-active separate GeGLU MLP, not a ninth routed expert. It has its own input norm and post-branch norm. Sparse routing uses the residual before the sparse input norm. After separate dense/sparse post-branch norms, the two branches are added, passed through the common post-FFN norm and added to the residual; layer scaling then remains in its original location. Replicating dense computation must not cause it to be summed twice. No PLE or shared-KV tail is active in this artifact. Sliding/global attention and ordinary request state remain unchanged by expert-axis ownership.

## Placement and measurement obligations

Exact stored payload is 3,345,408 bytes per expert per layer; 428,212,224 per full layer; 12,846,366,720 over 30 layers. Nonexpert text tensors total 1,621,321,788 bytes. Hypothetical full-model EP with all nonexpert text replicated would therefore hold 8,044,505,148 stored bytes per rank at 64/64, or 6,438,709,308 / 9,650,300,988 at 48/80. These are source-byte sums, not allocator peaks or an admission proof. They omit casts/caches, attention/KV, dispatch/return tensors, collective/key/codec buffers and retained workspaces. At the reported roughly 13.5 GB quiescent free on the 24 GB host, 64/64 does not even leave the unchanged 6 GiB floor after these source bytes alone. Unequal ownership is required for exploration, but 48/80 is not yet shown to fit either.

For sparse work, three full projections cost 5,947,392 multiply-accumulates per selected expert/token before activation; top-8 selects 47,579,136. All experts have equal geometry here, but actual routing counts and per-rank kernel efficiency determine work. Fit expert placements to per-layer measured assignment histograms, observed batch/kernel times and admitted resident memory; constrain each expert to exactly one owner and retain both source-layout commitments. Do not infer equal work from equal expert counts or extrapolate a short prompt to all workloads. Keep hot expert replication/migration out of the first contract because they change ownership and memory authority.

Preserving slot-order combination has a communication cost: all eight BF16 outputs occupy `8 * tokens * 2816 * 2 = 45,056 * tokens` bytes (23,068,672 at C512). A gather owner receives only remote assignments, but their count must be measured. Dispatch may deduplicate input rows per destination; otherwise one BF16 row per assignment costs 5,632 bytes, plus bounded IDs/slots/weights. The combined BF16 hidden output is 5,632 bytes/token if it must be replicated onward. These are payload formulas, excluding framing/codec/staging and topology-specific sends. They are not measured Thunderbolt cost. An all-reduce of two partial hidden rows is cheaper but changes the reduction tree and requires separate qualification.

First record per-layer/rank assignment counts, distinct input rows, exact payload bytes, same-process packing/projection/receive/reassembly durations, actual selected kernels, MLX active/cache/peak and raw OS resource samples. Never subtract clocks across hosts or label waiting time as network cost. Compare this true-EP candidate with separately qualified attention/dense TP and hybrid placement only after the one-layer/full-model gates. Kernel micro-TPS, source-byte savings and full-model quality/performance are separate results.
