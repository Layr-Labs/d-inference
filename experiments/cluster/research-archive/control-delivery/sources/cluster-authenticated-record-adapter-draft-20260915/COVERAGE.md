# Required-encryption call-site coverage

The independent source-only map is `resident-rdma-encryption-callsite-map-20260915`, manifest `59097d25d439c0c31b50e5ea2fecc97c572dcae2e242d8c769adb76bff22308d`; `MAP.md` and its 29 exact source pins remain unchanged. This adapter package adds no automatic product selection and does not yet replace the following calls. A required-encryption product may not advertise ready until every applicable route below is protected and the native padding/key/admission prerequisites hold.

The 24-byte codec prefix contains only closed type/direction/sequence/length/version/suite metadata. Its variable-mode length is an unauthenticated bounded allocation hint. Local expectation data is never copied from this prefix or a received model packet. The model-specific context builders are a required later integration seam: use local frame/shape/phase counters and exclude inference content, token-chain hashes and content-derived packet fingerprints from AAD. Type/request/epoch/Plan/length/direction and sequence are independently bound by the codec and adapter.

Other paths must be covered or refused:

- `Collective.sum`, `barrier`, `requireAgreement` and `selectToken` retain raw reduction APIs for other experimental paths. Ordinary shared resident generation currently has no callers of `sum`, but required-encryption admission must exclude raw TP/reduction routes. Ciphertext must never be fed to numerical all-reduce. Protecting these requires a separate exchange algorithm, not an encryption wrapper around arithmetic.
- Existing owner SSH control is encrypted separately, and cancellation remains out-of-band. Control encryption does not authorize a raw RDMA fallback. A record failure uses the existing independent native/process cancellation and retained lease cleanup.
- The fixed PID/UID-bound four-round bootstrap does not establish traffic keys. Required-encryption construction must refuse missing security context and legacy nil-bootstrap/keyless paths. Coordinator verification/routability and native per-epoch freshness are separate prerequisites, not properties inferred from these fixture constructors.
- One-chunk lookahead may prepare the next chunk only after the current send's real native completion. It still waits for the encrypted consumed ACK before advancing the receive/consume frontier. Adapter staging must be charged in addition to that already-admitted lookahead allowance.
- Native JACCL full-buffer tail bytes need the separate source/test correction documented in HANDOFF before all emitted bytes can be declared safe. Payload ciphertext tests alone cannot establish that guarantee.

No key establishment, call-site wiring, native padding correction, coordinator change, plaintext downgrade, deadline extension or owner-state change is part of this source candidate.
