# Provider integration audit — explicit distributed execution

Offline source review, 2026-09-13. Governing requirement: [`docs/design/distributed-inference-goal.md`](/Users/developer/DarkbloomDev/d-inference/docs/design/distributed-inference-goal.md), especially opt-in mode, committed-state ownership, bounded cancellation and exact numerical qualification. No provider code was changed; no build, network or GPU work was run.

The smallest useful integration seam is the existing **`CBv2Engine` protocol behind `EngineV2Bridge`**, with an explicit slot-construction branch before model allocation. Keep the current local construction path as the default. A first distributed engine can be serialized, text-only and cache-cold while reusing prompt preparation, streamed events, usage accounting and cancellation correlation. This is a proposed implementation boundary, not an existing distributed capability. It does not imply that the experimental ordinary Qwen forwards already implement production CBv2 state semantics.

## Five next implementation steps

1. **Make the slot decision explicit and test default preservation.** Resolve configured members, supported artifact/phase and an immutable qualified plan at slot creation. Keep the current shared local slot factory unchanged when distributed mode is absent. Initially switching a resident model's execution mode should drain and reload; silently replacing a live model-ID entry can overwrite its cancellation owner. Add factory tests for default-local, explicit refusal, and opt-in construction without launching workers.

2. **Add one serialized cluster `CBv2Engine` adapter and owned worker lifetime.** Reuse the experiment's verified bundle/shard-loading and process-lifecycle concepts behind this adapter, with one request owner, rank-agreed token history and deterministic collective sequence. Rank zero alone emits committed user-visible tokens/usage. Initially refuse multimodal, MTP, packed batching and state handoff; their presence in the source model is not qualification. Implement real request/capacity accounting; the protocol's default deadline result is `deadlineUnreachable(.unbounded)`, so no fabricated prefill prediction can pass remote atomic admission.

3. **Extend existing cancellation and retirement tests across the adapter.** Script pre-admission cancellation, disconnect during prefill, cancellation during a collective, peer exit, deadline expiry and slot unload. Verify one terminal event, exactly-once `OneShotRelease`, no duplicate tokens/usage, no worker/descendant left running, and no reservation release before retirement. Invalidate the epoch after rank failure; future admission may refuse or use an explicitly allowed local plan. Do not restart an already-emitting request without a separately validated committed-state mechanism.

4. **Bind qualification and state identity before enabling reuse.** Use artifact/config/tokenizer/build hashes plus the chosen partition, effective quantization, activation/state/reduction precision, kernel policy, transport and supported workload bounds as the plan qualification key. Extend the existing numerical/storage fingerprint composition rather than treating equal model names as compatible. Its current environment-prefix allowlist would not capture a new `DARKBLOOM_CLUSTER_` setting; bind explicit resolved plan/numerical fields instead of relying on that incidental scan. Track live membership/epoch separately for request ownership. Start with fresh state; later build complete-state import/export tests using existing checkpoint roles and recurrence generation rules. A route-replay diagnostic must never be eligible as an ordinary plan.

5. **Qualify the provider path, then expose readiness.** Drive prepared real-text tokens through the engine's actual submission/continuation path, using its existing teacher-forced/logit diagnostic contracts where supported, and compare local controls before advertising a capability. Establish authenticated peer trust, link/collective health and identity agreement before marking the slot ready. Capacity and status must show actual execution mode and transport with content-free failure reasons. Retain the canonical two-M3-Ultra 27B 8K uncached-prefill benchmark and paired local/replica baselines; synthetic integration tests cannot close that performance milestone.

A CBv2-native model/step adapter may eventually reuse more of the production scheduler than a serialized cluster engine. That is a later decision after request-owned KV/recurrent generations, collective membership changes and cancellation are qualified. The current `CBv2Engine` boundary gives the provider an opt-in path without first rewriting HTTP routing or pretending that replacing model linears is sufficient product integration.
