# Local stage check launcher draft

This is a proposed public replacement for the duplicated launch plumbing in the
frozen P2P and real-artifact stage experiments. It runs one fresh two-process
cohort on one Mac through the explicit MLX ring `loopback-test` backend. It is a
correctness tool, with no throughput, scheduler, RDMA, or two-machine claim.

The draft has not launched a native worker. Its CPU tests use fake processes and
block subprocess and socket creation. A separate saved-record compatibility
check exercises the validators against existing native reports; it does not
rerun those experiments or replace their independent audits.

## Proposed public placement

Move `stage_checks/` to `experiments/cluster/runtime/stage_checks/`, the thin
`run_stage_checks.py` to `experiments/cluster/`, and the tests to the runtime test
directory. Change the entry import to `from runtime.stage_checks.cli import
main` and test imports to `runtime.stage_checks`. No Swift changes are needed.
The existing `runtime.bundle`, `rank_worker`, `processes`, and `artifacts` remain
the bundle, process-group cleanup, and registered-artifact authorities. They are
copied into each run before use.

`cli.py` orchestrates; `archive.py` snapshots provenance; `inputs.py` retains
bounded metadata; `configuration.py` builds exact native arguments;
`resources.py` observes OS memory; `stream.py` and `supervision.py` own bounded
records and cohort lifetime. `p2p.py` and `ranks.py` keep their versioned evidence
namespaces separate. `request.py`, `storage.py`, and `evidence.py` check the
request, tensor accounting, and captured native values. `baseline.py` performs
the optional reference comparison.

## Commands

Both commands require a built release directory, the repository's runtime
directory, the expected executable SHA256, and a new output directory outside
the repository. Paths below are caller-supplied placeholders.

```sh
python3 run_stage_checks.py p2p \
  --release RELEASE --runtime RUNTIME --output NEW_OUTPUT \
  --expected-binary-sha256 BINARY_SHA256 --timeout-seconds 60

python3 run_stage_checks.py ranks \
  --release RELEASE --runtime RUNTIME --output NEW_OUTPUT \
  --expected-binary-sha256 BINARY_SHA256 \
  --model-dir LOCAL_MODEL --artifact-aggregate-sha256 ARTIFACT_SHA256 \
  --tokens-file PROMPT_IDS_JSON --teacher-tokens-file TEACHER_IDS_JSON \
  --chunk-size 32 --timeout-seconds 180
```

`p2p` runs the existing fixed no-model `stage-p2p-check` fixture: nine dtype/width
cases, six residual frames per case, and seven control cases per rank. It binds
the fixture fingerprint, native equality assertions, and peer records. It does
not independently reconstruct the fixture payload bytes; that remains a
separate CPU oracle in the historical experiment.

`ranks` runs `qwen-layer-stage-rank-check` with native precision and
`cbv2-contiguous`. It accepts locally registered dense Qwen artifacts admitted by
the native stage planner and verified loader, including their 8 GiB declared
payload, 6 GiB canonical tensor, and 512 MiB source-tensor caps. The actual
prompt has 1–128 IDs, chunk size 1–32, and output count 1–4. Supply 1–3 teacher
IDs to request 2–4 outputs; omit the teacher file for one output. IDs must be in
the admitted vocabulary. The layer split is an equal, phase-aligned split of
whole layers, with full projection widths and fresh request-owned state.
Native topology/quantization admission and the 512 MiB named state/boundary
estimate remain authoritative; the Python checks do not broaden them.

`--tokens-sha256` and `--teacher-tokens-sha256` optionally pin the input files.
Their exact bytes are always retained and hashed. Native rank input files are
generated from the retained parsed IDs, and their exact generated bytes are
checked after the run. No model weights are copied. The original artifact is
verified before and after execution, and each native loader independently
verifies the expected artifact through its pinned descriptors.

## Resource and lifetime contract

For real artifacts, the default screen requires at least 8 GiB of estimated
reclaimable memory, 4 GiB free output storage, and descriptor headroom.
`--minimum-reclaimable-gib` can raise the memory screen, never lower it. The
8 GiB screen is inherited from the tested bounded workload; it is **not** a
universal allocation bound for every admitted topology. Constructor caches,
kernel workspaces, and allocator residency may differ. Native tensor caps do
not prove that the whole process fits that screen.

Both commands sample macOS pressure and reported swap before execution, during
supervision, and afterward. Pressure must stay at level 0–2, and reported swap
must not increase. Reporting precision is preserved. Failure cancels the whole
cohort; it does not remove unrelated processes or retry a request.

The parent owns a monotonic active-cohort deadline of at most 60 seconds for
P2P or 180 seconds for real stages. Each unchanged rank supervisor and native
process also receives the bound. A failed spawn, peer exit, malformed or missing
record, memory gate, signal, or deadline retires all started supervisors through
the existing cancellation-file/process-group cleanup. Metadata verification,
artifact hashing, and bounded cleanup are outside the active-cohort deadline.
The receipt distinguishes reaped supervisors from an independently collected
native PID inventory; it does not invent the latter.

Each rank must emit one matching ready record followed by one matching terminal
record. P2P stdout is bounded to 4 MiB (2 MiB per line); stage stdout to 64 MiB
(60 MiB per line); stderr to 4 MiB while polled. The larger stage record retains
up to four full vocabulary rows plus bounded state inventories. Records are
read from private files, not unconsumed pipes. Invalid/truncated records fail;
they are not silently dropped.

## Evidence and optional baseline

Stage terminal records bind the artifact/configuration, ordered stage storage
commitment, exact request history and chunk/decode schedule, consumed ACK phase,
residual/header hashes, global-to-local state namespace and shapes, source byte
conservation, and native full-vocabulary logit bytes. Source shapes and packed
payload ownership remain the verified native loader's authority; the public
validator checks receipt consistency rather than adding another safetensor
reader. Peer residual hashes must agree. Stage-specific layout/configuration
hashes may differ only in their explicitly ordered stage entries.

Float32 values serialized for the logit report preserve the original native
Float16/BF16/Float32 values. The validator reconstructs that native dtype,
including signed zero, and verifies its byte hash. Merely finishing the rank
check does not establish equality to an ordinary full-model forward.

To request that separate comparison, add:

```sh
--baseline-jsonl INDEPENDENT_NATIVE_BASELINE_JSONL \
--baseline-sha256 BASELINE_FILE_SHA256
```

The pinned file must contain exactly one
`qwen_layer_stage_baseline_checkpoint` from the existing recorded baseline
contract. Its request UUID must differ while actual prompt/teacher IDs,
schedule, source artifact, configuration, conversion, and plan match. The
comparison requires exact global state metadata/hashes and all native logit
bytes. It checks the file's pin again when read. It does not create a baseline,
reinterpret a rank report as one, or re-establish that older run's binary/source
provenance; preserve its original receipt and independent audit as well.
Without the option, `baseline_audit.performed` is false. An optional comparison
failure leaves the native cohort result intact and marks the overall run
failed. No numerical tolerance or quality qualification is introduced.

Every run retains source and dependency identities, an immutable native/resource
bundle, copied Python runtime, launcher files, input/config/manifest bytes,
generated rank arguments/environment, raw stdout/stderr, memory observations,
and a terminal receipt. Existing sources/bundle/artifact and retained inputs
are checked again after execution. The executable pin is caller-supplied;
source hashing records provenance, not proof that an arbitrary binary was built
from that source. Keep the corresponding build receipt.

## Migration and validation

Keep the frozen `stage-p2p-launcher-draft`, `stage-rank-launcher-draft`, their
receipts, and their original test/native counts unchanged. New module tests,
saved-record checks, and any future integrated native run get new receipts.
The common launcher does not inherit a hardware qualification from those
historical runs. The first integrated validation should run the no-model P2P
positive and whole-cohort failure controls, then a separately recorded bounded
stage check with its explicitly pinned baseline. The artifact CLI is generic;
there is no claim that every admitted artifact has already run.

CPU-only draft tests:

```sh
python3 -m unittest discover -v -p 'test_stage*.py'
```

The recorded draft manifest lists exact source hashes, new CPU test count, and
saved-report compatibility results. No production serving, lookahead scheduling,
persistent cohort API, precision policy, remote SSH, or JACCL path is added.
