### Provider CI: a dev push that moves the build cache's dependency tier still saves a provider build

- A push to `dev` whose tree a pull request's run already tested runs no test job, and since 2026-11-19 no build job either, so it saves no cache. When that push moves the Swift build cache's dependency tier (it changes a gitlink, such as a `libs/mlx-swift-lm` bump, or a `Package.swift`, `Package.resolved` or `.gitmodules`), pull requests on the new tier then find no `dev` entry to restore: on 2026-11-24 from 00:37Z to 07:20Z, none of 23 pull request provider builds restored one, and 14 of them were on the tier of two `libs/mlx-swift-lm` merges whose pushes were skipped this way.
- The component classifier (`scripts/ci-component-paths.py`) now also reports `dependency_tier`, read from the same commit diff (`git diff --raw`: gitlink modes and manifest names). On such a `dev` push the plan sets `warm_provider_cache`, routes the provider build lane, and `Build provider test products` builds and saves its caches. It uploads no products and no test job runs; the `Provider Tests` gate and the tested-tree record are unchanged.
- A `dev` push whose change selects no provider test but moves the tier (a `Package.swift` outside the provider's inputs) warms the same way.
- Cost: one 12x32 build per qualifying push, from nothing after an MLX pin bump (about 5 minutes; 273 s p50 for a cold provider build on 2026-11-23), and one more Swift build entry in that runner's cache. 19 first-parent `dev` commits moved the tier in the eight days 2026-11-16 to 2026-11-23 (Pacific dates), 0 to 5 a day. Pull requests, dispatches, `master` and every other push run exactly as before.
- Limits: `dev` pushes coalesce, so a later push cancels a running warm build and saves nothing for that tier unless it moves the tier itself or runs the provider build; a tier move from the toolchain or from `scripts/provider-ci-cache.py`'s version is not in the diff; the entry reaches only the cache of the runner the build ran on; and a failed warm build marks the run red while the `Provider Tests` gate passes.
