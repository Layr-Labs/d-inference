## Quantized axes and legal cuts

Every inspected expert triplet has logical axes `[expert, output, input]`. Packed U32 weights hold 8 values/word at W4, 4 at W8. BF16 scales and offsets have one value per 64 input values. `biases` means affine quantization offsets, not an output bias.

- Qwen gate/up logical shape `[256,512,2048]`; W4 packed `[256,512,256]`, scales/offsets `[256,512,32]`. Down logical `[256,2048,512]`; packed `[256,2048,64]`, metadata `[256,2048,8]`. Expert and shared widths both split **256/256**, preserving four groups each.
- Gemma gate/up logical `[128,704,2816]`; packed final width 704 at W8 or 352 at W4; metadata `[128,704,44]`. Down logical `[128,2816,704]`; packed final width 176/88; metadata `[128,2816,11]`. **352/352 is not a group-preserving cut**: it crosses the sixth G64 group. Use **320/384** (5/6 groups). Dense width 2112 similarly needs **1024/1088** (16/17 groups), not 1056/1056. All 30 layers have these same widths. Reversing ownership on odd layers gives each rank exactly half the total FFN bytes; it does not eliminate each layer's compute imbalance.

The loader must slice expert tensors in three dimensions and support uneven rank extents. Gate/up slice axis 1; down slices packed axis 2 and the matching scale/offset groups. For fused gate-up, slice corresponding ranges from both halves, then form local `[gate rows, up rows]`; taking one contiguous half of a fused tensor is wrong. Qwen's sanitizer currently fuses matching gate/up policies. Gemma currently keeps them split. Preserve policy aliases and reject incompatible fusion instead of assuming uniform checkpoint bits.

Whole-expert ownership is a second candidate: 128/128 Qwen experts or 64/64 Gemma experts preserves each expert's full inner width, with replicated routing/input and filtered/remapped global routes. It avoids the odd-width cut but introduces token-dependent rank imbalance. Selection needs observed expert-assignment histograms and kernel timings; top-8 does not imply equal expert load.

## Model boundaries and collectives

Qwen's router projects the full input, applies full softmax, selects top-8, and renormalizes selected probabilities. `norm_topk_prob` is absent in this artifact; both pinned Qwen decoders explicitly resolve it to `true`. Its shared SiLU FFN is multiplied by a replicated sigmoid gate. Routed and gated shared local partials may be added before **one** hidden-output allreduce per layer, followed by the residual. This is algebraic equivalence; distributed accumulation changes floating-point order, so teacher-forced logits and router agreement must be checked.

Gemma's router first applies a learned RMS normalization scaled by `1/sqrt(2816)`, selects top logits, softmaxes only those, then multiplies learned per-expert scales. Both FFNs use approximate-tanh GeGLU. Dense and routed branches use different input norms and **separate output RMSNorms**. Reduce each branch before its own output norm, add the normalized branches, apply the final FFN norm, residual, then `layer_scalar`. Summing rank-local dense+routed partials into Qwen's single hidden vector would be incorrect. One collective may pack `[2, batch, chunk, hidden]`, retaining both vectors and both normalization barriers.

For a two-rank BF16 ring, retaining all prompt rows, FFN-only Qwen needs 40 vector reductions/chunk: **163,840 B sent and the same received per rank per prompt token**. Gemma with both branches sharded needs 60 vector reductions, packable into 30 calls: **337,920 B each direction per rank/token**. If Gemma's relatively small dense branch stays replicated, only routed outputs reduce: 168,960 B each direction/token, and per-rank weights become 14,678,190,140 B (W8) or 8,044,505,148 B (QAT). That is a concrete plan candidate to measure. These payload counts exclude protocol overhead, optional routing broadcasts, head sharding, and final-layer tail pruning. They are not measured transport costs.

Qwen has 30 GDN + 10 full-attention layers. Preserve F32 recurrent state and convolution history when extending beyond FFN sharding; whole value/key-head groups are a separate capability. With replicated attention/state, logical per-sequence GDN state is 62,914,560 B plus 1,474,560 B BF16 convolution history; full BF16 K/V adds 20,480 B/cached token across ten layers.

Both exact Gemma configs have **zero KV-shared layers, no PLE, and no double-wide dense FFN**. Do not inherit the family defaults. There are 25 sliding layers (1024 window, 8 KV heads, head dim 256) and 5 full layers (2 KV heads, head dim 512). Full `K=V` shares the raw projection; separate K/V normalization produces separate cache arrays. Logical BF16 caches are 209,715,200 B for saturated sliding windows plus 20,480 B/full-context token, per sequence per rank. Final logit softcap is 30 and tied embedding scaling must remain intact. Cache figures exclude allocator blocks/padding/transients.

## Qualification and measured plan selection

Both local `SwitchGLU` implementations can express the underlying gather/activation/down/weighted-reduction sequence. Current optimized weighted-unsort paths explicitly require original widths 512 (Qwen) or 704 (Gemma); the proposed local widths do **not** qualify. Gemma's coupled optimized expert-QMM path also requires W4/G64, excluding the active W8 artifact. Do not broaden those guards based on algebra. Use the generic path until each new geometry has correctness and timing evidence.

First qualify the reusable partial-output primitive with exact weights and common teacher tokens, comparing routed IDs/scores, each branch before its norm, full logits, and multi-chunk state against the same single-machine source implementation. Record accumulation dtype and maximum/relative errors. Whole-expert routes need tests for empty local assignments and skew. Group cuts need reconstructable source identities and exact copied-byte receipts; no implicit requantization.

The plan selector should consume artifact/config/header identity, kernel/build/hardware fingerprints, request batch/chunk/context, quantization and shard geometry, router load histograms, measured per-branch timings, communication size/latency curves, and peak memory. Compare replicated, expert-inner-only, both-branch inner TP, and whole-expert candidates by measured critical-path time, including barriers and the slower rank. Missing profiles mean unqualified, not an invented TPS. Keep Qwen3.8-27B dense as the first two-M3-Ultra performance target; metadata alone establishes no MoE speedup or 800/1,000-TPS claim.
