# Trusted-peer RDMA security: source audit and implementation boundary

This is a source-only audit of current MAIN on 2026-09-15. The user has specified trusted Macs running Darkbloom, both coordinator-verified and routable. Required protection is authenticated encryption of every inference-bearing RDMA record, authenticated membership, fresh keys, and replay rejection. Endpoint-memory blindness is outside this threat model. No runtime, network, trust, or interface settings were changed; no cryptographic implementation or physical security experiment was performed for this audit.

## Current result

The installed path authenticates/encrypts owner control through SSH and authenticates the local bootstrap peer with kernel PID/UID checks. The current RDMA data path sends plaintext residuals, generation records, and acknowledgments. It does not satisfy the new encrypted-in-transit requirement. Existing hashes and strict sequence checks provide important consistency/ownership checks, but they are not keyed message authentication.

The installed pair is also not bound to coordinator-verified provider membership. Its `coordinator` configuration field denotes the JACCL address/port, not the Darkbloom routing coordinator. Local installed-file checks, SSH host keys, process PIDs, and observed native Ready are different evidence from coordinator attestation/routability. This report does not assert the current development machines' coordinator status.

## Minimal reusable design

1. Add an explicit encrypted-record capability/security version and required selection. An encrypted-required session must reject missing/unsupported security before weights or requests; it must never fall back to plaintext. Preserve historical plaintext evidence as historical, not as security qualification.
2. Reuse the normal provider identity and coordinator control connection on both members. Introduce a bounded pair-authorization exchange evaluated atomically against the existing verification/routing gates for both live connections and the selected model/runtime capability. This is a typed addition, not a second registry or inference service. The current local-only startup needs this connection/admission seam; it cannot manufacture a receipt from saved setup.
3. Bind authorization to both stable verified identities AND current process connections/keys, ranks, cluster ID, fresh native epoch, owner lease/incarnation, native executable/capability/Plan/security suite, fresh per-native ephemeral public keys, authorization nonce and expiry/policy generation. Deliver the same canonical transcript independently to both authenticated members; require key confirmation. Authenticity must derive from the existing authenticated coordinator channel or a separately provisioned coordinator signature, never from a self-supplied JSON hash. Do not introduce a new signing-key scheme merely to avoid the existing channel.
4. Native-to-provider public-key exchange uses a new explicit, bounded, PID/UID-bound local message contract. Existing fixed four-round bootstrap is unchanged. Perform this before protected pre-weight agreement. A fresh key establishment belongs to the fresh native epoch; no secret in argv, environment, saved config, logs or diagnostic sidecars. Separate directional AEAD keys with explicit domain separation. A reused epoch/key must be refused by the session/key-establishment owner.
5. Place a small model-independent CryptoKit AEAD record codec above completed Collective P2P. Seal bounded CPU bytes; send sealed uint8 bytes over the same RDMA mechanism. Open/authenticate all bytes before reconstructing an MLX residual or calling its consumer. Use the existing local expectation to bind shape, dtype, frame/frontier and packet phase. Keep the current payload checks, sequence/state machine, consumed ACK, and native completion semantics.
6. Protect boundary headers/payloads, selected tokens, decisions, ready/consumed/accepted/retired acknowledgments, and load/request/readiness exchanges. A fixed public framing prefix may expose only bounded transport metadata; authenticate it. Do not send plaintext lengths that determine unbounded allocation. No model data goes into AAD; AAD is authenticated but not encrypted. Timing, record sizes and traffic patterns remain observable unless a separately charged padding policy is added.
7. Fresh directional keys plus a monotonically increasing sequence across the entire native session produce unique nonces. The sequence never resets per request. Bind direction, epoch, Plan, request, record type, sequence, exact plaintext length and membership transcript in AAD; also bind a digest of local phase/geometry expectations. Reject wrong context, replay, skip, exhaustion, invalid tag or length before model/state mutation. An authentication failure poisons the session and triggers existing bilateral cancellation/fencing; it does not acknowledge native retirement or clear leases.
8. Coordinator revocation/disconnect/expiry closes new admissions and drives bounded drain/fence with existing owner semantics. Authorization lifetime is not a refreshed request deadline. Keep request-send origin, fixed worker lifetime, reservation charges, true native retirement, owner release ACK and sticky quarantine. Coordinator eligibility is not memory capacity or physical RDMA reachability; require actual protected peer handshake and native Ready separately.

For the first implementation, use CryptoKit's standard AES-GCM and HKDF APIs; do not write an AEAD primitive or GPU cryptography kernel. Key establishment/authenticated membership remains a separately reviewed dependency. A value-only codec with supplied key material can be tested first but does not by itself make the product secure.

## Buffer cost and performance qualification

For one boundary, `B = chunkTokens × hiddenSize × activationElementBytes` (batch one). Current 9B C512/BF16 is 4 MiB and decode is 8 KiB. 27B C512/BF16 is 5 MiB; its C16 shape is 160 KiB and decode is 10 KiB. These are logical payload sizes, not measured peak allocations.

The AEAD tag is 16 bytes; a fixed small header/sequence adds constant wire overhead. Fresh directional nonce derivation can avoid transmitting a separate nonce. The costly part is staging: plaintext host materialization, sealed Data, possible Array/MLX sealed copy, received ciphertext, decrypted Data and reconstructed native residual can overlap. A straightforward implementation may add several B-sized buffers; **3–4 B is only a planning estimate, not a memory bound or measurement**. API-copy behavior must determine the exact named ledger before admission.

Reserve explicit host plaintext/ciphertext, native ciphertext/reconstructed residual and crypto scratch in addition to existing base state and lookahead extras. `QwenGenerationPrefillAllowance.swift` already reserves one prepared chunk plus host/bookkeeping; it is not spare encryption budget. Thread the added maximum into actual Ready, per-request reserve and live checks in `QwenResidentRuntime+Load.swift`, `QwenResidentRuntime.swift`, and `QwenResidentRequestResources.swift`. Preserve one outstanding record and the admitted lookahead frontier; release staging only after its relevant native send/receive fence. Do not claim zero-copy.

CPU encryption may add readback/synchronization and copying before/after AEAD. No throughput or TTFT claim is made here. Re-run exact token/final-state correctness, 24/48 GB memory gates and matched timing cohorts after the protected transport is implemented; prior plaintext timings remain separate.

## Implementation stages and gates

- **A — codec only:** new Foundation/CryptoKit value-only module, no native/owner/Provider changes. Supplied fresh session key; immutable binding; bounded seal/open; fail-closed replay/nonce state. CPU fixtures: bit flips, wrong key/epoch/Plan/request/direction/type/geometry, replay/skip/truncation/oversize, key/record limits, cancellation racing crypto publication, no plaintext fallback. This is not membership qualification.
- **B — membership/key establishment:** strict typed provider/coordinator and local-child messages; current dual-member gates, connection binding, fresh epoch keys and confirmation, expiry/revocation. No static readiness or attestation from config. Test stale/disconnected/demoted members, mismatched public keys, transcript replay and cancellation before Ready.
- **C — transport and accounting:** wrap every inference-bearing path enumerated above; no raw bypass under required security; authenticate before model consume; reserve actual staging peaks. Retain native/process deadline and cleanup proofs. Test malformed ciphertext cannot advance frontier and cannot synthesize consumption/retirement.
- **D — actual-machine qualification:** inspect sealed payload buffers (no plaintext test pattern), tamper/replay rejection, exact numerical regression, resource replay and autonomous cleanup/lease ACK. Then measure matched encrypted 9B/27B cut/timing cohorts. A CPU codec pass or successful SSH connection is not this gate.

No transport implementation is part of this frozen audit. The user's trusted-endpoint scope is resolved; the concrete missing product prerequisites are coordinator pair authorization/key establishment, complete encrypted record routing, and measured/charged staging buffers.
