# V2 teardown correction

Frozen V1 manifest `691626640f5ff5a1b8e485dcdc71974d6b514d45f4a8fe82c25e8e436868cc19` and its directory remain untouched. V1 passed its existing wait-interruption cases, but source review found that an interruption during the earlier unguarded `killpg` loop could skip the remaining groups and handles after `closed` had already been set. Formatting an exception with a broken `__str__` could similarly interrupt cleanup.

Only `worker_processes.py` changes at runtime. Every group kill now catches and records its own failure before proceeding to other groups. The shared recorder preserves the first operator interruption before attempting bounded safe formatting. Teardown distinguishes retiring from closed: no new work is permitted once retiring starts, the watchdog stays active through group fencing/reaping, and closed is set only after all leaders are reaped and handles are closed. A failed teardown can be attempted again; native request commands are never retried. The existing adapter preserves the original operator interruption over a secondary cleanup interruption.

The protocol, event schemas, callbacks, resources, command-write ordering, output caps, timer duration, process construction and public-integration seam are unchanged. Source comparison confirms every other V1 supervisor method is AST-identical, apart from initialization and the live-work check needed for retiring state. The generic fake peer, original15-test file, contract and adapter are byte-identical copies.

All19 fake tests passed: the unchanged15 plus four focused methods covering initial `killpg` KeyboardInterrupt/SystemExit, unprintable kill/wait errors, original KeyboardInterrupt with a secondary SystemExit, and an unretired fake leader retaining the watchdog and accepting a later teardown attempt. Tests execute only fake Python peers or patched fake process objects. No Swift compiler, native model executable, GPU or SSH was used. No actual numerical checker was added.
