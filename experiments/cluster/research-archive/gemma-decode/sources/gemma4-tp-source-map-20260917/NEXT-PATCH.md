# Smallest implementation and qualification sequence

1. **Keep root's current short Gemma baseline and owned-forward runtime as the base.** Pin the final actual source/MLX/metallib/model/config/tokenizer and numerical policy. Do not launch the old experimental worker simply because it already has an FFN TP flag. Select the existing generic window-state/probe composition, preserve global layer indices and measured per-layer K/V dtypes. A longer-prompt profile needs a real bounded Gemma resource reservation before execution; the current short baseline is not such authorization.

2. **Implement whole-expert EP first, one actual layer.** Use the companion `gemma4-expert-id-dispatch-draft-20260917` ownership/slot mapping, exact axis-zero selected reader and full704-width local banks. Keep original attention/router/dense/norms. One authoritative original router result identifies actual global experts, slots and weights; route only owned assignments. Gather unweighted full-H returns into original top-8 order and invoke the existing weighted reduction. This needs a narrow actual expert-call hook; a fixture replay at the post-norm is only a correctness oracle, not executable native EP. Preserve the original kernel selectors/fallbacks and record dispatch. Test empty/all-local/all-remote/skew/ties/noncontiguous48/80 and row counts across sorting thresholds. Never reinterpret a slot as a local ID without the ownership map.

3. **Wire that one layer through the existing pair owner and completed P2P.** One epoch/plan/request/global-layer/operation sequence, explicit rank ownership and bounded record geometry; reject missing/extra/duplicate/unowned outputs before consuming them. Authoritative routing and return buffers require capacity charges, absolute deadlines, cancellation/native synchronization and actual owner-release/ACK cleanup. For encrypted measurements use authenticated records for every inference-bearing control/input/return/readiness exchange; do not fall back to raw reductions or label raw RDMA results encrypted. The first aggregate/gather algorithm is separate from any future weighted-partial allreduce.

4. **Extend to all30 layers only after local and two-rank one-layer numerical gates.** Directly construct selected banks; no full-bank temporary or view retaining global storage. Pair-specific Ready/request capacity must include selected weights, replicated attention+KV+dense, worst admitted routing/input/return/copy budgets and retained evidence. Compare full vocabulary rows, exact generated IDs and all per-layer state components against the same ordinary arithmetic policy. State equality requires reconstructing global head/expert ownership where applicable; a smaller state hash cannot be compared as if layouts were identical. Stop at any concrete first divergence under existing tolerances.

5. **Independently add dense TP or head TP if measured bottlenecks justify them.** Dense TP reuses the existing selected rows/columns and dense norm-input reduction but adds a numerical policy and30 collective boundaries. Head TP composes this draft helper into `GemmaPartitionPlan`: expand the explicit kind, validate original full layout, apply its rank configuration updates before constructing models, select only self-attention tensors using the original policy and include rank-head geometry/reduction precision in the fingerprint. Add one pre-`post_attention_layernorm` reduction and explicit attention→dense→sparse dependency per layer, validating every target before replacement. Keep RoPE/window/head dimension unchanged. Never reduce the residual itself. No changes to these existing files are staged in this draft.

6. **Qualify only the added semantics, then measure matched end-to-end requests.** First compile the metadata helper with the real pinned experiment dependencies and call `checkGemmaAttentionPartition(configuration:)` from a narrow metadata-only executable; its staged cases need the exact retained26B config. Reuse existing `GemmaPartitionPlanCheck`, storage/loader/norm-boundary checks for the integration, adding actual sliding/full attention sum tests before hardware. Do not treat the Python metadata arithmetic as Swift verification. GPU gates then run under a separately reviewed owned command and actual resource bounds: bounded one-layer native reference/partition comparison, two-rank comparison, short full-model comparison, then a separately admitted longer prefill/decode cohort. No compiler/remote command is authorized or executed by this package.

Measure prefill and decode separately on the same real prompt, policy, warm/cold definition and admitted batch/chunk/output sizes. Keep full-row/state encoding outside timed forward intervals. Record same-process packing/projection/transfer/reassembly spans, actual collective count/payload/framing, kernel dispatch, raw OS pressure/free/swap/AC, native footprint and MLX active/cache/peak. Never subtract clocks across hosts. Report end-to-end TTFT and generated-token rate with actual cleanup, including replication/copy/codec costs. Benchmark EP48/80 placement based on observed per-layer assignments and memory; do not infer performance from RAM size, stored bytes or synthetic kernel TPS.

The default serving catalog and public cluster admission remain unchanged. This sequence reuses the same state/transport/owner instead of adding a new request framework. Software metadata PASS alone cannot open a native or production Ready gate.
