The combined-endpoint experiment supports a conservative measured allowance candidate for one serialized codec operation. It does not establish a universal per-rank serving bound. This conclusion comes from the exact compiled source listed in `per-rank-source-review.json`; no allocation experiment or actual 48 GiB output was executed or read for this review.

Both `CollectiveAuthenticatedRecords` instances are created before the operation loop and live until the loop returns. In each operation the source MLX array remains in the surrounding autorelease pool while sender export/seal/native frame send completes, receiver native frame import/copy/open/plaintext materialization completes, and the fixture copies and hashes the output. The mailbox also retains a completed host ciphertext frame between sender and receiver. Thus the experiment includes both persistent codec sessions, the source array alongside the receiver result, and validation storage that a single real rank ordinarily would not own together. Charging its entire observed increment on each rank avoids dividing an aggregate into unsupported directional components.

The two directions are executed serially: `sendArray` returns before `receiveArray` begins. The recorded high-water is the maximum of those phases, not a proof that their transient peaks were simultaneous. Mailbox `Data` storage can share backing memory, the allocator can reuse resident pages from the baseline, and a model-loaded process can have different fragmentation and retained buffers. A measured maximum therefore remains evidence from this exact execution/cache/OS/build environment. It cannot be promoted to a mathematical bound merely because two endpoint objects existed in one process.

`CollectiveAllocationProbe` takes the process baseline before endpoint construction, resets the native allocator peak, sets the freed-buffer cache limit to zero, runs the fixed case, synchronizes streams, and checks native active memory returned exactly to baseline with no tracked MLX arrays or native cache left. `CollectiveAllocationFootprint` reads `RUSAGE_INFO_V4` current and lifetime maximum physical footprint. The reported physical increment is `max(0, finalLifetimeMaximum - initialCurrentFootprint)`, which deliberately retains a possible earlier process high-water. It is not the difference of two historical maxima. Do not subtract native allocation bytes from physical footprint to claim a host-only measurement.

The reported peak snapshots are taken before report DTO construction and JSON encoding. The fixture output/export memory is not a general serving-output budget, and the input/validation overhead should not be subtracted to manufacture one. The native active increment and the physical increment are different, overlapping metrics. A later reviewed candidate should retain the full physical observation, charge independently derived native plaintext/frame staging bounds, and include a nonzero explicit safety margin plus persistent session allowance even where that double counts. The final policy must remain closed to the actual suite, code/build/OS/page/cache domain, covered shapes and dtypes, one operation in flight, and the tested reuse/failure cases. No numerical allowance is chosen here.

The mailbox replaces completed ciphertext delivery, so no real RDMA connection, registered JACCL staging buffer, QP/CQ state or native group is constructed by this probe. The fixture uses public key bytes and bypasses coordinator/native key establishment, and it has no model or lookahead state. Those missing persistent and transient costs must remain charged through their own resource rules; they cannot be inferred from this same-process result. A native group may retain transport allocations before the first protected operation, so both load-time and live-request checks matter.

Root's 24 GiB aggregate is separately attributed evidence: 35 cases, maximum native increment 20,987,904 bytes and maximum full physical increment 71,532,640 bytes, with cleanup verified by root. This review only pins that aggregate receipt; it does not replay its raw observations. The 48 GiB counterpart is unexecuted. No serving profile or encrypted two-rank qualification follows from either this source assessment or the constant-only supervisor derivative.
