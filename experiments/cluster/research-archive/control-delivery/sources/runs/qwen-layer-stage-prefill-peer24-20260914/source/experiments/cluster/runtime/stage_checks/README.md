# Local stage correctness checks

`run_stage_checks.py` runs one fresh two-process cohort on one Mac through the
explicit MLX ring `loopback-test` backend. It provides a fixed no-model P2P check
and a bounded real-artifact whole-layer stage check. These are correctness
tools; they do not qualify throughput, a production scheduler, RDMA, or physical
two-machine execution. Lookahead is not exposed by this launcher.

## Usage

From the repository root, supply a built inference release directory, its exact
executable SHA256, and a new output directory outside the repository:

```sh
python3 experiments/cluster/run_stage_checks.py p2p \
  --release RELEASE --runtime experiments/cluster/runtime --output NEW_OUTPUT \
  --expected-binary-sha256 BINARY_SHA256 --timeout-seconds 60

python3 experiments/cluster/run_stage_checks.py ranks \
  --release RELEASE --runtime experiments/cluster/runtime --output NEW_OUTPUT \
  --expected-binary-sha256 BINARY_SHA256 \
  --model-dir LOCAL_MODEL --artifact-aggregate-sha256 ARTIFACT_SHA256 \
  --tokens-file PROMPT_IDS_JSON --teacher-tokens-file TEACHER_IDS_JSON \
  --chunk-size 32 --timeout-seconds 180
```

`p2p` invokes native `stage-p2p-check`: nine dtype/width cases, six residual
frames per case, and seven control cases per rank. It validates the native
equality assertions, fixture identity, and peer agreement. It does not
independently reconstruct fixture payloads.

`ranks` invokes native `qwen-layer-stage-rank-check` with native precision and
`cbv2-contiguous`. It accepts locally registered dense Qwen artifacts admitted
by the native planner and verified loader, including their 8 GiB declared
payload, 6 GiB canonical tensor, and 512 MiB source-tensor limits. It is not
restricted to a particular artifact hash or tensor count. The prompt contains
1–128 integer token IDs, chunk size is 1–32, and output count is 1–4. Supply
1–3 teacher IDs for 2–4 outputs; omit the teacher file for one output. All IDs
must fit the model vocabulary and context. The native two-stage plan uses an
equal, phase-aligned split of whole layers, preserving full projection widths
and fresh request-owned state. Native topology, quantization, and the 512 MiB
named state/boundary admission remain authoritative.

`--tokens-sha256` and `--teacher-tokens-sha256` optionally pin input files.
Exact supplied bytes are always retained and hashed. Staged native JSON files
contain the retained parsed IDs; their generated bytes are checked afterward.
Model weights are not copied. The original registered artifact is verified
before and after execution, and each native stage loader verifies its expected
artifact through pinned descriptors.

## Resource and lifecycle limits

Real-artifact preflight requires at least 8 GiB estimated reclaimable memory,
4 GiB free output storage, and file-descriptor headroom.
`--minimum-reclaimable-gib` can raise that memory screen. The screen is not a
whole-process allocation guarantee for every admitted topology; constructors,
fusion caches, kernel workspaces, and allocator residency can differ.

Both commands observe macOS memory pressure and reported swap before, during,
and after execution. Pressure must stay at level 0–2 and reported swap must not
increase. Raw observations retain their printed precision. Failures retire the
whole cohort without clearing unrelated processes or retrying a request.

The parent owns a monotonic active-cohort deadline of at most 60 seconds for
P2P or 180 seconds for stage ranks. Each unchanged native process and rank
supervisor also receives the bound. Spawn failure, peer exit, malformed/missing
output, memory failure, signal, or deadline triggers the existing cancellation
file and process-group cleanup. Artifact/source hashing, preflight, and bounded
cleanup are outside the active-cohort deadline. Receipts distinguish reaped
supervisors from an independent native PID inventory; they do not invent the
latter.

Each rank must emit one matching ready record followed by one terminal record.
P2P stdout is limited to 4 MiB (2 MiB per line); stage stdout to 64 MiB (60 MiB
per line); stderr to 4 MiB while polled. Stage output can include four complete
vocabulary rows and bounded state inventories. Private output files avoid
unconsumed stdout pipes. Truncated or invalid records fail without silently
discarding values.

## What the receipt establishes

Stage validation binds the artifact/configuration, ordered storage commitment,
exact request history and chunk/decode schedule, completed consumed ACKs,
residual/header hashes, global state namespace and shapes, source byte
conservation, and native full-vocabulary logit byte hashes. Stage-local layout
and construction identities may differ only in their ordered stage entries.
Native source descriptors, parameter completeness, and packed-byte ownership
remain the verified loader's authority; the Python checks validate receipt
consistency rather than adding another safetensor reader.

Serialized Float32 logit values preserve the original native Float16, BF16, or
Float32 values. The validator reconstructs that native dtype, including signed
zero, and checks its byte hash. A completed pair does not by itself establish
equality to an ordinary full-model forward.

To request a separate comparison, add both:

```sh
--baseline-jsonl INDEPENDENT_NATIVE_BASELINE_JSONL \
--baseline-sha256 BASELINE_FILE_SHA256
```

The pinned file must contain exactly one
`qwen_layer_stage_baseline_checkpoint` using the recorded baseline contract.
Its independently recorded request UUID must differ, while actual prompt and
teacher IDs, schedule, source artifact, configuration, conversion, and plan
match. The comparison requires exact global state metadata/hashes and every
native logit byte. It rechecks the supplied file pin when reading. It does not
create a baseline or re-establish the older run's binary/source provenance;
retain that run's original receipt and independent audit. Without this option,
`baseline_audit.performed` is false. Comparison failure preserves the native
cohort result and marks the overall run failed. No numerical tolerance or
model-quality qualification is introduced.

Each run retains source/dependency identities, the executable/resource bundle,
copied Python runtime, launcher files, input/config/manifest bytes, generated
rank arguments/environment, raw output, and memory observations. Current and
copied source, bundle, artifact, and retained inputs are checked again after
execution. The caller's binary pin and source hashes record provenance; retain
the corresponding build receipt because they are not a reproducible-build
proof. Runtime imports come from the copied snapshot.

## Implementation and tests

The thin public entry calls `cli.py`. Modules separate archive/provenance,
input retention, argument construction, resource observations, record framing,
cohort supervision, the P2P and stage namespaces, request identity, storage/state
validation, and the optional baseline comparison. Bundle, registered-artifact,
and native process-group ownership reuse the existing runtime.

Run the dedicated CPU tests from the repository root:

```sh
python3 -m unittest discover -s experiments/cluster -p 'test_stage_checks*.py' -v
```

Tests use injected clocks and fake process objects; actual subprocess and
socket creation are rejected. Promotion and saved-record compatibility are
separate from native execution of this public entry. Preserve earlier frozen
launcher reports and counts unchanged. New integrated native runs and audits
must receive their own receipts; historical evidence does not qualify every
artifact admitted by this generic interface.

The 2026-09-14 integration passed all 210 cluster Python tests, including the
existing real CPU process-cleanup tests. The public P2P entry also completed
both native ranks successfully; independent CPU replay checked all 54 residual
frames and seven controls per rank, and the final process inventory was empty.
Four memory observations reported no additional swap. This integration run did
not exercise the public `ranks` command with a model. Its native evidence remains
separate from the earlier serialized-rank and lookahead records.
